1.1 Geospatial

描述：支持基于地理位置的操作，存储经纬度坐标并计算距离、范围等。
关键命令：

命令 功能说明 示例
GEOADD 添加地理坐标（经度、纬度、成员名称） GEOADD Sicily 13.361389 38.115556 "Palermo"
GEOPOS 查询成员坐标 GEOPOS Sicily "Palermo"
ZREM 删除成员（实际存储为有序集合） ZREM Sicily "Palermo"
GEODIST 计算两地距离（单位：m/km/mi/ft） GEODIST Sicily "Palermo" "Catania" km
GEOHASH 返回坐标的 Geohash 值（52位字符串） GEOHASH Sicily "Palermo"
GEOSEARCH 返回某半径或矩形范围内的成员（Redis 6.2+） GEOSEARCH Sicily FROMLONLAT 15 37 BYRADIUS 200 km ASC

注意：

  • GEOSEARCH执行效果
    1. 搜索范围：以 (15, 37) 为圆心，200 公里为半径的圆形区域。
    2. 返回结果：键 Sicily 中所有位于该区域内的成员名称（如 "Catania"、"Palermo"），并按距离由近到远排列
  • 删除操作需使用 ZREM（底层为有序集合）。

1.2 HyperLogLog

描述：用于基数统计（不重复元素个数），固定占用 12KB 内存，允许误差。
关键命令：

命令 功能说明 示例
PFADD 添加元素到 HyperLogLog PFADD hll1 foo bar zap
PFCOUNT 计算基数 PFCOUNT hll1
PFMERGE 合并多个 HyperLogLog PFMERGE hll3 hll1 hll2

特性：

  • 不存储元素本身，仅统计基数。
  • 示例结果：PFCOUNT hll3 返回合并后的基数（如 6）。

2 Redis键值管理操作

2.1 Key 操作

描述：Key 是访问 Redis 值的唯一入口，提供对键的增删改查、过期时间管理等操作。

2.1.1 常用命令分类

操作类型 命令示例 功能说明
匹配键 KEYS pattern 列出匹配模式的键（如 KEYS * 查询所有键）
删除键 DEL key [key...] 删除一个或多个键（如 DEL list1）
存在性检查 EXISTS key 检查键是否存在（返回 1/0）
迁移键 MOVE key db 将键移动到指定数据库（如 MOVE k1 2 移到数据库 2）
数据类型 TYPE key 返回键存储的数据类型（如 string、list，不存在返回 none）
设置超时 EXPIRE key seconds 设置键的过期时间（秒）
EXPIREAT key timestamp 设置过期时间为 UNIX 时间戳
取消超时 PERSIST key 移除键的过期时间，使其永久有效

2.1.2 危险命令（慎用！）

命令 风险说明
FLUSHALL 清空所有数据库的键（生产环境禁用）
FLUSHDB 清空当前数据库的键

2.1.3 Redis Key 操作命令全集

序号 命令 描述
1 DEL key 删除指定 key（存在时生效）
2 KEYS pattern 匹配符合模式的 key（如 KEYS user*）
3 EXISTS key 检查 key 是否存在（返回 1/0）
4 EXPIRE key seconds 设置 key 过期时间（秒）
5 EXPIREAT key timestamp 设置 key 过期时间为 UNIX 时间戳
6 PEXPIRE key milliseconds 设置 key 过期时间（毫秒）
7 PEXPIREAT key milliseconds-timestamp 设置 key 过期时间为毫秒级 UNIX 时间戳
8 MOVE key db 将 key 移动到指定数据库（如 MOVE k1 3）
9 PERSIST key 移除 key 的过期时间，使其永久有效
10 PTTL key 返回 key 剩余生存时间（毫秒，-1 表示永久，-2 表示已过期）
11 TTL key 返回 key 剩余生存时间（秒）
12 RANDOMKEY 随机返回当前数据库中的一个 key
13 RENAME key newkey 重命名 key（若 newkey 已存在则覆盖）
14 RENAMENX key newkey 仅当 newkey 不存在时重命名 key（返回 1 表示成功）
15 TYPE key 返回 key 存储的数据类型（如 string、hash）

2.1.4 操作示例

  1. 添加键并查询

    redis> SET pnum 200
OK
redis> KEYS *
1) "pnum"

  2. 查看数据类型

    redis> TYPE pnum
"string"

  3. 设置过期时间

    redis> EXPIRE pnum 5  # 5秒后过期
(integer) 1
redis> TTL pnum       # 查看剩余时间
(integer) -2          # -2 表示已过期

  4. 设置键值及过期时间（原子操作）

    # 方法1：SET + EX 选项
redis> SET pnum 200 EX 50
OK

# 方法2：SETEX 命令
redis> SETEX pnum 50 200
OK

2.1.5 关键注意事项

  1. 性能警告：

    • KEYS * 会阻塞 Redis 服务，生产环境建议使用 SCAN 替代。
    • FLUSHALL/FLUSHDB 会立即清空数据，无确认提示。

  2. 过期时间精度：

    • 秒级命令（EXPIRE/TTL）适用于一般场景，毫秒级（PEXPIRE/PTTL）需高精度时使用。

  3. 重命名冲突：

    • RENAME 会强制覆盖已存在的 newkey，而 RENAMENX 会安全检查。

2.2 String字符串

2.2.1 概述

Redis 的 String 是最基本的数据类型，可以存储：

  • 普通字符串
  • 数值类字符串
  • 序列化对象(如图片、视频等)
  • 最大容量：512MB

2.2.2 基本操作命令

赋值操作
命令 描述 示例
SET key value [EX seconds|PX milliseconds] [NX|XX] 设置键值 SET name "John"
MSET key1 value1 [key2 value2...] 批量设置键值 MSET k1 v1 k2 v2
SETBIT key offset value 设置字符串的位值(0/1) SETBIT flags 10 1
SETEX key seconds value 设置键值并指定过期时间(秒) SETEX token 3600 "abc123"
SETNX key value 仅当键不存在时设置值 SETNX newkey "value"
PSETEX key milliseconds value 设置键值并指定过期时间(毫秒) PSETEX tempkey 5000 "temp"
取值操作
命令 描述 示例
GET key 获取键值 GET name
MGET key1 [key2...] 批量获取键值 MGET k1 k2
GETBIT key offset 获取字符串的位值 GETBIT flags 10
GETRANGE key start end 获取子字符串 GETRANGE name 0 3
GETSET key value 设置新值并返回旧值 GETSET counter 100
字符串操作
命令 描述 示例
STRLEN key 获取字符串长度 STRLEN name
SETRANGE key offset value 从偏移量覆写字符串 SETRANGE greet 6 "Redis"
APPEND key value 追加字符串 APPEND greet " World"
数值操作
命令 描述 示例
INCR key 值增1 INCR views
DECR key 值减1 DECR stock
INCRBY key increment 值增加指定数值 INCRBY score 5
DECRBY key decrement 值减少指定数值 DECRBY stock 10
INCRBYFLOAT key increment 值增加指定浮点数 INCRBYFLOAT price 1.5

2.2.3 示例操作序列

> SET ticketNum 1000
OK
> GET ticketNum
"1000"
> INCR ticketNum
(integer) 1001
> DECRBY ticketNum 10
(integer) 991
> DEL ticketNum
(integer) 1

2.2.4 特性说明

  1. NX/XX选项：

    • NX：仅当键不存在时设置值
    • XX：仅当键存在时设置值

  2. 位操作：

    • 可以对字符串值进行位级别的操作(SETBIT/GETBIT)

  3. 原子性操作：

    • 所有数值操作(INCR/DECR等)都是原子性的

  4. 批量操作：

    • MSET/MGET支持批量设置/获取多个键值对

2.3 列表

2.3.1 概述

Redis List 是一个双向链表数据结构，特点包括：

  • 按照插入顺序排序
  • 可以在头部(左)和尾部(右)添加元素
  • 如果键不存在，Redis 会自动创建新链表
  • 索引从0开始，-1表示最后一个元素

2.3.2 基本操作命令

赋值操作
命令 描述 示例
LPUSH key value [value...] 从列表头部插入一个或多个值 LPUSH fruits apple banana
RPUSH key value [value...] 从列表尾部插入一个或多个值 RPUSH fruits orange
LPUSHX key value 仅当列表存在时从头部插入值 LPUSHX existing_list item
RPUSHX key value 仅当列表存在时从尾部插入值 RPUSHX existing_list item
取值操作
命令 描述 示例
LPOP key 移除并返回列表头部元素 LPOP fruits
RPOP key 移除并返回列表尾部元素 RPOP fruits
LRANGE key start stop 获取指定范围内的元素 LRANGE fruits 0 -1
LINDEX key index 通过索引获取元素 LINDEX fruits 1
索引操作
命令 描述 示例
LSET key index value 通过索引设置元素值 LSET fruits 0 "pear"
LINSERT key BEFORE|AFTER pivot value 在指定元素前后插入新元素 LINSERT fruits BEFORE "apple" "peach"
列表管理
命令 描述 示例
LLEN key 获取列表长度 LLEN fruits
LTRIM key start stop 修剪列表，只保留指定范围 LTRIM fruits 0 2
LREM key count value 移除指定数量的元素 LREM fruits 2 "apple"
阻塞操作
命令 描述 示例
BLPOP key [key...] timeout 阻塞式弹出列表头部元素 BLPOP tasks 5
BRPOP key [key...] timeout 阻塞式弹出列表尾部元素 BRPOP tasks 5
RPOPLPUSH source destination 原子性地转移元素 RPOPLPUSH src dest
BRPOPLPUSH source destination timeout 阻塞式转移元素 BRPOPLPUSH src dest 5
LREM 命令详解

LREM key count value 根据count值删除元素：

  • count > 0：从左往右删除count个匹配元素
  • count < 0：从右往左删除count个匹配元素
  • count = 0：删除所有匹配元素

2.3.3 典型应用场景

  1. 消息队列：

    • 生产者使用 LPUSH 插入消息
    • 消费者使用 RPOP 获取消息
    • 阻塞版本 BLPOP/BRPOP 可实现实时等待

  2. 最新消息列表：

    • 使用 LPUSH 添加最新消息
    • 使用 LTRIM 保持固定长度

  3. 任务调度：

    • 使用 RPOPLPUSH 实现安全的任务转移

2.3.4 示例操作序列

基本操作示例
> LPUSH userlist u100 u101 u103 u104 u105 u106 u107 u108
(integer) 8
> RPOP userlist
"u100"
> LLEN userlist
(integer) 7
> LINDEX userlist 6
"u101"
> LINDEX userlist 5
"u103"
> LINDEX userlist 0
"u108"
> LRANGE userlist 1 3
1) "u107"
2) "u106"
3) "u105"
元素删除示例
> RPUSH mylist "hello"
(integer) 1
> RPUSH mylist "hello"
(integer) 2
> RPUSH mylist "foo"
(integer) 3
> RPUSH mylist "hello"
(integer) 4
> LREM mylist -2 "hello"
(integer) 2
> LRANGE mylist 0 -1
1) "hello"
2) "foo"

2.4 集合(Set)

2.4.1 概述

Redis Set 是无序的字符串集合，主要特点包括：

  • 无序性：元素没有特定顺序
  • 唯一性：不允许重复元素
  • 集合运算：支持交、并、差等集合操作
  • 高效查询：判断元素是否存在的时间复杂度为O(1)

2.4.2 基本操作命令

元素操作
命令 描述 时间复杂度 示例
SADD key member [member...] 添加元素 O(1) SADD myset "a" "b"
SREM key member [member...] 删除元素 O(1) SREM myset "a"
SMEMBERS key 获取所有元素 O(N) SMEMBERS myset
SCARD key 获取元素数量 O(1) SCARD myset
SISMEMBER key member 判断元素是否存在 O(1) SISMEMBER myset "a"
SPOP key [count] 随机移除并返回元素 O(1) SPOP myset 2
SRANDMEMBER key [count] 随机返回元素(不删除) O(1) SRANDMEMBER myset
集合运算
命令 描述 时间复杂度 示例
SDIFF key [key...] 差集 O(N) SDIFF set1 set2
SINTER key [key...] 交集 O(N*M) SINTER set1 set2
SUNION key [key...] 并集 O(N) SUNION set1 set2
SDIFFSTORE dest key [key...] 差集存储到新集合 O(N) SDIFFSTORE res set1 set2
SINTERSTORE dest key [key...] 交集存储到新集合 O(N*M) SINTERSTORE res set1 set2
SUNIONSTORE dest key [key...] 并集存储到新集合 O(N) SUNIONSTORE res set1 set2
SMOVE source dest member 移动元素到另一集合 O(1) SMOVE set1 set2 "a"

2.4.3 示例分析

基础操作示例
> SADD myfans f1 f2 f3 f4 f6 f8 f12
(integer) 7  # 成功添加7个元素
> SADD yourfans f5 f6 f8 f10 f11 f12 f18 f21
(integer) 8  # 成功添加8个元素

> SREM myfans f6
(integer) 1  # 成功删除1个元素

> SMEMBERS myfans
1) "f3"      # 注意：输出顺序与添加顺序无关
2) "f1"
3) "f12"
4) "f8"
5) "f2"
6) "f4"

> SISMEMBER myfans f5
(integer) 0  # 0表示不存在
集合运算示例
# 并集
> SUNION yourfans myfans
1) "f1"     # 所有不重复的粉丝
2) "f2"
3) "f3"
4) "f4"
5) "f5"
6) "f6"
7) "f8"
8) "f10"
9) "f11"
10) "f12"
11) "f18"
12) "f21"

# 差集 (myfans有而yourfans没有的)
> SDIFF myfans yourfans
1) "f3"
2) "f4"
3) "f2"
4) "f1"

# 差集 (yourfans有而myfans没有的)
> SDIFF yourfans myfans
1) "f5"
2) "f6"
3) "f18"
4) "f21"
5) "f11"
6) "f10"

# 交集 (共同粉丝)
> SINTER yourfans myfans
1) "f12"
2) "f8"

2.4.4 实际应用场景

  1. 标签系统：

    # 给用户添加标签
SADD user:1:tags tech programming redis
SADD user:2:tags tech design

# 查找有共同兴趣的用户
SINTER user:1:tags user:2:tags  # 返回 "tech"

  2. 社交关系：

    # 共同好友
SINTERSTORE common_friends user:100:friends user:200:friends

# 可能认识的人(好友的好友)
SDIFFSTORE suggestions user:200:friends user:100:friends
SREM suggestions 100  # 排除自己

  3. 抽奖系统：

    # 添加参与者
SADD lottery_users user1 user2 user3

# 随机抽奖
SRANDMEMBER lottery_users 3  # 随机返回3个用户(不删除)
SPOP lottery_users 1        # 随机抽1个用户并移除

  4. 数据去重：

    # 记录已处理ID
SADD processed_items 1001 1002

# 检查是否已处理
SISMEMBER processed_items 1003  # 返回0表示未处理

2.5 Redis Hashes 散列

2.5.1 常用操作命令

1. 赋值操作
  • HSET：设置单个字段值 
    HSET user:1:phone home 13800138000
  • HMSET（已弃用，推荐用HSET替代）：设置多个字段值 
    HSET user:1:phone home 13800138000 work 13900139000
  • HSETNX：仅当字段不存在时设置值 
    HSETNX user:1:phone mobile 13700137000
2. 取值操作
  • HGET：获取单个字段值 
    HGET user:1:phone home
  • HMGET：获取多个字段值 
    HMGET user:1:phone home work
  • HGETALL：获取所有字段和值 
    HGETALL user:1:phone
  • HKEYS：获取所有字段名 
    HKEYS user:1:phone
  • HVALS：获取所有字段值 
    HVALS user:1:phone
3. 删除操作
  • HDEL：删除一个或多个字段 
    HDEL user:1:phone work
4. 其他操作
  • HLEN：获取字段数量 
    HLEN user:1:phone
  • HEXISTS：判断字段是否存在 
    HEXISTS user:1:phone home
  • HINCRBY：字段值整数递增 
    HINCRBY user:1:stats logins 1
  • HINCRBYFLOAT：字段值浮点数递增 
    HINCRBYFLOAT user:1:stats balance 50.5

2.5.2 应用场景示例

存储用户标签信息
# 设置用户1的电话标签
HSET user:1:phone home "13800138000" work "13900139000"

# 获取家庭电话
HGET user:1:phone home

# 获取所有标签
HGETALL user:1:phone
订单信息存储
# 设置订单信息
HSET order:1001 telnum "13301122123" address "海淀区西土城路10号" amount 3

# 查询所有字段
HKEYS order:1001

# 值递增
HINCRBY order:1001 amount 2  # amount从3变为5

2.5.3 注意事项

  1. 中文显示问题
    在Redis CLI中，中文可能显示为Unicode编码。使用 --raw 参数可正常显示：

    redis-cli --raw

  2. HMSET替代方案
    Redis 4.0+ 推荐用 HSET 替代 HMSET，两者功能相同。

  3. 性能特性

    • 每个Hash可存储多达 $2^{32}-1$ 个字段-值对。
    • HGETALL 对大数据量可能阻塞服务，建议用 HSCAN 迭代。

  4. 适用场景

    • 对象存储（用户属性、商品信息）
    • 频繁修改部分字段的场景（如计数器）

2.6 Sorted Sets （有序集合）

只有 Sorted Set（有序集合，即 ZSET）有 score 的概念！

  1. 不重复元素：成员（member）唯一，但分数（score）可重复。
  2. 自动排序：根据 score 从小到大排序，支持范围查询和排名操作。
  3. 高性能：所有操作时间复杂度为 O(log(N))，适合排行榜、优先级队列等场景。

2.6.1 常用操作命令

1. 增加/更新成员
  • ZADD：添加或更新成员分数 
    ZADD pranklist 100 p1 20 p2 33 p3
    • 返回成功添加的成员数量（如更新分数不计入）。
2. 删除成员
  • ZREM：删除指定成员 
    ZREM pranklist p1
  • ZREMRANGEBYSCORE：删除分数区间内的成员 
    ZREMRANGEBYSCORE pranklist 10 30  # 删除score在[10,30]的成员
  • ZPOPMIN/ZPOPMAX（Redis 5.0+）：弹出最低/最高分成员 
    ZPOPMIN pranklist 2  # 弹出2个最低分成员
3. 查询操作
  • ZRANGE：按score升序返回区间成员 
    ZRANGE pranklist 0 -1 WITHSCORES  # 返回所有成员及分数
  • ZREVRANGE：按score降序返回区间成员 
    ZREVRANGE pranklist 0 2  # 返回前3名（高分到低分）
  • ZSCORE：获取成员分数 
    ZSCORE pranklist p2
  • ZRANK/ZREVRANK：获取成员升序/降序排名（从0开始） 
    ZRANK pranklist p3  # 返回p3的升序排名
4. 统计操作

  • ZCARD：获取成员总数

    ZCARD pranklist

  • ZCOUNT：统计分数区间内的成员数

    ZCOUNT pranklist 50 100  # score在[50,100]的成员数
5. 分数操作
  • ZINCRBY：增减成员分数 
    ZINCRBY pranklist 15 p2  # p2的score增加15

2.6.2 应用场景示例

1. 销售排行榜
# 添加商品销量
ZADD sales_rank 1500 "iPhone" 3000 "iPad" 800 "MacBook"

# 获取Top2商品
ZREVRANGE sales_rank 0 1 WITHSCORES
1) "iPad"
2) "3000"
3) "iPhone"
4) "1500"

# 增加iPhone销量
ZINCRBY sales_rank 200 "iPhone"  # iPhone分数变为1700
2. 学生成绩管理
# 添加成绩
ZADD exam_scores 98 "Alice" 85 "Bob" 92 "Charlie"

# 查询及格人数（score>=60）
ZCOUNT exam_scores 60 +inf

# 删除不及格学生
ZREMRANGEBYSCORE exam_scores 0 59
3. 优先级任务队列
# 添加任务（优先级=score）
ZADD tasks 1 "Backup DB" 3 "Send Email" 2 "Generate Report"

# 处理最高优先级任务
ZPOPMAX tasks 1
1) "Send Email"
2) "3"

2.6.3 注意事项

  1. 分数范围

    • 支持 -inf（负无穷）和 +inf（正无穷）表示区间，如： 
      ZRANGEBYSCORE pranklist 50 +inf  # 查询score≥50的成员

  2. 相同分数排序

    • 若多个成员 score 相同，默认按字典序排序。

  3. 性能建议

    • 避免对大集合频繁使用 ZRANGE 0 -1，推荐分页查询： 
      ZRANGE pranklist 0 9  # 获取前10条

  4. 集群限制

    • 在Redis集群中，所有Sorted Set的key必须位于同一slot（可通过hash tag确保）。

2.7 Redis 发布订阅（Pub/Sub）

Redis 的 发布订阅（Pub/Sub） 是一种 消息通信模式，允许 发布者（Publisher） 向 订阅者（Subscriber） 发送消息。它采用 “频道（Channel）” 作为消息传递的媒介，实现 松耦合 的通信方式。

1. 核心概念

角色 说明
Publisher（发布者） 向指定 频道（Channel） 发送消息
Subscriber（订阅者） 订阅一个或多个 频道（Channel），接收消息
Channel（频道） 消息传递的媒介，订阅者可以监听多个频道

2. 基本命令

(1) 订阅频道
SUBSCRIBE channel1 channel2 ...
  • 订阅一个或多个频道，客户端进入 订阅模式，持续接收消息。
  • 返回值示例： 
    1) "subscribe"  # 表示订阅成功
2) "PSTest"     # 订阅的频道名
3) (integer) 1  # 当前订阅的频道数量
(2) 发布消息
PUBLISH channel "message"
  • 向指定频道发送消息。
  • 返回值：收到消息的订阅者数量（integer）。
(3) 取消订阅
UNSUBSCRIBE [channel1 channel2 ...]
  • 取消订阅指定的频道，如果不指定频道，则取消所有订阅。

3. 示例演示

步骤 1：订阅者订阅频道 PSTest
SUBSCRIBE PSTest

输出（订阅成功）：

1) "subscribe"
2) "PSTest"
3) (integer) 1

此时，该客户端会 阻塞等待消息。

步骤 2：发布者向 PSTest 发送消息
PUBLISH PSTest "Hello!"

返回：

(integer) 1  # 表示有 1 个订阅者收到了消息
步骤 3：订阅者接收消息

订阅者客户端会 自动显示收到的消息，格式如下：

1) "message"   # 表示这是一条消息
2) "PSTest"    # 消息来源的频道
3) "Hello!"    # 消息内容

如果发布者再发送一条消息：

PUBLISH PSTest "Have a good time!"

订阅者会收到：

1) "message"
2) "PSTest"
3) "Have a good time!"

4. 进阶用法

(1) 模式匹配订阅（PSUBSCRIBE）

可以使用 通配符 订阅多个频道：

PSUBSCRIBE news.*   # 订阅所有以 "news." 开头的频道

发布消息：

PUBLISH news.sports "Match started!"

订阅者会收到：

1) "pmessage"       # 表示模式匹配的消息
2) "news.*"         # 订阅的模式
3) "news.sports"    # 实际频道
4) "Match started!" # 消息内容
(2) 取消模式订阅（PUNSUBSCRIBE）
PUNSUBSCRIBE news.*

5. 与其他消息队列的区别

特性 Redis Pub/Sub Kafka / RabbitMQ
持久化 ❌ 不存储 ✅ 支持
消息堆积 ❌ 订阅者离线会丢失 ✅ 可存储未消费消息
性能 ⚡ 极高（内存操作） 🏎️ 高（但依赖磁盘）
适用场景 实时通知、轻量级消息 可靠消息队列、大数据流

3 Redis集群架构及管理

Redis Cluster 是 Redis 官方提供的分布式解决方案，采用 无中心化架构，通过 分片（Sharding） 和 高可用（HA） 机制实现数据的分布式存储和故障自动恢复。

3.1 Redis Cluster 核心架构

(1) 基本组成

  • 主节点（Master）：负责数据存储和读写请求。
  • 从节点（Replica）：作为主节点的备份，提供 故障转移（Failover） 能力。
  • Slot（槽）：Redis Cluster 将整个数据空间划分为 16384 个 Slot，每个主节点负责一部分 Slot。

(2) 数据分片（Sharding）

  • 键（Key）映射到 Slot：
    • 计算方式：CRC16(key) % 16384
    • 例如：user:100 的 Slot = CRC16("user:100") % 16384
  • Slot 分配到节点： 
    节点A：0 - 5460
节点B：5461 - 10922
节点C：10923 - 16383
  • 客户端访问：
    • 客户端可以连接任意节点，如果 Key 不在当前节点，Redis 会返回 MOVED 重定向，客户端自动跳转到正确的节点。

3.2 Redis Cluster 核心特性

特性 说明
无中心化 所有节点互联，客户端可连接任意节点
自动分片 数据按 Slot 分配到不同节点
高可用（HA） 主节点故障时，从节点自动提升为新主节点
可扩展性 动态增删节点，Slot 自动重新分配
数据强一致性 采用 异步复制，但提供 WAIT 命令 实现同步复制

3.3 集群管理命令

(1) 查看集群状态

CLUSTER INFO       # 查看集群整体状态
CLUSTER NODES      # 列出所有节点信息
CLUSTER KEYSLOT key  # 计算 Key 对应的 Slot

(2) 节点管理

CLUSTER MEET <ip> <port>   # 添加新节点到集群
CLUSTER FORGET <node_id>   # 从集群移除节点

(3) Slot 管理

CLUSTER ADDSLOTS <slot1> <slot2> ...  # 分配 Slot 给当前节点
CLUSTER DELSLOTS <slot1> <slot2> ...  # 移除当前节点的 Slot
CLUSTER FLUSHSLOTS                    # 清空当前节点的所有 Slot

(4) 数据迁移

CLUSTER COUNTKEYSINSLOT <slot>      # 统计 Slot 中的 Key 数量
CLUSTER GETKEYSINSLOT <slot> <count>  # 获取 Slot 中的 Key 列表

3.4 副本漂移（Replica Migration）

(1) 触发条件

Redis 定期检查：

  1. 是否存在主节点没有从节点（单点风险）。
  2. 是否存在主节点有多个从节点（可迁移）。

(2) 迁移流程

假设：

  • 主节点 A 有 2 个从节点 A1 和 A2。
  • 主节点 B 没有从节点。

Redis 会自动执行：

  1. 从 A 的从节点中选择一个（如 A1）。
  2. 将 A1 的主节点改为 B。
  3. A1 开始从 B 同步数据。
  4. 集群更新拓扑信息，通知所有节点。

3.5 多 Key 操作的限制

由于数据分布在不同的节点，跨 Slot 的多 Key 操作（如事务、Lua 脚本）可能失败。
解决方案：使用 Hash Tag 强制 Key 映射到同一个 Slot。

示例

# 这两个 Key 会被分配到同一个 Slot（仅计算 {} 内的内容）
SET user:{100}:name "Alice"
SET user:{100}:age 30

# 可以执行事务
MULTI
GET user:{100}:name
GET user:{100}:age
EXEC

4 Redis配置管理

4.1配置文件

  • 路径：
    • Linux: redis.conf
    • Windows: redis.windows.conf
  • 查询配置： 
    CONFIG GET parameter    # 查询单个参数（如 `CONFIG GET loglevel`）
CONFIG GET *           # 查询所有参数
  • 修改配置：
    1. 直接编辑配置文件：修改后需重启Redis生效。
    2. 动态修改（无需重启）： 
      CONFIG SET parameter new_value   # 如 `CONFIG SET loglevel "debug"`

4.2 关键配置项

配置项 说明
daemonize 是否以守护进程运行（后台模式）
port 监听端口（默认6379）
bind 绑定IP（默认仅本地，127.0.0.1）
requirepass 访问密码（默认无密码）
maxmemory 最大内存限制（如 maxmemory 1gb）
maxmemory-policy 内存满时的淘汰策略（如 volatile-lru、noeviction）
dir 数据持久化文件存储路径（如 dir /var/lib/redis）
dbfilename RDB文件名（默认 dump.rdb）
appendonly 是否开启AOF持久化（默认no）

4.3 数据备份与恢复

4.3.1 备份（持久化）

  1. RDB方式：
    • SAVE：阻塞式保存，生成dump.rdb。
    • BGSAVE：后台异步保存。
  2. AOF方式：
    • 需配置appendonly yes，通过bgrewriteaof重写AOF文件优化体积。

4.3.2恢复

  • RDB恢复：将备份的dump.rdb文件放到配置项dir指定的目录，重启Redis。
  • AOF恢复：优先加载appendonly.aof文件（若同时开启AOF和RDB）。

注意：

  • 默认仅RDB开启，AOF需手动配置。
  • 恢复时确保文件权限正确。

4.4 命令批量执行

1. 文件批量执行

  • 步骤：
    1. 将命令逐行写入文件（如commands.txt）。
    2. 通过管道执行：
      • Windows： 
        type commands.txt | redis-cli
type commands.txt | redis-cli --pipe  # 高效管道模式
      • Linux： 
        cat commands.txt | redis-cli

2. 事务批量执行

MULTI          # 开始事务
SET k1 v1      # 命令1
SADD set1 a b  # 命令2
EXEC           # 执行事务
  • 特点：
    • 命令失败不影响其他命令执行。
    • 无回滚机制。
  • 监视键： 
    WATCH key     # 监视key变化，若被修改则事务取消
UNWATCH       # 取消监视

关键区别

场景 特点
RDB vs AOF RDB快照式备份，AOF日志式追加；AOF更安全但体积大。
SAVE vs BGSAVE SAVE阻塞服务，BGSAVE后台运行。
事务 vs 管道 事务保证原子性（无回滚），管道仅批量发送命令（无原子性保证）。
