信号灯与共享内存(IPC)

这是对信号灯、共享内存和消息队列的简要总结，涵盖了UNIX中的进程间通信（IPC）机制。

1、信号灯（Semaphore）

  • 作用: 用于控制多进程对共享资源的互斥访问和进程间的同步。
  • 策略与机制分离: UNIX提供信号灯机制，进程本身需要正确使用信号灯来保证互斥和同步。
  • 不当使用: 如果进程错误使用信号灯，可能会导致信息访问的不安全和死锁。
  • P操作（sem_op < 0）: 用于请求资源（等待操作），如果信号灯值小于0，则进程会被阻塞。
  • V操作（sem_op > 0）: 用于释放资源（通知操作），进程释放信号灯。
  • 创建信号灯: 使用semget()函数来创建或获取信号灯组。 
    int semget(int key, int nsems, int flags);
  • 控制信号灯: 使用semctl()函数来进行对信号灯的控制操作，如删除、查询状态等。 
    int semctl(int sem_id, int snum, int cmd, char *arg);
  • 信号灯操作: 使用semop()函数进行P/V操作。 
    int semop(int sem_id, struct sembuf *ops, int nops);
    • sem_num: 信号灯编号。
    • sem_op: 操作值，决定是P操作、V操作还是等待。
    • sem_flg: 操作选项。

2、共享内存（Shared Memory）

  • 特点: 允许多个进程共同使用同一段物理内存空间，进程间传递数据速度快。
  • 问题: 访问共享内存时需要自行解决互斥和同步问题，通常使用信号灯来保证安全。
  • 应用: 适用于数据交换、运行监视等场景。
  • 共享内存操作:
    • 创建共享内存段: 使用shmget()函数。 
      int shmget(int key, int nbytes, int flags);
    • 获取共享内存段指针: 使用shmat()函数。 
      void *shmat(int shm_id, void *shmaddr, int shmflg);
    • 控制共享内存段: 使用shmctl()函数进行删除、查询等操作。 
      int shmctl(int shm_id, int cmd, char *arg);

3、生产者-消费者问题（Producer-Consumer Problem）

  • 问题描述: 生产者与消费者通过N个缓冲区组成的环形队列交换数据。
  • 程序设计: 使用共享内存与信号量来解决同步问题。
    • ctl create: 创建共享内存段和信号灯。
    • ctl remove: 删除共享内存段和信号灯。
    • producer: 启动生产者进程。
    • consumer: 启动消费者进程。

4、系统命令

  • ipcs: 列出当前系统中的IPC对象（包括信号灯、共享内存、消息队列等）。

内存映射文件

1、内存映射 (Memory Mapping)

  • 定义
    将文件的一部分映射为进程虚拟地址空间中的一段内存，进程通过指针操作该内存即可读写文件内容。

  • 特点与优点

    1. 文件访问与内存访问无差别。
    2. 系统按需调入文件内容，物理内存分配由页面调度算法自动完成。
    3. 比传统的 read 和 write 方法速度更快。
    4. 支持多进程共享内存，通过映射同一文件的相同区域实现数据共享。
    5. 提供文件读写的零拷贝机制，减少了CPU拷贝次数。

2、内存映射文件相关系统调用

  1. mmap (内存映射)

    • 功能：将文件的一个区域映射到内存。

    • 函数原型：

      void *mmap(void *addr, size_t len, int prot, int flags, int fd, off_t offset);

    • 参数说明：

      • addr: 映射区起始地址（一般设置为0，由系统自动分配）。
      • len: 映射的字节长度。
      • prot: 映射区的保护方式，如 PROT_READ、PROT_WRITE。
      • flags: 映射模式，如 MAP_SHARED (多进程共享)。
      • fd: 打开的文件描述符。
      • offset: 映射起始偏移。

    • 使用示例：

      char *p;
p = mmap(0, 65536, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
      • p[0] 到 p[65535] 可直接操作，最终对文件进行读写。

  2. munmap (取消内存映射)

    • 功能：解除文件的内存映射。
    • 函数原型： 
      int munmap(void *addr, size_t len);

3、零拷贝 (Zero-Copy)

  • 定义
    零拷贝技术通过减少 CPU 拷贝次数，提升数据传输效率。

  • 实现方式

    • 传统方法 (read/write)
      数据需要从磁盘通过DMA拷贝到内核缓冲区，再从内核缓冲区拷贝到用户缓冲区。
    • 零拷贝方式 (sendfile/splice)
      数据直接从磁盘通过DMA拷贝到网络缓冲区，无需经过用户空间。

4、零拷贝与效率

  • sendfile 和 splice 的优势
    • 减少CPU拷贝次数。
    • 减少上下文切换次数。
    • 提升数据传输效率，适合高效网络文件传输。

5、文件I/O方式与特点比较

方式 CPU拷贝次数 DMA拷贝次数 系统调用 上下文切换次数
传统方法 (I/O) 2 2 read/write 4
内存映射 (mmap) 1 2 mmap/write 4
sendfile 1 2 sendfile 2
scatter/gather copy 0 2 sendfile 2
splice 0 2 splice 0

文件和记录的锁定

1、文件锁定的基本概念

  • 文件锁定是操作系统为解决多进程访问同一文件的冲突而提供的机制。
  • 记录锁定是文件锁定的一种形式，锁定文件的某一部分。
  • 文件锁定的两种类型：
    • 共享锁（读锁，F_RDLCK）：允许多个进程同时读取，但禁止写操作。
    • 互斥锁（写锁，F_WRLCK）：禁止其他进程的读写操作。

2、文件锁定的系统调用

  • fcntl 函数

    • 用于对文件加锁或解锁。
    • 函数原型： 
      int fcntl(int fd, int cmd, struct flock *lock);
    • 参数说明：
      • fd：文件描述符。
      • cmd：命令，常用值为 F_SETLK（非阻塞锁定）或 F_SETLKW（阻塞锁定）。
      • lock：指向 struct flock 的结构体指针，定义锁的类型、位置和长度。

  • struct flock 结构体

    • 用于定义锁定的范围和类型： 
      struct flock {
    short l_type;    // 锁的类型：F_RDLCK, F_WRLCK, F_UNLCK
    short l_whence;  // 偏移起点：SEEK_SET, SEEK_CUR, SEEK_END
    long l_start;    // 锁定的起始位置
    long l_len;      // 锁定的长度，0 表示到文件末尾
};

3、文件锁定的应用

  1. 进程互斥
    • 多进程访问同一文件时，通过锁定机制避免数据冲突。
  2. 实现进程单例
    • 利用写锁尝试锁定文件的某一部分，若锁定成功，则表明该进程是唯一运行的实例。
  3. 数据完整性保护
    • 防止文件同时被多个进程修改，保障数据一致性。
