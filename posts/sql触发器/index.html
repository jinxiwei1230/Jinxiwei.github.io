SQL触发器

触发器(Trigger)是数据库中的一种特殊存储过程，它会在特定事件(如INSERT、UPDATE、DELETE)发生时自动执行。触发器主要用于维护数据的完整性、实施业务规则以及审计数据变更。

一、触发器的基本概念

1. 触发器的定义

触发器是一段与表相关联的PL/SQL代码，当表发生特定事件时自动执行。触发器不接收参数，也不能被直接调用。

2. 触发器的组成要素

  • 触发事件：引起触发器执行的操作(INSERT/UPDATE/DELETE)
  • 触发时间：BEFORE或AFTER，表示在事件之前或之后触发
  • 触发级别：ROW或STATEMENT，表示行级或语句级触发
  • 触发条件：WHEN子句指定的额外条件
  • 触发体：触发器被激活时执行的PL/SQL代码块

3. 触发器的分类

按触发时间分类

  • BEFORE触发器：在触发事件执行之前激活
  • AFTER触发器：在触发事件执行之后激活

按触发级别分类

  • 行级触发器(ROW)：对受影响的每一行都触发一次
  • 语句级触发器(STATEMENT)：对整个SQL语句触发一次

按触发事件分类

  • INSERT触发器：当插入数据时触发
  • UPDATE触发器：当更新数据时触发
  • DELETE触发器：当删除数据时触发

二、触发器的创建语法

CREATE [OR REPLACE] TRIGGER trigger_name
{BEFORE | AFTER} {INSERT | UPDATE | DELETE [OF column_name,...]} 
ON table_name
[REFERENCING [OLD AS old_name] [NEW AS new_name]]
[FOR EACH ROW]
[WHEN (condition)]
DECLARE
    -- 声明部分(可选)
BEGIN
    -- 执行部分
EXCEPTION
    -- 异常处理部分(可选)
END;

三、触发器的详细使用

1. BEFORE触发器

在数据被修改前执行，常用于数据验证或修改即将插入/更新的数据。

示例1：数据验证

CREATE OR REPLACE TRIGGER check_salary
BEFORE INSERT OR UPDATE ON employees
FOR EACH ROW
BEGIN
    IF :NEW.salary < 0 THEN
        RAISE_APPLICATION_ERROR(-20001, 'Salary cannot be negative');
    END IF;
END;

示例2：自动计算字段值

CREATE OR REPLACE TRIGGER calculate_bonus
BEFORE INSERT OR UPDATE ON sales
FOR EACH ROW
BEGIN
    :NEW.bonus := :NEW.amount * 0.1; -- 自动计算奖金为销售额的10%
END;

2. AFTER触发器

在数据被修改后执行，常用于审计跟踪或级联操作。

示例1：审计日志

CREATE OR REPLACE TRIGGER log_employee_changes
AFTER INSERT OR UPDATE OR DELETE ON employees
FOR EACH ROW
DECLARE
    v_action VARCHAR2(10);
BEGIN
    IF INSERTING THEN
        v_action := 'INSERT';
        INSERT INTO emp_audit VALUES(
            :NEW.emp_id, :NEW.emp_name, :NEW.salary, 
            USER, SYSDATE, v_action
        );
    ELSIF UPDATING THEN
        v_action := 'UPDATE';
        INSERT INTO emp_audit VALUES(
            :NEW.emp_id, :NEW.emp_name, :NEW.salary, 
            USER, SYSDATE, v_action
        );
    ELSIF DELETING THEN
        v_action := 'DELETE';
        INSERT INTO emp_audit VALUES(
            :OLD.emp_id, :OLD.emp_name, :OLD.salary, 
            USER, SYSDATE, v_action
        );
    END IF;
END;

示例2：级联更新

CREATE OR REPLACE TRIGGER update_dept_stats
AFTER INSERT OR UPDATE OR DELETE ON employees
FOR EACH ROW
BEGIN
    IF INSERTING THEN
        UPDATE departments
        SET emp_count = emp_count + 1
        WHERE dept_id = :NEW.dept_id;
    ELSIF UPDATING THEN
        IF :NEW.dept_id != :OLD.dept_id THEN
            -- 减少原部门计数
            UPDATE departments
            SET emp_count = emp_count - 1
            WHERE dept_id = :OLD.dept_id;
            
            -- 增加新部门计数
            UPDATE departments
            SET emp_count = emp_count + 1
            WHERE dept_id = :NEW.dept_id;
        END IF;
    ELSIF DELETING THEN
        UPDATE departments
        SET emp_count = emp_count - 1
        WHERE dept_id = :OLD.dept_id;
    END IF;
END;

3. INSTEAD OF触发器

主要用于视图上的触发器，允许对不可更新的视图执行DML操作。

示例：

CREATE OR REPLACE TRIGGER emp_dept_view_insert
INSTEAD OF INSERT ON emp_dept_view
FOR EACH ROW
BEGIN
    -- 检查部门是否存在
    DECLARE
        v_dept_id NUMBER;
    BEGIN
        SELECT dept_id INTO v_dept_id
        FROM departments
        WHERE dept_name = :NEW.dept_name;
        
        -- 部门存在，插入员工
        INSERT INTO employees(emp_id, emp_name, salary, dept_id)
        VALUES(:NEW.emp_id, :NEW.emp_name, :NEW.salary, v_dept_id);
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            -- 部门不存在，先插入部门
            INSERT INTO departments(dept_id, dept_name)
            VALUES(dept_seq.NEXTVAL, :NEW.dept_name);
            
            -- 再插入员工
            INSERT INTO employees(emp_id, emp_name, salary, dept_id)
            VALUES(:NEW.emp_id, :NEW.emp_name, :NEW.salary, dept_seq.CURRVAL);
    END;
END;

4. 复合触发器

Oracle 11g引入的新特性，一个触发器可以包含多个触发时间点。

示例：

CREATE OR REPLACE TRIGGER compound_emp_trigger
FOR INSERT OR UPDATE OR DELETE ON employees
COMPOUND TRIGGER
    -- 声明部分，所有时间点共享
    v_count NUMBER := 0;
    
    -- 语句执行前
    BEFORE STATEMENT IS
    BEGIN
        DBMS_OUTPUT.PUT_LINE('Before statement: ' || v_count);
    END BEFORE STATEMENT;
    
    -- 每行处理前
    BEFORE EACH ROW IS
    BEGIN
        v_count := v_count + 1;
        IF INSERTING THEN
            :NEW.created_date := SYSDATE;
            :NEW.created_by := USER;
        ELSIF UPDATING THEN
            :NEW.modified_date := SYSDATE;
            :NEW.modified_by := USER;
        END IF;
    END BEFORE EACH ROW;
    
    -- 每行处理后
    AFTER EACH ROW IS
    BEGIN
        DBMS_OUTPUT.PUT_LINE('Processed row ' || v_count);
    END AFTER EACH ROW;
    
    -- 语句执行后
    AFTER STATEMENT IS
    BEGIN
        DBMS_OUTPUT.PUT_LINE('Total rows processed: ' || v_count);
        INSERT INTO emp_audit_log(action_type, rows_affected, action_time)
        VALUES(
            CASE 
                WHEN INSERTING THEN 'INSERT'
                WHEN UPDATING THEN 'UPDATE'
                WHEN DELETING THEN 'DELETE'
            END,
            v_count,
            SYSDATE
        );
    END AFTER STATEMENT;
END compound_emp_trigger;

四、触发器的特殊变量和函数

1. :OLD和:NEW伪记录

  • :OLD：代表更新或删除前的行数据(INSERT操作中为NULL)
  • :NEW：代表插入或更新后的行数据(DELETE操作中为NULL)

2. 条件谓词

  • INSERTING：如果触发器由INSERT语句触发则为TRUE
  • UPDATING：如果触发器由UPDATE语句触发则为TRUE
  • DELETING：如果触发器由DELETE语句触发则为TRUE

3. UPDATING函数

检查特定列是否被更新(仅适用于UPDATE触发器)

IF UPDATING('salary') THEN
    -- 当salary列被更新时执行
END IF;

五、触发器的管理

1. 查看触发器

-- 查看所有触发器
SELECT trigger_name, table_name, triggering_event, status 
FROM user_triggers;

-- 查看触发器源代码
SELECT text FROM user_source 
WHERE name = 'TRIGGER_NAME' AND type = 'TRIGGER' 
ORDER BY line;

2. 启用/禁用触发器

-- 禁用触发器
ALTER TRIGGER trigger_name DISABLE;

-- 启用触发器
ALTER TRIGGER trigger_name ENABLE;

-- 禁用表上的所有触发器
ALTER TABLE table_name DISABLE ALL TRIGGERS;

-- 启用表上的所有触发器
ALTER TABLE table_name ENABLE ALL TRIGGERS;

3. 修改触发器

使用CREATE OR REPLACE TRIGGER语句重新创建触发器

4. 删除触发器

DROP TRIGGER trigger_name;

六、触发器的应用场景

1. 数据完整性

  • 复杂约束检查
  • 跨表一致性维护

2. 审计跟踪

  • 记录数据变更
  • 跟踪用户操作

3. 派生数据

  • 自动计算字段值
  • 维护汇总数据

4. 安全控制

  • 实施额外的安全策略
  • 限制特定操作

5. 业务规则

  • 实施复杂业务逻辑
  • 自动工作流

七、触发器的注意事项

  1. 性能影响：触发器会增加DML操作的开销，应谨慎使用
  2. 调试困难：触发器自动执行，错误可能不明显
  3. 递归触发：触发器可能引发其他触发器，导致无限循环
  4. 顺序问题：多个触发器的执行顺序可能影响结果
  5. 事务边界：触发器与触发语句在同一事务中，失败会回滚整个事务
  6. 避免过长逻辑：复杂业务逻辑最好放在应用程序中

八、触发器最佳实践

  1. 保持简单：触发器逻辑应尽量简单直接
  2. 文档记录：为触发器添加详细注释
  3. 性能测试：评估触发器对系统性能的影响
  4. 错误处理：包含适当的异常处理
  5. 避免递归：设计时注意避免触发器间的循环调用
  6. 考虑替代方案：评估存储过程、约束等是否更适合需求

九、不同数据库中的触发器差异

1. Oracle

  • 支持BEFORE/AFTER/INSTEAD OF触发器
  • 支持行级和语句级触发器
  • 11g引入复合触发器

2. SQL Server

  • 使用INSTEAD OF和AFTER触发器(没有BEFORE触发器)
  • 支持DDL触发器
  • 使用inserted和deleted虚拟表代替:NEW和:OLD

3. MySQL

  • 支持BEFORE/AFTER触发器
  • 只支持行级触发器
  • 不支持INSTEAD OF触发器
  • 使用NEW和OLD访问行数据

4. PostgreSQL

  • 支持BEFORE/AFTER/INSTEAD OF触发器
  • 支持行级和语句级触发器
  • 支持触发器函数

十、高级触发器技巧

1. 动态SQL在触发器中

CREATE OR REPLACE TRIGGER dynamic_audit
AFTER INSERT OR UPDATE OR DELETE ON employees
FOR EACH ROW
DECLARE
    v_sql VARCHAR2(1000);
BEGIN
    IF INSERTING THEN
        v_sql := 'INSERT INTO emp_audit VALUES(' || 
                 :NEW.emp_id || ', ''' || :NEW.emp_name || ''', ''' || 
                 USER || ''', SYSDATE, ''INSERT'')';
    ELSIF UPDATING THEN
        v_sql := 'INSERT INTO emp_audit VALUES(' || 
                 :NEW.emp_id || ', ''' || :NEW.emp_name || ''', ''' || 
                 USER || ''', SYSDATE, ''UPDATE'')';
    ELSIF DELETING THEN
        v_sql := 'INSERT INTO emp_audit VALUES(' || 
                 :OLD.emp_id || ', ''' || :OLD.emp_name || ''', ''' || 
                 USER || ''', SYSDATE, ''DELETE'')';
    END IF;
    
    EXECUTE IMMEDIATE v_sql;
END;

2. 条件触发器

CREATE OR REPLACE TRIGGER conditional_trigger
BEFORE UPDATE ON employees
FOR EACH ROW
WHEN (OLD.salary <> NEW.salary) -- 只有当薪资变化时才触发
BEGIN
    INSERT INTO salary_changes(emp_id, old_salary, new_salary, change_date)
    VALUES(:NEW.emp_id, :OLD.salary, :NEW.salary, SYSDATE);
END;

3. 跨数据库触发器

CREATE OR REPLACE TRIGGER sync_customer_data
AFTER INSERT OR UPDATE OR DELETE ON customers
FOR EACH ROW
DECLARE
    v_db_link VARCHAR2(30) := 'remote_db';
BEGIN
    IF INSERTING THEN
        INSERT INTO customers@remote_db
        VALUES(:NEW.cust_id, :NEW.cust_name, :NEW.email);
    ELSIF UPDATING THEN
        UPDATE customers@remote_db
        SET cust_name = :NEW.cust_name,
            email = :NEW.email
        WHERE cust_id = :NEW.cust_id;
    ELSIF DELETING THEN
        DELETE FROM customers@remote_db
        WHERE cust_id = :OLD.cust_id;
    END IF;
EXCEPTION
    WHEN OTHERS THEN
        -- 记录错误但允许主操作继续
        INSERT INTO sync_errors VALUES('CUSTOMER', :NEW.cust_id, SQLERRM, SYSDATE);
END;
