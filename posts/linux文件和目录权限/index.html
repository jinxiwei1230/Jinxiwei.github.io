第8章 Linux文件和目录权限

文件的权限

1、用于控制进程对系统中文件和目录的访问

2、权限的三个级别

  • 文件主，同组用户，其他用户
  • 每个文件有唯一的属主

3、普通文件的权限

  • 读、写、可执行
  • 不可写文件也可能会被删除

4、两类可执行文件

  1. 程序文件（可执行文件）：
  • 包含二进制的CPU指令集合。
  • 必须符合操作系统的格式要求才能加载运行。
  • 例如：Linux系统的ELF格式，Windows系统的PE格式。
  1. 脚本文件：
  • 是普通的文本文件。
  • 默认解释程序为 /bin/sh。
  • 可以在文件第一行通过 #!（Shebang）指定解释程序，例如 #! /bin/bash。
  • 解释程序可以是操作系统内置的程序或用户自定义的应用程序。
  1. 脚本程序运行机制：
  • 运行时由指定的解释程序解析并执行指令。
  • 解释程序会创建一个进程来执行脚本的每条指令。

目录的权限

1、目录的读写权限

  • 目录的读权限决定了能否查看目录内容。
  • 目录的写权限决定了能否在目录中添加或删除文件，但不影响对已有文件内容的修改。

2、目录的执行权限（x权限）

  1. 目录的执行权限：

    • x权限（执行权限）在目录中表示对路径的“可访问性”，即是否允许进入或访问目录中的内容。
    • 只有在具有执行权限的情况下，系统才允许在路径解析过程中“进入”该目录并进一步访问下一级目录或文件。

  2. 路径解析：

    • 当访问某个文件时，例如执行 cat /a/b/c，系统会依次解析路径中的每一级目录。
    • 要成功访问 /a/b/c 文件，路径中的每个目录（/a 和 /a/b）都需要有执行权限，否则系统无法进入这些目录，也就无法找到 c 文件。
    • 最终文件 c 本身只需具备读权限，以便 cat 命令能读取它的内容。

3、STICKY权限（粘着位）

  1. STICKY权限的主要用途——公共目录的文件删除控制：当目录带有写权限且启用STICKY属性时，目录中的文件只能由文件的所有者或管理员删除，其他用户的删除操作会被禁止。这使公共目录更加安全，不会因意外删除影响其他用户的文件。

  2. 示例：

  • /tmp 目录通常带有STICKY权限，因为它是公共目录，供所有用户存放临时文件。查看 /tmp 目录权限时可以看到STICKY位标志 t，例如： 
    drwxrwxrwt 13 root root 20480 Mar 22 06:11 /tmp
    • 权限的第一列显示 t 表示 /tmp 目录有STICKY权限。

4、文件权限的验证顺序

  1. 文件和进程的权限属性：
  • 每个文件和进程都有文件主和组属性。
    • 文件主和文件组：记录在文件的元数据（i节点）中。
    • 进程主和进程组：记录在进程控制块（PCB）中，通常使用uid（用户ID）和gid（组ID）表示。
  • uid和gid的名字和编号映射关系记录在系统目录 /etc/passwd 和 /etc/group 文件中。
  1. 权限验证顺序：

  • 文件主与进程主相同：当文件的文件主和进程的进程主相同时，系统会直接使用文件主的权限，忽略组和其他用户的权限。

  • 文件主与进程主不同，但同属一个组：如果文件主和进程主不同，但属于同一组，那么系统会使用组权限，忽略其他用户的权限。

  • 文件主与进程主不同，且不属于同一组：系统会使用文件的其他用户权限，即最低一层的权限。

  • 注意：超级用户 root 不受权限限制，可访问所有文件。

  1. 示例解释：
  • 权限示例：---r--rw-
    • 文件主（user）权限：---，无任何权限。
    • 文件所属组（group）权限：r--，仅有读权限。
    • 其他用户（others）权限：rw-，可读写。

权限相关的命令

1、确定文件的权限

  • 使用ls命令, 有关选项-l和-d
  • ls -l 可以查当前目录下所有文件和子目录的权限
  • ls -ld . 列出当前目录自身的权限

2、chmod 命令（字母形式）

  • chmod [ugoa][+-=][rwxst] 文件名：

    • [ugoa]：指定权限的对象：
      • u：用户（user），即文件主。
      • g：组用户（group），即与文件主同组的用户。
      • o：其他用户（other），即不属于同组的其他用户。
      • a：所有用户（all），包括文件主、组用户和其他用户。
    • [+-=]：权限操作符：
      • +：添加权限。
      • -：移除权限。
      • =：设定精确权限（覆盖原权限）。
    • [rwxst]：指定权限类型：
      • r：读权限（read）。
      • w：写权限（write）。
      • x：执行权限（execute）。
      • t：粘着位（sticky bit），通常用于目录，表示该目录下文件只能由文件主或超级用户删除。
      • s：SUID/SGID 位，SUID 让程序以文件所有者的权限执行，SGID 让程序以文件所属组的权限执行。

  • 示例说明

  • chmod u+rw *
    给文件主（u）添加读写权限（rw），作用于所有文件（*）。

  • chmod go-rwx *.[ch]
    对文件扩展名为 .c 或 .h 的文件，去除组用户和其他用户的读、写、执行权限（go-rwx）。

  • chmod a+x batch
    给文件 batch 添加执行权限（x），作用于所有用户（a）。

  • chmod u=rx try2
    将文件 try2 的用户权限精确设定为只读和执行权限（u=rx），移除其他权限。

3、chmod 命令的数字（八进制）形式

  • 每个权限位用一个八进制数字表示，数字对应的权限如下：

    • 4：读权限（r）
    • 2：写权限（w）
    • 1：执行权限（x）
    • 0：无权限（-）

  • 组合方式：

    • 读写权限（rw-）= 4 + 2 = 6
    • 只读权限（r--）= 4
    • 读和执行权限（r-x）= 4 + 1 = 5
    • 读、写和执行权限（rwx）= 4 + 2 + 1 = 7

  • 示例解析： chmod 644 xyz1 xyz2
    将文件 xyz1 和 xyz2 的权限设置为 644。

    • 644 的每一位含义：
      • 6（文件主）：rw-，文件主拥有读写权限。
      • 4（组用户）：r--，组用户仅有读权限。
      • 4（其他用户）：r--，其他用户仅有读权限。
    • 二进制表示为：110 100 100，即 rw- r-- r--。

  • 只有文件主和超级用户（root）才有权限使用 chmod 修改文件权限，其他用户没有权限更改文件权限。

4、umask 命令：控制新建文件或目录的初始权限

  1. umask 的作用
  • 屏蔽码：umask 会遮蔽掉某些权限位，从而控制文件和目录的初始权限。
    • 每个文件或目录在创建时，系统会根据默认的权限模板和 umask 值计算出最终权限。
    • 默认情况下，文件的权限模板为 666（可读写，无执行权限），目录的权限模板为 777（可读写执行）。
    • umask 值中的位会从默认模板中减去相应的权限。
  1. 权限计算方式
  • 文件权限 = 666 - umask
  • 目录权限 = 777 - umask
  • 例如，umask 为 022 时：
    • 新文件的权限为 666 - 022 = 644（可读写，无执行权限）。
    • 新目录的权限为 777 - 022 = 755（可读写执行，组用户和其他用户仅有读和执行权限）。
  1. 相关命令
  • umask：显示当前的 umask 值。例如，执行 umask 会输出一个四位八进制数（例如 0022 或 022），显示当前的屏蔽码。
  • umask 022：设置 umask 值为 022，表示新文件的初始权限为 644，新目录的初始权限为 755。
  1. 特点
  • umask 是进程的属性，会影响在该进程下创建的所有文件和目录。
  • 它是shell 的内部命令，可以直接在 shell 中设置，且会影响该 shell 下运行的所有命令的文件权限。

4、进程umask属性的作用

  1. 掩码值的含义 掩码值表示在创建新文件或目录时，要屏蔽掉的权限。它以八进制数表示，每一位对应于文件主、组用户和其他用户的权限。

  2. 掩码值示例

  • 掩码值：022
    • 二进制表示：000 010 010
    • 说明：
      • 第一位（文件主）：0，不屏蔽权限。
      • 第二位（组用户）：2（010），屏蔽组用户的写权限（w）。
      • 第三位（其他用户）：2（010），屏蔽其他用户的写权限（w）。
    • 效果：新创建的文件权限为 644（即 rw-r--r--），新创建的目录权限为 755（即 rwxr-xr-x）。
  1. 自动执行批处理文件
  • 通常，umask 命令会被放置在 shell 启动时自动执行的批处理文件中，例如：
    • $HOME/.bash_profile：这个文件在用户登录时被执行，可以在其中设置 umask 值，以便在每次登录时自动应用。
  1. 进程 umask 属性的作用
  • umask 是进程的属性：每个进程都有自己的 umask 值，决定该进程下创建的文件和目录的默认权限。
  • 当用户启动一个新的 shell 或脚本时，umask 值会影响所有在该 shell 中运行的命令和程序，确保创建的文件和目录遵循所设定的权限规范。
  • 通过设置 umask 值，用户可以强化安全性，限制其他用户对新文件或目录的访问权限。

5、系统调用 umask

  1. 修改进程的 umask 属性值：umask 调用允许程序动态地改变自身的 umask 值，从而影响之后创建的文件和目录的权限。

  2. 影响新创建文件的权限：当通过 open 系统调用创建新文件时，文件的初始权限由 open 调用中的权限值和进程的 umask 值共同决定。

  3. 不影响已存在文件的权限：对于已存在的文件，其权限设置不受 open 和 umask 的影响。即，改变 umask 只影响后续创建的文件。

  • 假设当前进程的 umask 值为 077，用 C 程序调用 open 创建文件：
int fd = open(filename, O_CREAT | O_WRONLY, 0666);
  • 0666 是 open 指定的权限，表示文件可以被所有用户读写。初始权限 0666 减去 umask 077 得到的实际权限为 0600，即文件只能被文件的创建者读写。

读取而不改变 umask 值：

  • 调用 umask 获取当前 umask 值，并记录。
  • 立即再调用一次 umask，将 umask 值设置为之前记录的值，这样实际 umask 值就保持不变。

SUID权限

1、三级权限存在的问题：系统中任一个用户，要么对文件的全部内容具有访问权，要么不可访问文件。有的情况下，很不方便。

2、在 Unix/Linux 系统中，进程的实际 UID（用户标识符）和有效 UID 是管理用户权限的重要概念，尤其是在处理 SUID（Set User ID）权限时。以下是对这些概念的详细解释：

3、实际 UID 和有效 UID

  1. 实际 UID:

    • 实际 UID 是指创建进程的用户的 UID，表示进程的真实所有者。
    • 例如，如果用户 liu 启动一个程序，则该程序的实际 UID 是 liu 的 UID。

  2. 有效 UID:

    • 有效 UID 用于决定进程在系统中可以执行哪些操作，特别是在访问文件和执行程序时。
    • 当一个程序具有 SUID 权限时，进程的有效 UID 会被设置为该程序的文件所有者的 UID，而实际 UID 保持不变。

4、SUID 权限:

  • 当一个可执行文件被设置为 SUID 时，用户在执行该文件时，将以文件所有者的权限执行。这使得用户能够在某些情况下访问其默认情况下无法访问的文件。
  • 例如，若文件 query 由用户 liu 拥有并设置为 SUID，则当任何用户（如 liang）执行 query 时，进程的有效 UID 将变为 liu 的 UID。

5、权限验证过程

  1. 打开文件:

    • 当进程调用 open() 等系统调用来打开文件时，系统会根据进程的有效 UID 和文件的所有者 UID 进行访问合法性验证。
    • 如果进程的有效 UID 与文件的所有者 UID 匹配，或者文件的权限设置允许当前用户访问，则访问将被允许。

  2. SUID 的访问控制:

    • 通过 SUID，用户可以通过文件主提供的程序访问文件，但这种访问是有限的，仅限于该程序的功能。
    • 例如，query 可能允许 liang 访问 liu 拥有的文件，但 liang 不能直接访问 list.txt，只有通过 query 才能实现。

6、示例

  1. 设置 SUID 权限:

    • 命令 chmod u+s query 为 query 文件设置了 SUID 权限。此时，文件的权限变化为 -rws--x--x，其中 s 表示 SUID 位已被设置。
    • 这意味着当任何用户运行 query 时，该程序将以 liu 的用户身份执行。

  2. 文件权限查看:

    • 执行命令 ls -l list.txt query 的输出如下： 
      -rw------- 1 liu leader 722 Dec 10 23:04 list.txt
-rws--x--x 1 liu leader 56134 Dec 10 23:07 query

  3. 用户 liang 运行 query:

    • 当用户 liang 运行 query 命令时，进程的有效 UID 将变为 liu 的 UID。因此，query 将能够以 liu 的权限来访问文件 list.txt。
    • 如果 query 程序的代码被编写为在内部读取 list.txt，则它可以成功访问该文件并返回所需的信息。
