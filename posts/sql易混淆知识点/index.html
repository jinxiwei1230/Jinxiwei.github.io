SQL易混淆知识点

1、partition by 和 group by的区别

GROUP BY

  • 用途: GROUP BY 用于将数据分组，并对每个分组进行聚合计算（如 SUM、AVG、COUNT 等）。

  • 结果: 它会将多行数据合并为一行，每个分组只返回一行结果。

  • 使用场景: 当你需要对数据进行分组并计算汇总值时使用。

  • 示例:

    SELECT dept_id, AVG(salary) AS avg_salary
FROM employees
GROUP BY dept_id;

    这个查询会返回每个部门的平均工资，每个部门只有一行结果。

  • 特点:

    • 分组后的结果会减少行数。
    • 只能选择分组字段和聚合函数的结果。

PARTITION BY

  • 用途: PARTITION BY 是窗口函数的一部分，用于在窗口函数中对数据进行分组，但不会减少行数。

  • 结果: 它不会将多行合并为一行，而是为每一行计算一个值（如排名、累计值等）。

  • 使用场景: 当你需要对数据进行分组计算，但希望保留原始行数时使用。

  • 示例:

    SELECT name, salary, dept_id,
       RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rank
FROM employees;

    这个查询会为每个部门的员工根据工资排名，但不会减少行数，结果中每一行都会保留。

  • 特点:

    • 分组后的结果不会减少行数。
    • 可以同时选择分组字段、原始字段和窗口函数的结果。

核心区别

特性 GROUP BY PARTITION BY
行数变化 减少行数（每个分组返回一行） 不减少行数（保留原始行数）
用途 数据分组和聚合 数据分组并计算窗口函数
是否支持聚合函数 是（如 SUM、AVG、COUNT 等） 否（窗口函数如 RANK、ROW_NUMBER）
结果字段 只能选择分组字段和聚合结果 可以选择原始字段和窗口函数结果

示例对比

使用 GROUP BY:

SELECT dept_id, COUNT(*) AS employee_count
FROM employees
GROUP BY dept_id;

结果:

dept_id employee_count
1 3
2 3
3 2
  • 每个部门只有一行结果，显示该部门的员工数量。

使用 PARTITION BY:

SELECT name, salary, dept_id,
       COUNT(*) OVER (PARTITION BY dept_id) AS employee_count
FROM employees;

结果:

name salary dept_id employee_count
Alice 5000 1 3
Bob 6000 1 3
Charlie 7000 1 3
David 5500 2 3
Eve 6500 2 3
Frank 8000 2 3
Grace 4500 3 2
Hank 5000 3 2
  • 每个部门的员工数量被计算出来，但原始行数保持不变。

什么时候要用 OVER ？

当你需要 计算某个统计值（如平均数、排名、累计和等），但又不想减少原表的行数，就应该使用 OVER 窗口函数。

使用 OVER 的场景

1. 需要同时看到原始数据和聚合结果

问题： 计算每个员工的薪资和其部门的平均薪资差距，同时保留每个员工的信息。

SELECT 
    name, 
    salary, 
    dept_id, 
    salary - AVG(salary) OVER (PARTITION BY dept_id) AS diff_from_avg
FROM employees;

什么时候用 OVER？

  • 你要 计算部门平均薪资（分组统计）
  • 但你又想 保留每个员工的原始数据
  • GROUP BY 不能用，因为它会丢失个别员工的信息

2. 计算排名

问题： 在每个部门内按薪资排名，找出薪资最高的员工。

SELECT 
    name, 
    salary, 
    dept_id, 
    RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rank
FROM employees;

什么时候用 OVER？

  • 你要 按照部门（dept_id）分区
  • 你要 计算排名，但仍要保留每个员工的原始数据

3. 计算累计值

问题： 计算每个员工 按照薪资排序后的累计薪资。

SELECT 
    name, 
    salary, 
    SUM(salary) OVER (ORDER BY salary) AS running_total
FROM employees;
  • 你要 计算累计薪资
  • 但你仍想 保留每个员工的信息

4. 计算每一行的百分比

问题： 计算每个员工的薪资占公司总薪资的比例。

SELECT 
    name, 
    salary, 
    salary / SUM(salary) OVER () AS salary_percentage
FROM employees;

什么时候用 OVER？

  • 你要 计算总薪资（SUM(salary)）
  • 但你仍然 需要每个员工的信息

OVER 什么时候不要用？

如果你只需要一个聚合值（而不需要原始数据），就用 GROUP BY！

SELECT dept_id, AVG(salary) 
FROM employees
GROUP BY dept_id;

这里不需要 OVER，因为 GROUP BY 直接返回部门级别的聚合数据。

总结：什么时候用 OVER？

需要计算聚合值（如平均值、排名、累计值等），但又想保留原始数据时，用 OVER。 如果你只想得到分组的汇总结果，而不关心每条记录，直接用 GROUP BY。

  • OVER() 保留所有行
  • GROUP BY 聚合后只返回分组结果

PARTITION BY RANGE 是用于表分区的

用于分区表时，PARTITION BY 是在 CREATE TABLE 语句中定义表的分区策略。 它的作用是将数据物理上分成不同的子表（分区），提升查询性能。

CREATE TABLE sales (
    sale_id SERIAL,
    sale_date DATE,
    amount NUMERIC
) PARTITION BY RANGE (sale_date);

🔹 作用：

  • sales 这张表是一个分区表（不存数据）。

  • PARTITION BY RANGE (sale_date) 表示数据会按 sale_date 进行范围分区。

  • 之后需要创建子分区，例如：

    CREATE TABLE sales_2024_01 PARTITION OF sales
    FOR VALUES FROM ('2024-01-01') TO ('2024-02-01');

📌 结论：

  • PARTITION BY RANGE 是用于表分区的，影响的是数据的存储方式。
  • 它决定数据存在哪个分区，提升查询效率。

窗口函数

查询每个部门薪资排名前 3 的员工姓名和薪资：

WITH ranked_employees AS (
    SELECT 
        name, salary, dept_id,
        RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rank
    FROM employees
)
SELECT name, salary, dept_id
FROM ranked_employees
WHERE rank <= 3;

2、函数（Function） 和 存储过程（Stored Procedure）:

方面 函数（Function） 存储过程（Stored Procedure）
返回值 必须返回一个值（标量、表或其他数据类型） 可以返回多个值，也可以不返回值
调用方式 可在 SELECT 语句中调用，如 SELECT my_function(args) 不能在 SELECT 语句中调用，需使用 CALL 或 EXEC
参数 只支持 IN 类型参数（输入参数） 支持 IN（输入参数）、OUT（输出参数）、INOUT（输入输出参数）
主要用途 适用于计算、数据转换等操作 适用于批量处理、业务逻辑封装
事务控制 不能使用事务（COMMIT、ROLLBACK） 可以使用事务控制
是否支持 TRY...CATCH 不支持 支持
是否可以修改数据库 不能执行 INSERT、UPDATE、DELETE 等 DML 语句（某些数据库如 SQL Server 支持表值函数进行 DML） 可以执行所有 SQL 语句，包括 DML 和 DDL
性能 适用于简单计算，执行速度快 适用于复杂逻辑，可能会稍慢

示例

1. 函数示例（计算两数之和）

CREATE FUNCTION add_numbers(a INT, b INT)
RETURNS INT
BEGIN
    RETURN a + b;
END;

调用：

SELECT add_numbers(10, 20);

2. 存储过程示例（插入数据）

CREATE PROCEDURE insert_student(IN name VARCHAR(50), IN age INT)
BEGIN
    INSERT INTO students (name, age) VALUES (name, age);
END;

调用：

CALL insert_student('Alice', 22);

3、树形表递归查询

树形结构表用于表示具有层级关系的数据。常见的例子包括组织结构、分类目录、评论回复等。categories 表的结构如下：

  • id: 节点的唯一标识。
  • name: 节点的名称。
  • parent_id: 父节点的 ID。如果节点是根节点，parent_id 通常为 NULL 或 0。

假设我们有一个 employees 表，表示公司员工的层级关系。每个员工有一个 manager_id，指向其上级经理的 id。表结构如下：

id name manager_id
1 Alice NULL
2 Bob 1
3 Charlie 2
4 David 2
5 Eve 3
6 Frank 4

查询某个员工（例如 id = 2，即 Bob）的所有下属（包括直接下属和间接下属）。

递归查询 SQL

WITH RECURSIVE subordinates AS (
    -- 基础查询：选择初始员工（Bob）
    SELECT id, name, manager_id
    FROM employees
    WHERE id = 2
    UNION ALL
    -- 递归查询：选择当前员工的所有直接下属
    SELECT e.id, e.name, e.manager_id
    FROM employees e
    JOIN subordinates s ON e.manager_id = s.id
)
-- 最终查询：返回所有下属
SELECT * FROM subordinates;

基础查询

SELECT id, name, manager_id
FROM employees
WHERE id = 2
  • 选择 id = 2 的员工（Bob）作为初始结果集。
  • 初始结果集：
id name manager_id
2 Bob 1

2. 递归查询

SELECT e.id, e.name, e.manager_id
FROM employees e
JOIN subordinates s ON e.manager_id = s.id
  • 每次递归都会查找当前结果集中员工的直接下属。
  • 递归过程：
    • 第一次递归：查找 manager_id = 2 的员工（Bob 的直接下属）。
      • 结果：Charlie（id=3）和 David（id=4）。
    • 第二次递归：查找 manager_id = 3 和 manager_id = 4 的员工。
      • 结果：Eve（id=5，Charlie 的下属）和 Frank（id=6，David 的下属）。
    • 第三次递归：查找 manager_id = 5 和 manager_id = 6 的员工。
      • 结果：没有更多下属，递归结束。

3. 最终结果

id name manager_id
2 Bob 1
3 Charlie 2
4 David 2
5 Eve 3
6 Frank 4
  • 递归查询通过 WITH RECURSIVE 实现，适用于树形结构或层级关系的数据。
  • 每次递归都会基于前一次的结果集进行扩展，直到没有更多数据。
  • 在这个例子中，我们查询了 id = 2（Bob）的所有下属，包括直接下属和间接下属。

查询某个员工的所有上级

如果我们想查询某个员工（例如 id = 5，即 Eve）的所有上级，可以这样写：

WITH RECURSIVE managers AS (
    -- 基础查询：选择初始员工（Eve）
    SELECT id, name, manager_id
    FROM employees
    WHERE id = 5
    UNION ALL
    -- 递归查询：选择当前员工的上级
    SELECT e.id, e.name, e.manager_id
    FROM employees e
    JOIN managers m ON e.id = m.manager_id
)
-- 最终查询：返回所有上级
SELECT * FROM managers;

结果

id name manager_id
5 Eve 3
3 Charlie 2
2 Bob 1
1 Alice NULL

4、索引优化

在 orders 表中，如何为 customer_id 和 order_date 设计联合索引以优化查询 WHERE customer_id = 100 AND order_date > '2024-02-10'？ 

CREAT INDEX customer_id_order_date_idx ON oeders(customer_id, order_date);

原理：联合索引按照最左前缀匹配原则，优先按照customer_id过滤，再按oeder_date查找。

5、事务与隔离级别

事务：用户定义的一个数据库操作序列，要么全做，要么全不做，是一个不可分割的单位。

ACID：

  • **原子性(atomicity):**事务是数据库逻辑单位，要么不做，要么全做。
  • **一致性(consistency):**数据库只包含成功事务提交的结果。
  • **隔离性(isaolation):**一个事务执行不能被其他事务干扰。
  • **持续性(durability):**事务一旦提交，对数据库的改变时永久的。

脏读：B事务读到了A事务回滚或撤销的错误数据。

不可重复读：A读取数据后，B执行修改操作，A再次读取数据时与前一次得到的值不一样。

幻读：A读取数据后，B执行插入或删除操作，A无法再次读取。

丢失修改：A和B同时读入一个数据，并各自修改，B提交的结果破坏了A提交的结果，导致A修改的数据丢失。

4类隔离级别：

  • 读未提交：允许一个事务读取另一个事务正在修改的未提交的事务。
  • 读已提交：只允许一个事务读请一个事务已经提交的数据。
  • 可重复读：一个事务开始读取数据后，其他事务就不允许再对该数据执行UPDATE操作。
  • 可串行化：最高的事务隔离级别，事务的执行顺序时可串行化的，可以避免丢失数据，脏读，不可重复读和幻读。
