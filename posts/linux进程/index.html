进程的基本概念和逻辑内存

1、进程与程序

  • 程序：

    • 是指令和数据的集合，存放在磁盘上的普通文件中。
    • 必须符合系统要求并标记为可执行文件。

  • 进程：

    • 是程序的运行实例，包括指令段、用户数据段和系统数据段。
    • 提供执行环境。

  • 程序与进程的关系：

    • 程序用于初始化进程的指令段和用户数据段，初始化后两者无直接联系。
    • 进程运行时，程序文件不可修改或删除。
    • 一个程序可以初始化多个进程，它们之间没有联系。
    • 内核可通过共享指令段或动态链接共享函数库来节省内存，对用户透明。

2、进程的组成部分

  • 指令段 (Text)：

    • 包含程序的CPU指令代码，包括主程序、子程序和调用的库函数代码。
    • 大小固定且只读。

  • 用户数据段(支持动态调整)：

    • 包括全局变量、静态变量、字符串常量等。
    • 支持动态内存分配，大小可通过 sbrk() 调整（单位为页）。
    • 使用库函数如 malloc() 和 free() 实现内存管理。

  • 用户栈段：

    • 提供程序执行所需的栈空间。
    • 用于保存子程序返回地址、传递参数，以及存储局部变量（非静态）。
    • 包含命令行参数和环境参数，初始化于 main 函数运行之前。
    • 支持动态增长，但有增长限制。

  • 系统数据段：

    • 包含内核维护的进程数据（如页表和进程控制块 PCB）。
    • 与指令段、数据段、栈段分离，由内核管理。

进程的执行状态

1、进程的系统数据（PCB）

  • 内存管理：

    • 页表：用于虚拟内存管理，占已分配虚拟内存的约 1/1024（32 位奔腾 CPU）。

  • 文件管理：

    • 打开的文件描述符表：记录进程打开的文件。
    • 当前目录：记录当前目录的 i 节点。
    • 根目录：记录根目录位置。

  • 进程状态信息：

    • 核心态堆栈：用于内核态操作，大小几 KB。
    • 进程状态：如运行、等待、就绪等。
    • 优先级：用于调度决策。

  • 标识信息：

    • PID（进程 ID）和 PPID（父进程 ID）。
    • 进程组号：进程所属的组号。

  • 权限管理：

    • 主 UID/GID：实际用户 ID 和组 ID。
    • 有效 UID/GID：用于权限验证。
    • umask 值：文件权限掩码。

2、传统 UNIX 的 user + proc 结构：

  • user 结构：

    • 大小约 5000 字节，定义在 <sys/user.h>。
    • 包含进程运行时需要的数据，如核心态堆栈（占较多空间）。
    • 进程运行时动态分配，仅运行时存在。

  • proc 结构：

    • 大小约 300 字节，定义在 <sys/proc.h>。
    • 存储进程不运行时需要的管理信息。
    • 始终存在，用于系统管理进程。

  • 用户对系统数据的访问：

    • 用户程序不能直接修改进程的系统数据。
    • 可通过系统调用（如 chdir, umask, open, close, setpgrp, getpid, getppid）访问或修改相关属性。

2、进程的基本状态：

  • 运行状态：

    • 进程被内核分配 CPU 时间片运行。

  • 睡眠状态（也称阻塞、等待或挂起状态）：

    • 进程条件未满足时进入睡眠状态，不占用 CPU 时间。
    • 条件满足后，进程从睡眠状态转为运行状态。

3、进程的调度机制：

  • 调度优先级：

    • 高优先级进程优先获得调度。
    • 进程优先级动态调整，睡眠状态的进程被唤醒时优先级提升，以提高对用户输入或设备操作的响应速度。

  • 优先级调整：

    • 用户程序可用 nice() 系统调用有限度地调整优先级。

4、ps命令：

  • 用于查阅进程状态（process status）,实际上是从内核中提取 PCB 数据并以选择性的方式显示。

常用选项：

  • 无选项：

    • 列出当前终端启动的进程。
    • 显示项目：PID，TTY，TIME，COMMAND。

  • -e：

    • 列出系统中所有进程（扩展进程范围）。

  • -f：

    • 以 full 格式列出进程，增加更多列信息。

  • -l：

    • 以 long 格式显示，提供详细的每进程属性。

ps 显示的主要进程属性：

  1. UID：用户 ID，标识进程所属用户。
  2. PID：进程 ID，唯一标识进程。
  3. PPID：父进程的 PID。
  4. STIME：进程启动时间。
  5. C：CPU 占用指数（短期 CPU 使用情况，算法因系统而异）。
  6. SZ：进程逻辑内存大小（单位：页）。
  7. TTY：终端名称，显示进程所属的终端设备。
  8. COMMAND：进程启动命令。
  9. WCHAN：进程睡眠通道，显示阻塞位置。
  10. TIME：累计 CPU 使用时间（单位：秒）。
  11. PRI：优先级，数值越低优先级越高。
  12. S：进程状态：
    • S (Sleep): 睡眠状态
    • R (Run): 运行状态
    • Z (Zombie): 僵尸状态

进程的执行时间

1、进程执行时间的组成：

  • 睡眠时间：进程处于睡眠状态的时间。
  • CPU 时间：包括以下两部分：
    • 用户时间：进程在用户态执行的时间。
    • 系统时间：进程在内核态执行的时间。

2、time 命令：

  • 外部命令 /usr/bin/time：
    格式：Real、User、System 时间。

    • Real：程序运行的总时间（墙上时钟时间）。
    • User：CPU 用户时间。
    • System：CPU 系统时间。

  • C-Shell 内部命令 time：
    输出格式包含更多信息，如 I/O 操作和内存使用。

4、与 CPU 时间相关的命令和系统调用：

  • vmstat：显示有关 CPU、内存、磁盘、分页和进程活动的信息

    1. 进程（procs）
    • r 等待运行的进程数（就绪队列中的进程）。
    • b 正在等待 I/O 的进程数（阻塞队列中的进程）。
    1. 内存（memory）
    • swpd 使用的虚拟内存大小（以 KB 为单位）。
    • free 系统中空闲内存的大小（以 KB 为单位）。
    • buff 用于缓冲的内存大小（以 KB 为单位）。
    • cache 用于缓存的内存大小（以 KB 为单位）。
    1. 分页（swap）
    • si 每秒从磁盘换入的内存页数（swap in）。
    • so 每秒换出的内存页数（swap out）。
    1. 块设备 I/O（io）
    • bi 每秒从块设备（如硬盘）读取的数据块数。
    • bo 每秒写入块设备的数据块数。
    1. 系统（system）
    • in 每秒中断的次数。
    • cs 每秒上下文切换的次数（反映多任务切换频率）。
    1. CPU（cpu）
    • us 用户态占用的 CPU 时间百分比。
    • sy 系统态占用的 CPU 时间百分比。
    • id CPU 空闲时间百分比。
    • wa I/O 等待占用的 CPU 时间百分比。
    • st 被虚拟机抢占的 CPU 时间百分比。

  • times() 系统调用：返回当前进程和子进程的 CPU 使用时间：

    • 结构体 tms：
      • tms_utime：用户 CPU 时间。
      • tms_stime：系统 CPU 时间。
      • tms_cutime：子进程的用户 CPU 时间。
      • tms_cstime：子进程的系统 CPU 时间。
    • clock()：返回 times() 的总 CPU 时间，单位是 1/CLOCKS_PER_SEC 秒。

  • getrusage() 函数：

    • times() 的升级版，提供更多信息，如内存使用量、I/O 次数、进程切换次数等。

5、与时间管理相关的函数：

  • time()：获取当前时间坐标（秒级精度）。
  • gettimeofday()：获取当前时间，精确到微秒（μs）。
  • mktime()：将年月日时分秒转换为时间坐标值。
  • ctime() / asctime() / localtime()：时间坐标与年月日时分秒的转换。
  • strftime()：自定义日期和时间字符串格式。

6、忙等待问题：

  • 忙等待缺点：浪费 CPU 资源，在多任务系统中不可取。
  • 解决方案：
    • 使用 sleep(1) 设置轮询间隔为 1 秒。
    • 使用 select() 可将睡眠时间精确到 10 毫秒级。

进程的生命周期：从生到死

fork 系统调用

1、核心功能：创建一个新进程，是创建进程的唯一方式。

2、内存复制机制

  • 完全复制：指令、用户数据段、堆栈段。
  • 部分复制：系统数据段。
  • 优化技术：现代系统使用 写时复制 (Copy-On-Write, COW)，延迟实际内存的复制操作，只有当父或子进程尝试修改共享数据时才执行真正的复制。

3、fork 的返回值

  • 父进程：返回子进程的 PID（正整数）。
  • 子进程：返回 0。
  • 失败：返回 -1，并设置 errno。

4、内核的实现

  • 创建新的 PCB：为子进程分配独立的进程控制块 (PCB)。
  • 复制父进程环境：包括 PCB 信息、内存资源等。
  • 共享资源：对程序员透明，父子进程共享部分资源（如文件描述符等）。

命令行参数与环境参数

1、命令行参数

  • 位置：位于进程堆栈底部的初始化数据。
  • 传递方式：
  • 命令行参数通过 main() 函数的参数 argc 和 argv 传递：
    • argc：表示命令行参数的个数，包括程序名。
    • argv：是一个指针数组，存储每个命令行参数的地址。
  • 例：./program arg1 arg2 中：
    • argc = 3
    • argv[0] = "./program"
    • argv[1] = "arg1"
    • argv[2] = "arg2"

2、环境参数

  • 定义：用于传递系统环境信息，例如路径、主目录、终端类型等。
  • 访问方法：
    1. 通过外部变量 environ：全局外部变量，直接遍历 environ 指针数组打印所有环境变量。 
      extern char **environ;
char **p = environ;
while (*p) printf("[%s]\n", *p++);
    2. 通过 main 函数的第三个参数：env 参数与 environ 指向相同内容，功能一致。 
      main(int argc, char **argv, char **env) {
    char **p = env;
    while (*p) printf("[%s]\n", *p++);
}
    3. 通过 getenv 函数：返回指定环境变量的值，常用于快速查询特定环境信息，如 HOME、PATH 等。 
      char *p = getenv("HOME");
if (p) printf("[%s]\n", p);

exec 系统调用

1、功能

  • exec 系统调用用于用一个指定的程序文件重新初始化当前进程。
  • 它会加载新的程序，替换当前进程的指令段、用户数据段、堆栈段，以及更新 CPU 的程序计数器 (PC)。
  • 注意：exec 并不会创建新进程，而是将当前进程的执行内容替换成新程序的内容，进程 ID (PID) 不变。
  • 可以指定新的命令行参数和环境变量，重新初始化进程堆栈。
  • 调用 exec 后，原进程的代码、数据和堆栈将完全被新程序覆盖。

2、6 种格式的 exec 系统调用

  1. execl (list)

    • 形式：使用参数列表形式传递命令行参数。
    • 例： 
      execl("/bin/ls", "ls", "-l", NULL);
    • 参数是通过一个个独立的参数传递给函数，最后以 NULL 结束。

  2. execv (vector)

    • 形式：使用指针数组的形式传递命令行参数。
    • 例： 
      char *args[] = { "ls", "-l", NULL };
execv("/bin/ls", args);
    • 这里，命令行参数以数组的形式传递给 execv，数组末尾需加 NULL 作为结束标志。

  3. execle (list + environment)

    • 形式：类似 execl，但是可以指定环境变量。
    • 例： 
      execle("/bin/ls", "ls", "-l", NULL, environ);
    • 环境变量 environ 被显式地传递给新的进程，替代默认的环境。

  4. execve (vector + environment)

    • 形式：类似 execv，但也可以指定环境变量。
    • 例： 
      char *args[] = { "ls", "-l", NULL };
execve("/bin/ls", args, environ);
    • 与 execv 相似，参数通过数组传递，同时环境变量通过 environ 传递给新的进程。

  5. execlp (list + path)

    • 形式：类似 execl，但在寻找可执行文件时使用 PATH 环境变量。
    • 例： 
      execlp("ls", "ls", "-l", NULL);
    • 不需要提供绝对路径，execlp 会自动查找系统 PATH 环境变量指定的目录来寻找可执行文件。

  6. execvp (vector + path)

    • 形式：类似 execv，但是会使用 PATH 环境变量来查找可执行文件。
    • 例： 
      char *args[] = { "ls", "-l", NULL };
execvp("ls", args);
    • 参数通过数组传递，命令名会根据 PATH 进行查找，类似于 execlp。

总结

  • exec 系统调用用于将当前进程的代码替换为新程序的代码，进程不变，但执行内容改变。
  • 命令行参数传递方式：
    • l：通过参数列表传递。
    • v：通过指针数组传递。
    • e：可以指定新的环境变量。
    • p：通过 PATH 环境变量查找可执行文件。

*“僵尸”进程 (Zombie Process)

1、概念

  • 僵尸进程是指一个已经终止（退出）但其父进程尚未调用 wait() 或 waitpid() 等系统调用来读取其退出状态的进程。
  • 这些进程的资源已经被操作系统回收，包括内存和其他系统资源，但仍然保留在内核中，仅占用少量的内核进程表条目。
  • 僵尸进程的存在是为了记录进程的终止状态，直到父进程来收集这些信息（通过 wait() 或 waitpid()）。
  • 一旦父进程“收尸”完成，僵尸进程就会从进程表中移除。
  • 虽然僵尸进程不占用太多资源，但如果有大量的僵尸进程，可能会耗尽系统的进程表，导致无法创建新进程。

2、孤儿进程

  • 孤儿进程是指其父进程在其终止之前已经退出的进程。孤儿进程会被 init 进程（PID为1的进程）接管。
  • init 进程会周期性地调用 wait() 来清理其“收养”的孤儿进程，从而避免形成僵尸进程。

3、wait() 系统调用

  • wait() 是父进程用来等待其子进程终止的系统调用。如果子进程已终止，wait() 会立即返回，否则它会使父进程阻塞，直到有子进程终止。
  • 功能：父进程可以通过调用 wait() 来获取子进程的终止状态。

字符串库函数：strtok strtok 函数用于将一个字符串分割成一系列的子字符串（通常称为“单词”或“token”），并返回每个子字符串的指针。该函数会逐步遍历输入字符串，按照指定的分隔符进行拆分。

system() 函数的功能 system() 用于在程序中执行一个 shell 命令。它会启动一个新的子进程，执行由字符串参数传递的命令。执行完毕后，子进程会终止，父进程会等待子进程完成执行。
