第九章 Shell的基本原理

shell 概述

1、 Unix Shell 概述 Shell是Unix操作系统中的命令解释器，是用户与操作系统交互的桥梁。它通过解析和执行用户输入的命令，向操作系统内核发出指令。

2、 Shell的功能

  1. 命令解释器：Shell是用户与系统的接口，解释和执行用户的命令。
  2. 文件名替换、命令替换、变量替换
  3. 历史替换与别名替换
  4. 流程控制的内部命令

3、 Shell的特点

  • 主要用途：适用于批处理，能自动化执行大量任务，但在执行效率上比一些算法语言稍低。
  • 编程风格：Shell脚本语言是面向命令处理的，流程控制结构通过对内部命令的解释实现，简洁灵活。

4、 常见的Shell种类

  1. Bourne Shell (B-shell)：最早广泛应用的Shell，是早期UNIX的标准Shell，路径为/bin/sh。
  2. C Shell (C-shell)：路径为/bin/csh，最早应用于BSD系统。
  3. Korn Shell (K-shell)：是B-shell的超集，路径为/bin/ksh，支持类型变量和数组。
  4. Bourne Again Shell (bash)：Linux系统的标准Shell，路径为/bin/bash，兼容B-Shell并吸收了C-shell的特性，提供方便的命令行编辑功能。

bash 启动

1、启动交互式bash

  1. 注册 Shell：通过系统注册的方式启动 bash 作为用户的默认登录 shell。
  2. 键入 bash 命令：在命令行中输入 bash，进入一个新的交互式 shell 实例。
  3. 脚本解释器：通过执行 bash 脚本文件，将命令批量自动执行。

2、Bash 的启动与退出行为

  1. 用户偏好的自动执行命令 - 作为注册 Shell 启动时：自动执行用户主目录中的 .bash_profile 文件。该文件通常位于 ~/.bash_profile 或 $HOME/.bash_profile，用于设置用户的环境变量和启动项。 - 作为注册 Shell 退出时：自动执行 $HOME/.bash_logout 文件中的命令，用于用户退出登录时清理环境。 - 作为交互式 Shell 启动时：自动执行 $HOME/.bashrc 文件。该文件通常包含别名、环境变量和交互命令的配置，适用于每次打开新的 shell 会话时执行。 > 注意：如 umask 等命令应写在 .profile 文件中，以便在所有登录会话中生效。

  2. 系统级的自动执行命令 - 作为注册 Shell 启动时：系统自动执行 /etc/profile 文件，设置所有用户的系统级环境变量。 - 作为交互式 Shell 启动时：系统自动执行 /etc/bash.bashrc 文件，用于定义系统范围的别名、变量和函数。 - 作为注册 Shell 退出时：自动执行 /etc/bash.logout 文件中设置的命令，适用于所有用户的退出操作。

2、脚本文件

3、执行脚本文件的几种方式

  1. 使用 bash < lsdir
  • 命令：bash < lsdir
  • 描述：通过输入重定向的方式执行脚本，将 lsdir 文件的内容传递给 bash 解释器。
  • 特点：生成一个新的子进程执行脚本，但 无法携带命令行参数。
  1. 使用 bash lsdir
  • 命令：bash lsdir 或 bash lsdir /usr/lib/gcc
  • 描述：直接用 bash 解释器执行脚本，可以携带命令行参数。
  • 特点：生成一个新的子进程执行脚本。
  1. 使用 bash -x lsdir
  • 命令：bash -x lsdir
  • 描述：以调试模式执行脚本。-x 选项会将每一条执行的命令逐行打印，便于查看脚本的执行过程。
  • 特点：生成一个新的子进程，并以调试模式运行，适合用于调试脚本。
  1. 给脚本文件设置可执行权限后直接执行
  • 命令： 
    chmod u+x lsdir    # 设置可执行权限
./lsdir /usr/lib/gcc
  • 描述：通过 chmod u+x 为 lsdir 脚本赋予执行权限，之后可以直接使用 ./lsdir 执行脚本。
  • 特点：生成一个新的子进程执行脚本，./ 表示在当前目录中执行脚本。
  1. 在当前 Shell 进程中执行脚本
  • 命令：. lsdir /usr/lib/gcc 或 source lsdir /usr/lib/gcc
  • 描述：使用 . 或 source 运行脚本，这两种方式都会在 当前 Shell 进程 中执行脚本，而不是新创建子进程。
  • 特点：适用于需要在当前 Shell 中执行脚本的场景，例如，执行脚本中的变量定义或环境变量设置使其在当前 Shell 中生效。
  1. 总结
    方法 是否创建新进程 是否可携带参数 适用场景
    bash < lsdir 是 否 不需参数的简单脚本执行
    bash lsdir 是 是 标准脚本执行
    bash -x lsdir 是 是 调试脚本
    ./lsdir 是 是 脚本已赋执行权限的标准执行
    . lsdir / source lsdir 否 是 在当前 Shell 中运行脚本

历史与别名

1、历史表

  • 存储机制：历史表记录先前输入的命令，按编号递增，以 FIFO 方式刷新。

  • 大小控制：历史表大小由 HISTSIZE 控制。设置方法：

    echo "HISTSIZE=500" >> ~/.bashrc

  • 查看历史：

    • history：查看当前会话的历史命令。
    • $HOME/.bash_history：退出 Bash 时保存命令记录的文件。

2、历史替换

  • 上下箭头键

  • !!：引用上一条命令。

  • !str：引用以 str 开头的最近执行过的命令。例如：

  • Ctrl + R：输入部分命令后按 Ctrl + R 可以快速查找历史命令。

输入重定向

  1. 从文件获取标准输入 <filename
  • 使用 < 将文件内容作为标准输入提供给命令。 sort < telno.txt 将 telno.txt 文件的内容作为输入传递给 sort 命令进行排序。
  1. 从 Shell 获取标准输入：允许替换 <<word
  • 使用 << 可以从 Shell 脚本中获取数据，直到再次遇到指定的定界符 word。在这种模式下，Shell 会进行变量替换和命令替换。 
    cat << TOAST
* Now : `date`
* My Home Directory is $HOME
TOAST
    • 输出： 
      * Now : Thu Nov 7 10:00:00 UTC 2024
* My Home Directory is /home/user
  1. 禁止替换的输入重定向：不允许替换 <<'word'

  • 使用定界符两侧的单引号 '，Shell 不会对定界符之间的内容进行变量替换或命令替换。

    cat << 'TOAST'
* Now : `date`
* My Home Directory is $HOME
TOAST
    • 输出： 
      * Now : `date`
* My Home Directory is $HOME
  1. 从命令行获取信息作为标准输入 <<<word
  • 使用 <<< 可以将命令行输入作为标准输入传递给命令。 
    base64 <<< meiyoumima
    将字符串 meiyoumima 转换为 Base64 编码。

输出重定向与管道

  1. 标准输入：stdin,fd=0 标准输出：stdout,fd=1 标准错误输出：stderr,fd=2

  2. 使用系统调用 (原始 I/O) 的程序示例 使用 write 函数直接将数据输出到标准输出 (stdout) 和标准错误 (stderr)，数据不经过缓冲区，直接传输到目标文件描述符。 这种方式属于原始 I/O，效率较低，但对于实时性要求较高的任务（如错误日志）是合适的。

  • write(1, str1, strlen(str1));：将 str1 写入文件描述符 1（即 stdout）。
  • write(2, str2, strlen(str2));：将 str2 写入文件描述符 2（即 stderr）。
  1. 区别
  • 原始 I/O：直接使用系统调用，如 write，数据立即写入，不经过缓冲区。
  • 缓冲 I/O：使用 C 标准库函数，如 printf、fprintf，数据经过缓冲区后再输出，更适合效率要求高的场景。
  1. 标准输出 (stdout) 重定向
  • >filename：将标准输出重定向到文件 filename，如果文件已存在，会先清空文件内容。
  • >>filename：将标准输出追加到文件 filename 尾部，而不覆盖原内容。

  1. 标准错误 (stderr) 重定向 2> filename：将标准错误输出 (文件描述符 2) 重定向到文件 filename。

  2. 分离 stdout 和 stderr

  • 2>&1：将标准错误输出重定向到与标准输出相同的地方。 
    command > output.log 2>&1
    把 command 的标准输出和标准错误都重定向到 output.log。
  1. 多文件句柄重定向
  • ./myapp 5< a.txt 6> b.dat：指定应用程序 myapp 使用文件描述符 5 从 a.txt 读取输入，使用文件描述符 6 将输出写入 b.dat。
  1. 输出重定向示例

  • 示例 1：将标准输出和标准错误分别重定向到不同的文件。

    try > try.out 2> try.err

    或

    try 1> try.out 2> try.err

  • 示例 2：将标准输出定向到 try.out，忽略标准错误。

    ./stda 1> try.out 2> /dev/null
  1. 标准输出和标准错误一起重定向

  • 正确用法：

    ./stda > rpt 2>&1

    在这个例子中，stdout 和 stderr 都被重定向到 rpt 文件中。

  • 错误用法：

    ./stda 2>&1 > rpt

    这里，stderr 被重定向到当前的终端（默认目标），而 stdout 被重定向到 rpt 文件。因为 2>&1 指令将 stderr 重定向到 stdout 当前的目标（即终端），然后 stdout 再被重定向到 rpt，这就导致 stderr 依然输出到终端而不是 rpt 文件。

  1. 管道 (Pipeline) 用法

  • ls -l | grep '^d'： 前一命令的stdout作后一命令的stdin

  • 同时重定向 stdout 和 stderr 到管道：

    cc try.c -o try 2>&1 | more

    前一命令的stdout+stderr作为下一命令的stdin

变量的赋值及使用

  1. 变量赋值和引用
  • 赋值： 
    addr=20.1.1.254  # 赋值时等号两侧不能有空格
  • 引用：
    • 使用 $addr 或 ${addr}，如： 
      echo ${addr}A    # 正确，输出 "20.1.1.254A"
echo $addrA      # 错误，因 shell 无法识别变量边界
  • 特殊字符：
    • 赋值时包含空格等特殊字符需要加引号： 
      unit="Beihang University"
echo $unit       # 输出 "Beihang University"
  1. 未定义变量
  • 使用未定义变量时默认为空字符串： 
    echo Connect to $proto Network  # 输出 "Connect to  Network" (若 proto 未定义)
  1. Shell内部开关
  • set -u：若引用未定义变量则报错。
  • set +u：引用未定义变量时默认为空串（默认）。
  • set -x：执行命令前显示替换后的命令，前面带 + 号。
  • set +x：关闭上述显示。
  1. echo 命令

  • echo arg1 arg2 arg3 ...：打印命令行参数，参数之间用空格分隔，最后带换行。

  • 转义字符（需要 -e 选项以支持转义，Linux中常用）：

    • \c：不换行
    • \b：退格
    • \n：换行
    • \r：回车
    • \t：水平制表
    • \\：反斜线
    • \nnn：八进制表示ASCII字符

  • 示例：

echo Beijing China                 # 输出：Beijing China
echo "Beijing China"               # 输出：Beijing China
echo -e '\065'                     # 输出字符 '5'（八进制 ASCII 065）
cnt=10
echo -e "\\r$cnt \\c"              # 回车后打印变量 cnt 的值，不换行
  1. printf 命令

  • printf 用法与 C 语言 printf 类似，支持格式化输出。

  • 语法：printf '格式' 参数

  • 示例：

proto="TCP/IP"
printf '\033[01;33mConnect to %s Network\n\033[0m' $proto
#\033[01;33m：设置文本为黄色。
#\033[0m：恢复默认颜色（通常为白色）。

环境变量

1、环境变量和局部变量

  • 默认类型：所创建的shell变量，默认为局部变量

  • 内部命令 “export”：局部变量转换为环境变量，例如：export proto

  • 局部变量和环境变量

    • shell启动的子进程继承环境变量，不继承局部变量
    • 子进程对环境变量的修改，不影响父进程中同名变量 （环境变量的设置，如PATH，
    • CLASSPATH，LANG，如果必要的话，放在~/.bashrc中或/etc/profile中）

2、系统的环境变量

  • 创建：登录后系统自动创建一些环境变量影响应用程序运行

  • HOME: 用户主目录的路径名

  • PATH: 命令查找路径

    • 与DOS/Windows不同的是,它不首先搜索当前目录
    • PATH=/bin:/usr/bin:/etc
    • PATH=.:bin:/usr/bin:/etc 先搜索当前目录(危险!)
    • PATH=/bin:/usr/bin:/etc:. 后搜索当前目录(危险!)

  • TERM: 终端类型 全屏幕操作的软件(如vi)，使用它搜索终端库 （环境变量的赋值对某个应用程序，包括java虚拟机以及其他的系统软件，有什么影响，与这个AP的设计相关，需要 查阅相关的手册）

3、相关命令：set/env 内部命令set列出当前所有变量及其值以及函数定义

  • 包括环境变量和局部变量、函数定义
  • set | grep ^fname=

外部命令/bin/env列出环境变量及其值

4、Shell脚本中通过$引用环境变量，可以在脚本内部设置环境变量，但如果需要子进程继承这些变量，需要使用export。 C程序通过getenv()获取环境变量的值，C程序的子进程会继承Shell环境变量，但需要通过Shell设置和导出。 环境变量是进程特有的，只在当前进程及其子进程中有效，当退出Shell时，环境变量消失

shell替换

1. 文件名生成（Glob Expansion）

Shell会根据文件通配符（如*、?、[]等）来生成匹配的文件列表。这种扩展在命令执行之前完成。

  • 例如：ls *.c
    • 如果当前目录下有a.c和x.c，Shell会将*.c替换为a.c x.c，然后执行ls a.c x.c。
    • 如果没有匹配的文件，*.php将不会展开，保持原样。

2. 变量替换

Shell允许在命令中引用变量，使用$符号来替代变量的值。

echo "My home is $HOME, Terminal is $TERM"

这行会输出类似 My home is /home/user, Terminal is xterm（具体路径和终端类型视环境而定）。

3. 命令替换（Backticks 和 $()）

命令替换允许你把命令的输出结果插入到另一个命令中。可以使用反引号（ ） 或 $()。

  • 反引号：

    now=`date`
./arg `date`

    执行时，date命令会返回当前日期，./arg命令会接收到日期作为参数。

    ts=`date '+%Y%m%d-%H%M%S'`
mv myap.log `whoami`-$ts.log
frames=`expr 5 + 13`

  • $()： 使用$()替代反引号更加清晰易读，且支持嵌套命令替换。

    now=$(date)
./arg $(date)

    执行时，输出相同，date的输出会作为参数传递给./arg。

    示例：

    ts=$(date '+%Y%m%d-%H%M%S')
mv myap.log $(whoami)-$ts.log
frames=$(expr 5 + 13)

4. 内部变量

  • $0：脚本本身的名称。
  • $1, $2, …：脚本的第一个、第二个参数。
  • $#：传递给脚本的参数个数。
  • "$*"：将所有参数作为一个单独的字符串传递，参数之间用空格分隔。
  • "$@"：每个参数单独处理，作为单独的字符串，适合传递给其他命令。

5. 位置参数举例

shift 命令 shift命令用来改变位置参数。每次shift操作会使位置参数向左移动一个位置，$#的值减1。

  • 例如： 
    shift 3
    这将会使$4变为$1，$5变为$2，依此类推。

示例脚本：param.sh

echo $#          # 输出参数个数
echo "Usage: $0 arg1 arg2 ..."
./arg "$@"       # 将所有参数传递给./arg
./arg "$*"       # 等同于"./arg $1 $2 $3 ..."

$ ./param.sh Copy Files to $HOME

执行时，$@和$*都会把所有参数传递给其他命令，$#输出参数个数。

元字符

shell元字符

空格,制表符 命令行参数的分隔符 回车 执行键入的命令 > < | 重定向与管道 (还有||) ; 用于一行内输入多个命令(还有;;) & 后台运行 (还有&&) $ 引用shell变量

  1. 空格和制表符（Tab） 空格和制表符用于分隔Shell命令的参数。
$ echo "Hello World"

这里的Hello和World是两个参数，空格将它们分开。

  1. 回车（Enter） 回车用于执行Shell命令。按下回车键时，Shell会执行当前行的命令。

  2. 重定向与管道

  • > 和 <（重定向）

    • >：将输出重定向到文件（覆盖文件内容）。
    • <：将文件内容作为输入传给命令。

  • |（管道） 管道用于将一个命令的输出作为另一个命令的输入。

  • ||（逻辑“或”） 只有当前一个命令失败时，才会执行后一个命令。

  1. ;（命令分隔符） 分号允许在一行内执行多个命令，Shell会按顺序依次执行它们。
$ echo "First Command"; echo "Second Command"
  • ;;：用于Shell脚本中的case语句中，标识一个case分支的结束。
  1. &（后台执行） **&**将命令放在后台执行，Shell不会等待命令执行完毕，会立即返回提示符。
$ sleep 5 &  # 该命令会在后台执行，不会阻塞Shell
  • &&（逻辑“与”）：只有当前一个命令成功执行时，才会执行下一个命令。

  1. $（引用Shell变量） 使用$来引用Shell变量的值。

  2. `（反引号）：命令替换 反引号用于将命令的输出作为字符串替换。 或者使用$()来代替反引号，后者更加易读和支持嵌套命令替换。

  3. *, [ ], ?（文件通配符）

  • *：匹配任意多个字符。
  • ?：匹配单个字符。
  • [ ]：匹配括号内的字符集。
  1. \（转义字符） 反斜杠\用于取消后面字符的特殊作用，即转义字符。它可以让特殊字符作为普通字符使用。

  • 转义特殊字符：

    $ echo "This is a \$ sign"  # 输出：This is a $ sign
$ echo "A quote: \"hello\"" # 输出：A quote: "hello"
$ echo "file\ name"         # 输出：file name

  • 转义文件名中的空格：

    $ ls file\ name.txt  # 转义空格，列出 file name.txt 文件
  1. ()（括号）

  • 用于在子Shell中执行一组命令。括号内的命令会在一个新的Shell环境中执行，父Shell的环境不会被影响。

    $ (echo "Hello from Subshell")  # 在子Shell中执行命令

  • 定义Shell函数：

    $ function greet() { echo "Hello, $1"; }
$ greet World  # 输出：Hello, World
  1. 组合符号的分隔作用 ( ), ><, |, ;&等符号既可以作为分隔符，又可以作为元字符具有特殊作用。例如：
$ ls > file.txt; wc -l file.txt & sort < file.txt | uniq

解释：

  • >：重定向输出到file.txt
  • ;：分隔命令，先执行ls，然后执行wc -l file.txt
  • &：wc -l在后台运行
  • <：从file.txt读取数据
  • |：管道将sort命令的输出传递给uniq
  1. 引号的作用

  • 双引号 "：双引号内的特殊字符（如 $ 和 `）仍会被解释，但其他字符（如空格）会被保留为字面量。

    $ echo "My home dir is $HOME"  # 输出：My home dir is /home/user
$ echo "My home dir is \$HOME" # 输出：My home dir is $HOME

  • 单引号 '：单引号内的所有字符都被当作普通字符处理，不会有任何特殊解释。

    $ echo 'My home dir is $HOME'  # 输出：My home dir is $HOME

引号及转义处理

1、 常见的转义字符

  • 反斜杠 \：本身就是转义符，用于转义后面的字符。

  • $：在字符串中表示变量，需要转义时使用\$。

  • 双引号 "：需要转义时，使用 \" 来表示字面上的双引号。

  • 单引号 '：在字符串中，单引号本身不能直接使用，如果要在单引号内使用单引号，必须使用两对单引号 '\''。

  • 反撇号 `：用来执行命令替换，在字符串中如果需要反撇号，则使用 ```。

    value="World"
echo "Hello, \"$value\"!"  # 输出：Hello, "World"!

echo 'This is a single quote: '\''Hello'\'''
# 输出：This is a single quote: 'Hello'

2、 C语言中的转义字符 在C语言中，转义字符用于处理字符串中的特殊字符，如换行符、制表符、引号等。常见的转义字符包括：

  • \n：换行符
  • \t：制表符
  • \\：反斜杠
  • \"：双引号
  • \：转义符本身

3、 正则表达式中的转义字符

  • \.：匹配一个字面上的点号。
  • \*：匹配一个字面上的星号。
  • \[：匹配一个字面上的左方括号。
  • \]：匹配一个字面上的右方括号。
  • \( 和 \)：匹配字面上的括号。

示例：正则表达式中的转义

# 匹配文件名中的点（.）
grep "\.txt" filenames.txt

# 匹配字面上的星号（*）
grep "file\*name" filenames.txt

4、 应用场景：使用转义字符

$ ls Data\ File.txt  # 使用反斜杠转义空格

Shell脚本中的转义 在Shell脚本中，如果要打印特定的字符（如控制字符或格式化字符），可以使用转义序列。例如，\033[H是控制台的光标移动命令，常用于清屏或定位。

# 清屏并显示特定信息
printf "\033[2J\033[H value = [$value]\n"

在配置文件中使用转义 在配置文件中（如.conf文件），如果某个字段包含特殊字符（如IP地址），需要确保这些字符在匹配时不被Shell或正则表达式误解。

# 假设需要匹配包含IP地址的行
grep "192\.168\.[0-9]*\.[0-9]*" config.conf
