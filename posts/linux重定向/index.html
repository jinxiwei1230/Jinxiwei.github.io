进程与文件描述符

活动文件目录（AFD）及文件管理系统分析

1、磁盘文件目录（Disk File Directory） 磁盘文件目录通常包括两级：

  • 文件名：文件在磁盘上的名字。
  • i节点：每个文件在文件系统中的元数据（inode）记录，包含文件的属性，如文件大小、权限、创建时间、修改时间等。 在磁盘上的文件目录结构中，文件名和对应的 i 节点是最重要的信息。i 节点为文件提供了关于文件内容的描述，但是不包含文件的实际数据。

2、活动文件目录（Active File Directory） 活动文件目录通常分为三级，其中包括文件描述符表（FDT）、系统文件表（SFT）和活动 i 节点表（AIT）。

  1. 文件描述符表（FDT） 每个进程都有的一张表，通常存储在进程的 PCB（进程控制块）的 user 结构中。 FDT 维护每个进程打开的文件的描述信息。它的主要作用是将文件描述符（fd）映射到具体的文件操作，如文件读写等。
  • 文件描述符：fd 是进程打开的文件在 u_ofile 数组中的下标，每个进程有一张自己的文件描述符表。
  • user 结构：在每个进程的 user 结构中，整型数组 u_ofile 用来记录该进程已打开的文件。u_ofile 数组的下标即为文件描述符（fd）。
  1. 系统文件表（SFT） 系统文件表（SFT）是整个操作系统共享的一张表，存储在内核中，包含对文件的管理信息。每个文件在系统中有一个 file 结构，该结构包含文件的操作标志、引用计数、偏移量和对应的 i 节点等信息。
  • struct file: 
    struct file {
    char f_flag;      // 读写操作标志（例如：只读、只写等）
    char f_count;     // 文件的引用计数
    long f_offset;    // 文件读写位置指针
    int f_inode;      // 文件的 i 节点索引
};
  1. 活动 i 节点表（AIT） 活动 i 节点表存储了操作系统内核当前正在使用的 i 节点，整个系统只有一张活动 i 节点表。它缓存了磁盘上对应的 inode 信息，避免每次访问文件时都需要从磁盘读取。
  • inode 结构：i 节点描述了文件的元数据，例如文件权限、所有者、文件大小、时间戳等信息。
  • 引用计数：内存中的 i 节点表有一个专用的引用计数，用来记录 i 节点当前被多少个进程引用。如果一个进程打开了一个文件，i 节点的引用计数会增加。引用计数为零时，表示该 i 节点已经不再被使用，可以释放。

3、各表结构的关系

  • FDT 与 SFT 的关系：每个进程的文件描述符表（FDT）指向系统文件表（SFT）中的某一项。在 FDT 中，文件描述符是 u_ofile 数组的下标，而在 SFT 中，每一个 file 结构对应着打开的文件，file 结构包含文件的状态信息。
  • SFT 与 AIT 的关系：SFT 中的 file 结构包含一个指向活动 i 节点的指针，表示文件的元数据。每个文件的 i 节点信息可以通过 SFT 访问，系统文件表负责管理文件的访问和更新。
  • 内存 inode 表：缓存了外存 inode 的数据，以便快速访问。内存中的 inode 是对磁盘 inode 的缓存，提供了对文件元数据的快速读取。

4、系统文件管理流程

  1. 分配文件描述符：操作系统为进程分配一个文件描述符，并记录在 FDT 中。
  2. 更新系统文件表：对应的 file 结构被填充，并放入系统文件表中。file 结构包含文件的打开状态和指向 i 节点的引用。
  3. 更新 i 节点：文件的 i 节点会被加载到活动 i 节点表中，增加引用计数。
  4. 文件操作：进程可以通过文件描述符进行文件的读写操作。每次文件读写时，操作系统都会更新 file 结构中的偏移量（f_offset），指示下一个读取位置。

文件描述符的继承与关闭

1、文件描述符继承

  1. 文件描述符继承：父进程在调用fork()时，子进程会继承父进程的文件描述符。这些文件描述符会指向相同的文件，在父子进程中共享文件偏移量。因此，父子进程可以同时对同一个文件进行操作。

  2. 文件描述符的关闭：父进程关闭文件描述符后，文件描述符在子进程中仍然有效，直到子进程关闭它。文件描述符的关闭不会影响子进程，除非显式调用close()。

  3. 文件描述符传递：在父进程和子进程之间传递文件描述符时，父进程需要将文件描述符传递给子进程，通常使用execlp()或类似的系统调用来传递文件描述符。

  4. 文件操作的同步：父进程和子进程共享文件描述符，因此它们会共享文件的读写位置。两个进程如果同时写入文件，可能会导致数据交错。

close-on-exec标志

在Unix/Linux操作系统中，close-on-exec标志（FD_CLOEXEC）是一个文件描述符的属性。 当进程调用exec()族函数（如execvp()、execve()等）时，所有标记了FD_CLOEXEC标志的文件描述符会被自动关闭。这是为了确保执行新程序时，旧程序打开的文件不会泄露给新程序，增强了系统的安全性。

1、设置和使用close-on-exec标志

  1. 在open()调用中使用O_CLOEXEC属性 在打开文件时，可以通过在open()系统调用中传递O_CLOEXEC标志来设置文件描述符在执行exec()时关闭。例如：

    int fd = open("file.txt", O_CREAT | O_WRONLY | O_CLOEXEC, 0666);

  2. 通过fcntl()设置和获取close-on-exec标志 使用fcntl()系统调用可以动态地获取和设置文件描述符的控制字。

    • 获取文件描述符的控制字： 使用F_GETFD命令来获取文件描述符的当前控制字（包括FD_CLOEXEC标志）。

      int flags = fcntl(fd, F_GETFD, 0);

    • 设置close-on-exec标志： 使用F_SETFD命令可以修改文件描述符的控制字，并设置或清除FD_CLOEXEC标志。

      flags |= FD_CLOEXEC;  // 设置close-on-exec标志
fcntl(fd, F_SETFD, flags);

      这段代码会将fd的控制字更新，启用FD_CLOEXEC标志，从而在后续的exec()调用时关闭该文件描述符。

    • 清除close-on-exec标志：

      flags &= ~FD_CLOEXEC;  // 清除close-on-exec标志
fcntl(fd, F_SETFD, flags);

重定向

dup2系统调用是用来复制一个文件描述符到另一个文件描述符，常用于输入输出重定向。 1、 dup2 系统调用

  • 功能：dup2(int fd1, int fd2)将fd1文件描述符复制到fd2。如果fd2已打开，它会先关闭fd2，然后将fd1复制到fd2。这种方法用于将标准输入（stdin）、标准输出（stdout）或标准错误输出（stderr）重定向到文件或其他资源。

  • 常见用途：dup2用于输入输出重定向，通常结合fork和exec系统调用来实现子进程的输入输出重定向。

管道

管道操作概述

管道是一个用于进程间通信（IPC）的重要机制。管道提供了一种无符号边界的字节流方式，通过管道，一个进程可以将数据写入管道，另一个进程可以从管道中读取数据。管道有两端：一个是读端，另一个是写端。

1、创建管道 管道通过pipe()系统调用来创建。pipe()函数的声明如下：

int pipe(int pfd[2]);
  • 参数：
    • pfd[0]：管道的读端文件描述符，用于从管道读取数据。
    • pfd[1]：管道的写端文件描述符，用于向管道写入数据。
  • 返回值：
    • 如果成功，pipe()返回0，表示管道创建成功。
    • 如果失败，返回-1，并设置errno来指示错误原因。

2、管道写操作 向管道写数据使用write()系统调用。语法如下：

ret = write(pfd[1], buf, n);
  • pfd[1]：管道的写端文件描述符。
  • buf：要写入管道的数据缓冲区。
  • n：要写入的字节数。
  • 行为：
    • 如果管道已经满了，write()将会阻塞，直到管道的读端从管道读取数据，从而腾出空间。
    • 管道的容量通常是有限的，典型的大小为8192字节，但具体大小与操作系统实现有关。

2、管道读操作 从管道读取数据使用read()系统调用。语法如下：

ret = read(pfd[0], buf, n);

  • pfd[0]：管道的读端文件描述符。

  • buf：用于存放从管道中读取数据的缓冲区。

  • n：读取的最大字节数。

  • 行为：

    • 如果管道的写端已关闭，read()返回0，表示管道已经空，且没有更多的数据可读。
    • 如果管道为空，且写端仍然没有关闭，则read()将会阻塞，直到管道有数据可供读取。
    • 如果管道不为空：
      • 如果n >= m（m是管道中实际数据的字节数），read()将读取所有的数据。
      • 如果n < m，则read()最多读取n字节。

4、关闭管道

  • 关闭写端：

    • 如果关闭了管道的写端，管道的读端的read()操作将返回0，表示管道已关闭，不再有数据可读。

  • 关闭读端：

    • 如果关闭了管道的读端，管道的写端的write()操作将在写入数据时触发SIGPIPE信号。如果未捕获SIGPIPE，进程将终止。如果捕获了SIGPIPE信号，程序可以自定义行为。
close(pfd[1]);  // 关闭写端
close(pfd[0]);  // 关闭读端

管道传输的特点：

1、无记录边界的字节流：

  • 管道是以字节流的形式传递数据，没有明确的消息边界。这意味着写入的数据可以在读取时被分割成多个小部分，或者多个写入的数据可以被一次性读取。例如，一个 write() 操作可能会导致 read() 返回多个数据块，或者多个 write() 操作的数据被合并为一个块返回。

2、双向通信时使用两个管道：

  • 若父子进程需要双向通信，可以使用两个管道，一个用于从父进程到子进程的通信，另一个用于从子进程到父进程的通信。
  • 如果只使用一个管道进行双向通信，可能会导致父进程和子进程互相读取和写入自己刚写入的数据，这种情况下数据可能被不正确地处理。

3、死锁问题： 死锁的情形通常是：

  • 父进程写数据到管道，写端被阻塞，因为管道缓冲区满。
  • 子进程也尝试向父进程发送数据，并被阻塞。

命名管道（FIFO）

1、命名管道（FIFO，First In, First Out）是管道的一种变体，它允许在不同进程之间进行通信，甚至这些进程不需要有共同的祖先。与匿名管道不同，命名管道存在于文件系统中，因此可以通过文件路径来访问。

  • **匿名管道的缺点：**仅限于同祖先进程间通信
  • **命名管道的优势：**不需要共同的祖先进程，命名管道允许任何两个进程通过一个具有指定名称的管道文件进行通信。

2、创建命名管道： 命名管道通常通过 mknod 命令或者 mkfifo() 系统调用创建。

  1. 使用 mknod 命令创建命名管道：

    mknod pipe0 p

    这条命令会在当前目录创建一个名为 pipe0 的命名管道。你可以使用 ls -l 命令查看文件类型，它会显示为 p，表示这是一个管道文件。

  2. 使用 mkfifo() 系统调用创建命名管道：

    #include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
mkfifo("pipe0", 0666);

3、发送数据到命名管道：

int fd = open("pipe0", O_WRONLY);  // 打开命名管道以写方式
write(fd, buf, len);  // 写入数据
close(fd);  // 关闭文件描述符

4、从命名管道读取数据：

int fd = open("pipe0", O_RDONLY);  // 打开命名管道以读方式
read(fd, buf, sizeof(buf));  // 读取数据
close(fd);  // 关闭文件描述符
