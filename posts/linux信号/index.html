信号的产生及类型

1、命令kill

  • 功能：用于向进程发送信号。
  • 基本用法：
    • kill -signal PID-list：发送指定信号到一个或多个进程。
    • 默认信号为 SIGTERM（15），用于正常终止进程。
    • 示例：
      • kill 1275：向进程 1275 发送 SIGTERM 信号。
      • kill -9 1326：向进程 1326 发送 SIGKILL 信号，强制终止进程。

2、进程组

  • 定义：
    • 进程组由 p_pgrp 字段标识，相同 p_pgrp 值的进程属于同一组。
    • 如果 p_pgrp 等于 p_pid，则该进程是组长。
  • 行为：
    • 创建新组：setsid() 系统调用让进程脱离原组并成为新组组长。
    • 继承：子进程通过 fork 继承父进程的 p_pgrp。
    • 示例：kill -0 0 会向与当前进程同组的所有进程发送信号。

3、信号机制

  • 功能：信号是一种“软件中断”，用于通知进程处理异常事件。
  • 信号产生：
    1. 用户态进程：
      • 通过 kill() 或 alarm() 调用发送信号。
    2. 内核触发：
      • 由中断或异常事件触发。
      • 例子：
        • SIGSEGV（段违例）：进程访问非法内存地址时触发。
        • SIGFPE（浮点溢出）：如零做除数。
        • SIGPIPE：管道读端关闭时写端触发。

4、信号类型

  • 信号在 <sys/signal.h> 文件中以宏定义，种类有限（约几十种）。
  • 关键信号及其作用：
    • SIGTERM（15）：软件终止信号（默认信号）。
    • SIGHUP（1）：挂断信号，用户退出 shell 时触发。
    • SIGINT（2）：中断信号，用户按 Ctrl-C 触发。
    • SIGQUIT（3）：退出信号，按 Ctrl-\ 触发，产生 core 文件。
    • SIGKILL（9）：强制终止信号，不可被捕获或忽略。
    • SIGALRM（14）：计时器信号，由 alarm() 触发。
    • SIGPIPE：管道写端对已关闭读端写操作。
    • 用户自定义信号：SIGUSR1、SIGUSR2。
    • 异常信号：
      • SIGSEGV：段违例。
      • SIGFPE：浮点溢出。
      • SIGILL：非法指令。
    • 其他信号：
      • SIGCLD：子进程终止。
      • SIGWINCH：终端窗口大小改变。

进程对信号的处理

1、设置为默认处理方式

  • 大部分信号的默认处理是终止进程，有些信号会生成 core 文件供调试。
  • 示例代码： 
    signal(SIGINT, SIG_DFL); // 设置 SIGINT 信号为默认处理方式

2、信号被忽略：举例

  • 进程可以选择忽略某些信号（但无法忽略 SIGKILL 和 SIGSTOP）。

  • 注意：某信号被忽略会被子进程继承。

  • 示例代码：

    signal(SIGINT, SIG_IGN); // 忽略 SIGINT 信号

  • 例子：

    • 独立运行的 bar 进程可以被 kill -15 或 Ctrl-C 终止。
    • 如果 foo 启动了 bar 且在 foo 中忽略了 SIGTERM 和 SIGINT 信号，则 bar 无法被 kill -15 或 Ctrl-C 终止。

    代码示例：

    • foo.c

      #include <signal.h>
#include <unistd.h>

int main(void) {
    signal(SIGTERM, SIG_IGN); // 忽略 SIGTERM
    signal(SIGINT, SIG_IGN); // 忽略 SIGINT
    if (fork()) {
        for (;;) sleep(100); // 父进程无限睡眠
    } else {
        execlp("./bar", "bar", NULL); // 子进程执行 bar
    }
    return 0;
}

    • bar.c

      #include <stdio.h>
#include <unistd.h>

int main(void) {
    int i = 0;
    for (;;) {
        printf("%d\n", i++);
        sleep(1); // 每秒输出计数
    }
    return 0;
}

3、信号的捕捉

  • 捕捉信号并通过自定义函数处理，用户在信号发生时执行该函数。
  • 示例代码： 
    #include <stdio.h>
#include <signal.h>
#include <unistd.h>

// 信号处理函数
void sig_handle(int sig) {
    printf("HELLO! Signal %d catched.\n", sig);
}

int main(void) {
    // 捕捉 SIGINT 和 SIGTERM 信号
    signal(SIGINT, sig_handle);
    signal(SIGTERM, sig_handle);

    for (;;) sleep(500); // 无限睡眠
}
  • 运行效果：
    • 按下 Ctrl-C 或发送 kill -15 信号时，会输出类似以下信息： 
      HELLO! Signal 2 catched.   // Ctrl-C 触发 SIGINT
HELLO! Signal 15 catched.  // kill -15 触发 SIGTERM

4、僵尸进程

  1. 定义：

    • 子进程终止后，父进程未使用 wait 或 waitpid 收集子进程的退出状态，导致子进程成为僵尸进程（defunct 或 zombie）。
    • 僵尸进程虽然不占用内存资源，但占用内核的 proc 表项（进程表项）。
    • 如果系统中存在大量僵尸进程，会导致进程表耗尽，无法创建新进程。

  2. 解决僵尸进程的方法：

    • 父进程调用 wait 或 waitpid： 父进程通过 wait 系统调用清理僵尸进程的资源。
    • 忽略 SIGCLD 信号： 
      signal(SIGCLD, SIG_IGN); // 忽略子进程终止信号
    • 捕获 SIGCLD 信号，并在信号处理函数中调用 wait： 
      void sig_cld_handler(int sig) {
    while (waitpid(-1, NULL, WNOHANG) > 0) { }
}
signal(SIGCLD, sig_cld_handler);

  3. 子进程中止后的异步通知机制：

    • 子进程终止时，系统会向父进程发送 SIGCLD 信号，父进程可以通过处理该信号避免僵尸进程。

5、发送信号kill

  • 语法： 
    int kill(int pid, int sig);
  • 参数说明：
    • pid > 0：向指定 PID 的进程发送信号。
    • pid == 0：向当前进程组的所有进程发送信号。
    • pid < 0：向以 -pid 为组长的进程组发送信号。
    • sig == 0：不发送信号，仅用于检测某个进程是否存在。
  • 返回值：
    • 成功：返回 0。
    • 失败：返回 -1，可以通过 errno 判断错误原因：
      • errno == ESRCH：指定的 PID 进程不存在。

6、系统调用与信号

  1. 进程睡眠：

    • 系统调用（如 scanf、sleep、msgrcv 等）会使进程进入睡眠状态。
    • 睡眠状态的进程收到信号会被“唤醒”，系统调用被中断，返回 -1，errno 通常为 EINTR。

  2. 特殊情况：

    • 某些系统调用在深度睡眠状态下可能无法被信号中断。
    • 即使使用 kill -9 也无法终止此类进程。

7、pause与alarm系统调用

  1. 功能：

    • alarm 设置进程的报警时钟，倒计时结束时向进程发送 SIGALRM 信号。

  2. 语法：

    int alarm(int secs);
    • secs > 0：设置时钟为指定的秒数。
    • secs == 0：取消闹钟。

  3. 行为：

    • 默认情况下，进程收到 SIGALRM 信号后会终止。
    • 父进程的闹钟设置会被子进程继承。

全局跳转：sigsetjmp 和 siglongjmp

这两个函数是用来实现全局跳转的一种机制，能够在程序的执行中实现栈的快速恢复和控制流的转移，常用于处理信号中断、错误恢复等场景。

1、函数定义

#include <setjmp.h>

int sigsetjmp(jmp_buf env, int savemask);
/* 保存当前的栈环境，返回值为 0 或 siglongjmp 提供的返回值。 */

void siglongjmp(jmp_buf env, int val);
/* 恢复到 sigsetjmp 保存的栈环境，将 sigsetjmp 返回值改为 val。 */

2、工作原理

  1. sigsetjmp：

    • 保存当前的栈环境、寄存器状态以及信号屏蔽字（取决于 savemask 参数）。
    • 返回值：
      • 第一次调用时返回 0。
      • 如果从 siglongjmp 恢复时返回 val（但始终不是 0）。

  2. siglongjmp：

    • 恢复到由 sigsetjmp 保存的栈环境，执行位置返回到调用 sigsetjmp 的地方。
    • 返回值：
      • 通过 val 指定返回值（如 val=5，则 sigsetjmp 返回值为 5）。
      • 如果 val 是 0，则 sigsetjmp 返回值将被改为 1。

3、函数参数

  1. jmp_buf env:

    • 保存的栈环境和寄存器状态。
    • 是一个结构体，用户无需关心具体内容。

  2. savemask:

    • 如果为 1，sigsetjmp 还会保存当前的信号屏蔽字。
    • 如果为 0，不保存信号屏蔽字（更高效，但可能引发信号处理不一致的问题）。

4、应用场景

  1. 信号处理：

    • 处理信号中断后快速跳转到安全的恢复点。
    • 避免多次嵌套的信号处理导致的栈耗尽问题。

  2. 错误恢复：

    • 类似于异常处理机制，捕获错误后可以跳转到某个安全状态继续执行。

  3. 长时间任务中断：

    • 在长时间运行的函数中，可以通过信号中断提前返回并重新选择操作。

5、常见问题

  1. 为什么使用 sigsetjmp 而不是 setjmp？

    • sigsetjmp 允许保存信号屏蔽字，确保信号处理的一致性，适用于信号处理中。
    • setjmp 不会保存信号屏蔽字。

  2. siglongjmp 的 val 参数为 0 时怎么办？

    • 如果 val 为 0，sigsetjmp 会将返回值自动设置为 1，避免返回值混淆。

  3. sigsetjmp 和 siglongjmp 是否能跨函数使用？

    • 可以跨函数使用，只要 jmp_buf 是全局的或能保证其生命周期在使用范围内。
