(一) Neo4j DB

1. Neo4j 特点

  • 性能优越：读写能力高效。
  • 设计灵活：无固定模式，易于根据业务需求扩展。
  • 迭代的敏捷性：适应敏捷开发方法。
  • 安全可靠：支持事务管理，提供实时在线备份和日志恢复功能。
  • 简单易用：支持多种程序设计语言（如 Spring Data Neo4j）和 REST API。
  • 类 SQL 的查询语言：提供 Cypher 语言用于图数据查询。
  • 批量导入导出：支持图数据的批量操作。
  • Web UI：提供浏览器操作的 Web 界面。
  • 原生图存储与计算引擎：采用原生图存储模式，支持高效的图计算。
  • 丰富的算法库：提供 APOC、GDS 等图数据处理与分析算法库。
  • 索引与约束：支持索引机制和 UNIQUE 约束。
  • 集群架构：易于横向扩展。
  • 适应新型场景：V5.17+ 支持图分析、GenAI 等新型应用场景，支持向量索引的创建和高效搜索。

2. Neo4j 数据模型

Neo4j 采用属性图模型描述业务关键图数据，其核心要素包括：

  • 节点（Node）：表示实体，可包含属性。
  • 关系（Relationship）：表示节点之间的连接，可包含属性。
  • 节点属性（Node Properties）：节点的键值对属性。
  • 关系属性（Relationship Properties）：关系的键值对属性。
  • 标签（Label）：表示节点的类别或类型。
  • 存储结构：
    • 节点存储（Node store）
    • 关系存储（Relationship store）
    • 属性存储（Property store）

3. 数据类型

Neo4j 支持多种数据类型，节点和关系的属性是键值对（Key-Value），其中：

  • Key：字符串类型，表示属性名称。
  • Value：支持以下数据类型：
    1. Boolean：布尔值（true/false）。
    2. Integer：64 位整型。
    3. Float：64 位浮点。
    4. String：字符串。
    5. Date：日期。
    6. Time：时间。
    7. DateTime：日期时间。
    8. LocalDateTime：本地日期时间。
    9. LocalTime：本地时间。
    10. Duration：时段。
    11. Point：地理位置坐标点。
    12. Map 类型：键值对形式。
    13. List 类型：类似数组，存储多个值的序列，支持位置索引（从 0 开始，负索引表示从尾部开始）。
    14. ByteArray：字节数组，用于小取值范围数值属性。
    15. null 类型：表示不存在属性，查询时返回 null。

4. 时间与日期处理

  • 时间与日期类型：通过函数调用获取值，例如：
    • date()：获取当前日期。
    • timestamp()：获取当前毫秒级时间戳（基于 System.currentTimeMillis()）。
    • 使用 APOC 库函数（如 apoc.date.format）进行格式转换，例如按 "yyyy-MM-dd HH:mm:ss" 格式显示。

5. 结构类型

结构类型可以作为 Cypher 查询语句的返回结果，包括：

  • 节点（Node）：
    • 包含节点 ID、标签（Labels）和 Map 类型属性列表。
  • 关系（Relationship）：
    • 包含关系 ID、类型（Type）、Map 类型属性列表、起始节点标识和终止节点标识。
  • 路径（Path）：
    • 由节点和关系的序列构成。

(二) Neo4j 节点操作

1. 创建节点

  • 创建没有属性的节点
    语法：

    CREATE (<node-v-name>:<label-name>)

    示例：

    CREATE (emp:Employee)
CREATE (dept:Dept)

    注意：如果执行两次相同的创建语句，不会报错，但会创建重复的节点。

  • 创建有属性的节点
    语法：

    CREATE (
  <node-v-name>:<label-name>
  { 
    <Property1-name>:<Property1-Value>,
    ...
    <Propertyn-name>:<Propertyn-Value>
  }
)

    示例：

    CREATE (dept:Dept { 
  deptno:10, 
  dname:"Accounting", 
  location:"Haidian" 
})

2. 创建标签

  • 创建单一标签的节点
    语法：

    CREATE (<node-v-name>:<label-name>)

    示例：

    CREATE (tnode:Paper)

  • 创建多个标签的节点
    语法：

    CREATE (<node-v-name>:<label-name1>:<label-name2>.....:<label-namen>)

    示例：

    CREATE (m:Movie:Cinema:Film:Picture)

3. 节点查找

  • 查找满足条件的节点
    语法：

    MATCH (emp:Employee) 
WHERE emp.name = 'Abc' OR emp.name = 'Xyz' 
RETURN emp

  • 查找所有节点
    语法：

    MATCH (n) RETURN n

4. 更改节点属性

  • 批量修改节点属性
    语法：

    MATCH (emp:Employee) SET emp.sal=3456 RETURN emp

  • 根据条件修改节点属性
    语法：

    MATCH (emp:Employee) 
WHERE emp.id=121 
SET emp.sal=5678 
RETURN emp

  • 根据属性匹配修改节点属性
    语法：

    MATCH (emp{id:121}) 
SET emp.sal=9000 
RETURN emp

5. 删除节点

  • 删除节点
    语法： 
    DELETE <node-name-list>
    示例： 
    MATCH (e:Employee) DELETE e
    注意：如果节点包含关系，则无法直接删除。

6. 删除节点属性

  • 删除节点属性
    语法： 
    REMOVE <property-name-list>
    示例： 
    MATCH (book{id:122}) 
REMOVE book.price 
RETURN book

7. 删除节点标签

  • 删除节点标签
    语法：

    REMOVE <label-name-list>

    示例：

    MATCH (m:Movie) 
REMOVE m:Picture

  • REMOVE 与 DELETE 的区别：

    • DELETE：用于删除节点和关系。
    • REMOVE：用于删除属性和标签。
    • 两者都需要与 MATCH 配合使用。

8. 使用循环批量创建节点

  • 批量创建节点
    语法： 
    WITH ["a","b","c"] as coll
FOREACH (value in coll | CREATE(:person{name:value}))
    示例： 
    WITH ["Alice", "Bob", "Charlie"] as names
FOREACH (name in names | CREATE(:Person{name:name}))

(三) Neo4j 关系操作

1. 创建关系

  • 创建无属性的关系
    语法：

    CREATE
(<node1-v-name>:<node1-label-name>{…})
-[<relationship-v-name>:<relationship-label-name>]
->(<node2-v-name>:<node2-label-name>{…})
RETURN <relationship-v-name>

    示例：

    CREATE (p1:Person)-[like:LIKES]->(p2:Person)

    注意：RETURN 子句是可选的，可以返回关系或其他表达式的结果。

  • 创建有属性的关系
    语法：

    CREATE (<node1-v-name>:<node1-label-name>{<define-properties-list>})
-[<relationship-v-name>:<relationship-label-name>{<define-properties-list>}]
->(<node2-v-name>:<node2-label-name>{<define-properties-list>})
RETURN <relationship-v-name>

    示例：

    CREATE (TheMatrix:Movie {title:'The Matrix', released:1999, tagline:'Welcome to the Real World'})
CREATE (Keanu:Person {name:'Keanu Reeves', born:1964})
CREATE (Keanu)-[:ACTED_IN {roles:['Neo']}]->(TheMatrix)

  • 匹配已有节点并创建关系
    语法：

    MATCH (<node1-v-name>:<node1-label-name>{…}),(<node2-v-name>:<node2-label-name>{…})
CREATE (<node1-v-name>)-[<relationship-v-name>:<relationship-label-name> {<define-properties-list>}]->(<node2-v-name>)
RETURN <relationship-v-name>

    示例：

    CREATE (e:Customer{custID:100});
CREATE (cc:CreditCard{cardID:300360});
MATCH (e:Customer{custID:100}),(cc:CreditCard{cardID:300360})
CREATE (e)-[r:DO_SHOPPING_WITH]->(cc);

2. 删除关系

  • 删除关系
    语法：

    DELETE <relationship-v-name>

    注意：需配合 MATCH 子句指定要删除的关系。
    示例：

    MATCH (cc:CreditCard)-[r]-(e:Customer)
WHERE id(r)=273 
DELETE r

  • 删除节点及关系
    示例：

    MATCH (cc:CreditCard)-[r]-(e:Customer)
DELETE r

3. 排序子句

  • 排序
    语法： 
    ORDER BY <property-name-list> [DESC]
    示例： 
    MATCH (emp:Employee) 
RETURN emp.Eid, emp.name, emp.sal, emp.deptno 
ORDER BY emp.name DESC

4. 使用 WITH 连接子句

  • WITH 子句
    语法： 
    MATCH (a:Person)-[:ACTED_IN]->(b:Movie)
WITH a, count(b) AS k
WHERE k > 0
RETURN a, k
ORDER BY k DESC

5. 路径操作

  • 最短路径查询
    语法：

    MATCH (bacon:Person {name:"Kevin Bacon"})-[*1..4]-(hollywood)
RETURN DISTINCT hollywood

  • 最短路径函数
    使用 shortestPath 函数查询最短路径。

6. 索引操作

  • 创建索引
    语法：

    CREATE INDEX index_name FOR ()-[r:REL_TYPE]-() ON (r.property)

    示例：

    CREATE INDEX rel_range_index_name FOR ()-[r:KNOWS]-() ON (r.since)

  • 删除索引
    语法：

    DROP INDEX index_name [IF EXISTS]

7. 约束操作

  • 创建唯一约束
    语法：

    CREATE CONSTRAINT constraint_name
REQUIRE <property_name> IS UNIQUE

  • 删除唯一约束
    语法：

    DROP CONSTRAINT constraint_name [IF EXISTS]

8. 存储过程调用

  • 调用存储过程
    示例：

    CALL db.labels()  // 显示当前所有标签
CALL db.relationshipTypes()  // 显示当前所有关系类型
SHOW PROCEDURES  // 返回可用存储过程列表及说明

(四）Neo4j 集群技术与管理

1. Neo4j 集群技术

Neo4j 提供两种主要的集群方式，以满足高性能、高可用性和扩展性需求：

（1）高可用性集群（High Availability, HA）
  • 特点：
    • 主从架构，支持 1 主多从。
    • 主服务器负责写入，数据同步到从服务器。
    • 从服务器可以处理读请求，写请求需转发到主服务器。
    • 数据一致性通过主节点同步实现，从节点的写入在其他从节点上不是立即可见。
  • 适用场景：
    • 适用于低版本 Neo4j，现代版本已较少使用。
（2）因果集群（Causal Clustering）
  • 特点：
    • 采用先进的 Raft 协议。
    • 节点分为两类：
      • 核心服务器（Core Server/PRIMARY）：负责读写操作，大多数核心服务器处理写操作。
      • 读复制服务器（Read Replicas/SECONDARIES）：负责分担读数据任务，数据从核心服务器异步更新。
    • 容错能力：通过公式 M = 2F + 1 计算核心服务器数量，其中 F 为可容忍的故障服务器数量。
      • 例如，容忍 1 台故障需 3 台核心服务器，容忍 2 台故障需 5 台核心服务器。
    • 因果一致性：保证客户端至少能读取自己的写入。
    • 扩展性：读复制服务器支持大规模横向扩展，高效分担查询负载。

2. Neo4j 管理与监控

Neo4j 提供了丰富的管理与监控功能，包括数据导入、备份恢复、事务管理和日志监控等。

（1）图数据导入
  • 方法：
    1. LOAD CSV 命令：导入 CSV 格式数据。 
      LOAD CSV WITH HEADERS FROM "http://data.neo4j.com/northwind/products.csv" AS row
    2. neo4j-admin database import：通过命令行工具导入数据。
    3. 第三方 ETL 工具：如 Apache NiFi、Talend 等。
（2）图数据备份与恢复（离线）
  • 备份：
    • 支持完全备份和增量备份
    • 使用 neo4j-admin 命令： 
      neo4j-admin database dump --to-path=/backup/path neo4j
  • 恢复：
    • 使用 neo4j-admin 命令： 
      neo4j-admin database load --from-path=/backup/path --overwrite-destination=true neo4j
（3）事务管理
  • 显式事务管理：
    1. 开始事务。
    2. 执行写操作。
    3. 标记事务成功或失败。
    4. 提交或回滚事务。
  • 隐式事务管理：
    • 单条 Cypher 语句自动提交（Auto-commit）。
  • 隔离级别：
    • 默认 READ_COMMITTED。
    • 支持手动获取读锁、写锁以实现更高隔离级别（如 REPEATABLE_READ、SERIALIZABLE）。
（4）监控与日志
  • 日志类型：
    • neo4j.log：基础日志。
    • debug.log：调试日志。
    • query.log：记录超时查询（企业版）。
    • security.log：安全事件日志（企业版）。
    • http.log：HTTP API 请求日志。
    • gc.log：JVM 垃圾回收日志。
  • 日志路径配置：
    • 一般日志路径：server.directories.logs=logs。
    • 事务日志路径：server.directories.transaction.logs.root=data/transactions。
