Socket概述

1、网络协议栈分层实现

  1. 传输层以上（应用层）

    • 由用户态应用程序实现。
    • 提供网络服务接口，如 HTTP、FTP 等。

  2. 传输层和网络互联层

    • 传输层：TCP/UDP 在内核中实现。
    • 网络互联层：如 IP 协议的路由功能也在内核中实现。
    • 路由协议：如 OSPF、BGP，通常由用户态进程实现。

  3. 第一层和第二层（物理层和数据链路层）

    • 一般由硬件实现，如网卡、交换机等。

2、UNIX 提供的网络功能接口

  1. 文件方式组织设备与通信

    • BSD 将设备和通信管道都组织为文件，创建方式不同，但访问方式一致。
    • 主要包括：
      • 终端设备：用于用户与计算机交互。
      • 管道：实现进程间通信。
      • 通信服务 Socket：为网络通信设计。

  2. AT&T UNIX 的 TLI（Transport Layer Interface）编程接口

    • 提供面向网络通信的接口。
    • 不仅支持 TCP/IP，也支持其他协议。

  3. 虚拟 Loopback 接口

    • 使用回环地址 127.0.0.1。
    • 实现同一台计算机上不同进程之间的通信。

3、TCP 与 UDP 的区别

  1. TCP（Transmission Control Protocol）

    • 特点：
      • 面向连接。
      • 可靠传输（通过确认机制、重传机制、流量控制实现）。
      • 字节流传输（不保证报文边界）。
    • 适用场景：文件传输、邮件服务、远程登录等。

  2. UDP（User Datagram Protocol）

    • 特点：
      • 面向数据报。
      • 不可靠传输（可能错报、丢报、乱序，无流量控制）。
      • 支持广播和组播。
      • 数据报传输（保留报文边界）。
    • 适用场景：视频流、实时通信、广播消息等。

4、字节顺序

  1. CPU 字节顺序

    • Big Endian（大端序）：高字节存储在低地址。
      • 适用 CPU：PowerPC、SPARC、Motorola。
    • Little Endian（小端序）：低字节存储在低地址。
      • 适用 CPU：Intel X86。

  2. 网络字节顺序

    • 采用 Big Endian，与 X86 的 Little Endian 相反。
    • 需要在传输数据时进行字节序转换。

  3. 字节序转换函数

    • htonl（Host to Network Long）：主机字节序转网络字节序（4 字节整数）。
    • ntohl（Network to Host Long）：网络字节序转主机字节序（4 字节整数）。
    • htons（Host to Network Short）：主机字节序转网络字节序（2 字节整数）。
    • ntohs（Network to Host Short）：网络字节序转主机字节序（2 字节整数）。

TCP客户-服务器程序

1、Socket 基础概念

  1. Socket 定义：

    • Socket 是网络通信的端点，用于实现进程间数据传输。
    • 端点名 = IP 地址 + 端口号。

  2. Socket 系统调用：

    • socket：创建 Socket 文件描述符。
    • bind：为 Socket 指定本地端点名（IP 地址和端口号）。
    • listen：通知内核开始监听连接请求。
    • accept：接受连接请求，完成 TCP 三次握手，返回新的文件描述符。
    • connect：客户端调用，向服务端发起连接请求，设置远程端点名。
    • close：关闭 Socket，释放文件描述符。

2、客户端程序分析：client.c

  1. 代码关键步骤：

    • 创建 Socket 文件描述符：

      sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
      • 参数说明：
        • AF_INET：IPv4 协议。
        • SOCK_STREAM：面向连接的 TCP 通信。
        • IPPROTO_TCP：指定使用 TCP 协议。

    • 设置远端端点名：

      name.sin_family = AF_INET;
inet_aton(argv[1], &name.sin_addr);
name.sin_port = htons(PORT_NO);
      • inet_aton 将字符串形式的 IP 地址转换为二进制形式。
      • htons 将端口号转换为网络字节序。

    • 发起连接：

      connect(sock, (struct sockaddr *)&name, sizeof(name));
      • 向服务端发起连接请求，进行 TCP 三次握手。

    • 发送数据：

      write(sock, sbuf, strlen(sbuf));
      • 从标准输入读取数据并发送到服务端。

    • 关闭连接：

      close(sock);

3、服务端程序分析：server0.c

  1. 代码关键步骤：

    • 创建 Socket 文件描述符：

      admin_sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);

    • 绑定本地端点名：

      name.sin_family = AF_INET;
name.sin_addr.s_addr = INADDR_ANY;
name.sin_port = htons(PORT_NO);
bind(admin_sock, (struct sockaddr*)&name, sizeof(name));
      • INADDR_ANY 表示绑定到所有可用的本地 IP。

    • 监听连接请求：

      listen(admin_sock, 5);
      • 参数 5 表示允许的最大连接等待队列长度（未被 accept() 的连接）。

    • 接受连接请求：

      data_sock = accept(admin_sock, 0, 0);
      • 阻塞等待客户端连接，完成 TCP 三次握手。

    • 接收数据：

      nbyte = read(data_sock, buf, SIZE);
      • 从客户端读取数据并输出。

    • 关闭连接：

      close(data_sock);

多进程并发处理

1、主函数

    int admin_sock, data_sock, pid, name_len;
    struct sockaddr_in name, peer;
  • admin_sock: 服务器监听套接字，用于接受客户端的连接。
  • data_sock: 数据套接字，用于与客户端通信。
  • pid: 存储 fork() 的返回值，用于区分父进程和子进程。
  • name 和 peer: 分别表示服务器自身的地址信息和客户端的地址信息。

2、创建套接字

admin_sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
if (admin_sock < 0)
    exit(-1);
  • 使用 socket() 创建一个 TCP 流式套接字：
    • AF_INET: 使用 IPv4。
    • SOCK_STREAM: 表示面向连接的服务（TCP）。
    • IPPROTO_TCP: 明确指定使用 TCP 协议。

3、绑定地址

name.sin_family = AF_INET;
name.sin_addr.s_addr = INADDR_ANY;
name.sin_port = htons(PORT_NO);
if (bind(admin_sock, (struct sockaddr*)&name, sizeof(name)) < 0)
    exit(-1);
  • 设置 sockaddr_in 结构体 name：
    • sin_family: 地址族，IPv4。
    • sin_addr.s_addr: 绑定到所有可用网络接口（INADDR_ANY）。
    • sin_port: 绑定到端口号 12355，使用 htons() 将主机字节序转换为网络字节序。
  • 调用 bind() 将套接字与地址绑定。如果失败，程序退出。

4、启动监听

listen(admin_sock, 5);

5、忽略子进程状态

signal(SIGCLD, SIG_IGN); /* 必须执行此操作，否则进程僵尸问题 */
  • 如果父进程忽略 SIGCHLD 信号（通过 signal(SIGCLD, SIG_IGN)），操作系统会自动清理子进程的资源，不需要父进程显式调用 wait()。

6、主循环

for (;;) 
    name_len = sizeof(peer);
    data_sock = accept(admin_sock, (struct sockaddr *)&peer, &name_len);
    if (data_sock < 0) continue;
    printf("Accept connection from %s:%d\n",
           inet_ntoa(peer.sin_addr), ntohs(peer.sin_port));
  • for (;;): 服务器主循环，不断接受客户端连接。
  • accept():
    • 从监听套接字中取出一个连接，生成数据套接字 data_sock。
    • peer 保存了客户端的地址信息。
  • 打印客户端的 IP 地址和端口号：
    • inet_ntoa(): 将网络字节序 IP 地址转换为点分十进制字符串。
    • ntohs(): 将网络字节序端口号转换为主机字节序。

7、分叉子进程

pid = fork();
if (pid > 0) { /* parrent process */
    close(data_sock); /* 必须执行此操作，原因有2 */
} else if (pid == 0) { /* child process */
    char fd_str[16];
    close(admin_sock);
    sprintf(fd_str, "%d", data_sock);
    execlp("./server1a", "./server1a", fd_str, NULL);
    perror("execlp");
    exit(1);
}
  • 父进程:
    • fork() 返回值大于 0 时，表示当前为父进程。
    • 关闭 data_sock，避免同时有多个进程持有该套接字。
  • 子进程:
    • fork() 返回值为 0 时，表示当前为子进程。
    • 关闭监听套接字 admin_sock，因为子进程只负责处理当前连接。
    • 使用 execlp() 启动 server1a 程序，将 data_sock 的文件描述符传递过去。

服务器会为每个客户端连接创建一个独立的子进程：

  • 父进程： 一直运行在主循环中，调用 accept()，等待新的客户端连接。 每次连接后，创建一个子进程，并继续监听。
  • 子进程： 运行 execlp()，执行 server1a 程序，处理当前连接。 处理完毕后，子进程退出，释放资源

8、端点名相关的系统调用

  • getpeername：获取对端的端点名（即对方的地址和端口）。

    int getpeername(int sockfd, struct sockaddr *name, int *namelen);
    • sockfd：套接字文件描述符。
    • name：结构体，用于存储对端地址信息。
    • namelen：传入传出型参数，函数调用前表示缓冲区大小，返回时表示实际写入的字节数。

  • getsockname：获取本地的端点名（即本地的地址和端口）。

    int getsockname(int sockfd, struct sockaddr *name, int *namelen);

9、read/write 系统调用的语义

  • write：数据从应用层传递到发送缓冲区，最终通过 TCP 协议发送给对端。

  • read：接收对端发送的数据到达接收缓冲区，应用层读取数据。

  • TCP 流控制与故障处理

  • 流控问题：流控用于防止发送方发送数据过快，接收方无法处理。TCP 通过滑动窗口协议进行流控。

  • 断线、重启、Keepalive：TCP 提供自动的重连机制，如设置 SO_KEEPALIVE 来检测连接是否活跃。

  • 粘连问题：TCP 在发送多个小的数据块时，可能将它们粘在一起发送，因此需要在应用层处理消息的边界。

  • UDP 通信

  • recvfrom/sendto：可以指定对方的端点名，适用于无连接的 UDP。

    int recvfrom(int sockfd, void *buf, int nbyte, int flags, struct sockaddr *from, int *fromlen);
int sendto(int sockfd, void *buf, int nbyte, int flags, struct sockaddr *to, int tolen);

  • UDP 特性：

    • 无连接，数据报不保证顺序。
    • 没有流控功能，不可靠传输。
    • 不支持粘连问题（每个报文独立）。

10、shutdown 系统调用

  • shutdown：用于关闭套接字的发送和/或接收功能。

    int shutdown(int sockfd, int howto);
    • howto 取值：
      • SHUT_RD：不能接收数据。
      • SHUT_WR：不能发送数据。
      • SHUT_RDWR：禁止所有收发操作。

  • TCP 协议：可以半关闭连接，允许发送方向关闭，但接收方向仍然可以接收数据。

  • UDP 协议：关闭接收方向，内核仅记录标记，不再提供数据，但无法阻止对方发送。

11、Socket 控制与配置

  • getsockopt 和 setsockopt：

    • 用于获取和设置套接字的选项，如 TCP 保活、重传次数、重传时间等。
    int getsockopt(int sockfd, int level, int optname, void *optval, int *optlen);
int setsockopt(int sockfd, int level, int optname, void *optval, int optlen);

  • ioctl：用于获取和设置特定套接字的控制信息。

    int ioctl(int fd, int cmd, void *arg);

12、无阻塞 I/O

  • fcntl：可以改变文件描述符的属性，如设置为非阻塞模式。 
    int flags = fcntl(fd, F_GETFL, 0);
fcntl(fd, F_SETFL, flags | O_NDELAY);
  • 无阻塞模式：
    • 当发送缓冲区满时，write() 会立即返回 -1，并将 errno 设置为 EWOULDBLOCK 或 EAGAIN。
    • 当接收缓冲区空时，read() 会立即返回 -1，并将 errno 设置为 EWOULDBLOCK。

单进程并发处理

1、select 多路 I/O select 系统调用使得用户进程能够同时等待多个文件描述符的事件发生。通过 select，用户可以告知内核在多个文件描述符上进行事件检测，如读、写或异常事件，进程会在相应的事件发生时返回。否则，进程会在内核中等待，直到某个文件描述符的事件就绪或超时。

select 系统调用

int select(int maxfdp1, fd_set *rfds, fd_set *wfds, fd_set *efds, struct timeval *timeout);
  • maxfdp1：最大文件描述符的值加1。
  • rfds：待检查的文件描述符集合（是否可以读取）。
  • wfds：待检查的文件描述符集合（是否可以写入）。
  • efds：待检查的文件描述符集合（是否有异常情况）。
  • timeout：指定最多等待的时间。如果为 NULL，表示无限期等待；如果为 0，表示不等待，立即返回；如果有具体时间值，表示最多等待的时间。

2、集合操作 select 使用集合类型 fd_set 来表示文件描述符集合。操作集合时，提供了以下函数：

  • FD_ZERO(fd_set *fds)：清空集合 fds。
  • FD_SET(int fd, fd_set *fds)：将文件描述符 fd 添加到集合 fds。
  • FD_CLR(int fd, fd_set *fds)：从集合 fds 中删除文件描述符 fd。
  • FD_ISSET(int fd, fd_set *fds)：检查文件描述符 fd 是否在集合 fds 中。

3、“准备好”定义

  • “读准备好”：表示文件描述符在 rfds 集合中，且该文件描述符的 read 操作不会阻塞。
  • “写准备好”：表示文件描述符在 wfds 集合中，且该文件描述符的 write 操作不会阻塞。
  • “异常情况”：表示文件描述符在 efds 集合中，发生了异常情况，如加急数据到达。TCP 协议中的异常通常指有加急数据，而对方连接关闭或网络故障不算异常。

UDP通信

1、UDP协议

  • 无连接性：UDP 是一种面向报文的协议，不像 TCP 那样建立连接。数据直接通过数据包发送，不保证可靠性、顺序性或重复数据处理。
  • 发送和接收：UDP 的 sendto 和 recvfrom 函数允许在不需要连接的情况下直接指定远端的 IP 和端口。

2、套接字（Socket）编程

  • 套接字创建：使用 socket() 函数创建套接字。AF_INET 表示使用 IPv4 协议，SOCK_DGRAM 表示使用数据报（即 UDP）协议，IPPROTO_UDP 是指定使用 UDP 协议。
  • 绑定（Bind）：使用 bind() 函数将套接字与特定的 IP 地址和端口号绑定。在接收端，bind() 允许指定本地端口来监听来自其他客户端的消息。
  • 连接（Connect）：connect() 函数将套接字与远端地址建立关联。虽然 UDP 是无连接的协议，但通过 connect() 调用，系统会记录远端地址，这样在发送数据时可以省略每次指定远端地址（客户端可以通过 write() 发送数据，而不需要每次使用 sendto() 指定远端地址）。但是，connect() 并不会产生实际的网络流量。

3、数据发送和接收

  • write() 和 sendto()：
    • write() 是基于已连接的套接字进行数据发送。与 sendto() 不同，write() 可以简化代码，因为已经通过 connect() 调用指定了远端地址，但 UDP 协议本身并不要求必须使用 connect()。
    • sendto() 是用于指定目标地址和端口进行数据发送的函数。它适用于 UDP，因为 UDP 是无连接的协议。
  • read() 和 recvfrom()：
    • read() 用于从已连接的套接字中读取数据。对于 UDP，通常使用 recvfrom()，因为它能够返回数据来源的地址信息。
    • recvfrom() 用于从套接字中读取数据，并且可以通过参数返回远端的 IP 和端口信息。通常用于服务端接收来自不同客户端的数据。

4、select() 和 定时器

  • select()：select() 是一种多路复用技术，允许一个进程等待多个 I/O 操作完成。它常用于非阻塞 I/O 操作。通过 select()，可以同时等待多个事件，如读取数据、写入数据或定时器超时。
  • 定时器：通过 select() 可以实现定时器功能，使得进程在等待数据的同时，可以在超时后执行某些操作。
