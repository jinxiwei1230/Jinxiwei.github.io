1 键值数据库概述

1. 键值数据库技术特点

核心优势
  • 高性能：
    • 哈希算法关联Key-Value，时间复杂度O(1)的查询效率。
  • 操作简单：
    • 提供丰富API，支持增删改查、范围查询、集合运算（并集/交集/差集）。
  • 多数据结构支持：
    • 字符串、双向链表、Hash表、集合、有序集合等。
    • 值可为二进制、文本、JSON等格式。
高级特性
  • Key过期管理：支持TTL（Time to Live）。
  • 持久化：内存数据可持久化到磁盘，防止数据丢失。
  • 事务：
    • 单命令原子性执行，支持批量操作的事务管理。
  • 扩展性：
    • 分片技术实现水平扩展。
  • 高可用：
    • 主从复制、读写分离、哨兵机制保障容错性。
  • 多语言API：支持多种编程语言接口。

2. Redis高可用架构

  • 机制：
    • 主从集群、读写分离、哨兵监控、增量复制。
  • 节点角色：
    • 主节点（Master）与从节点（Replica）。
  • 应用场景：
    • 通过副本节点提升读性能，主从切换保障故障恢复。

3. 对比：Amazon DynamoDB

  • 核心能力：
    • 完全托管，毫秒级延迟（<10ms）。
    • 内置安全、备份、恢复机制。
  • 数据模型：
    • 项目：主键/复合键 + 不限数量的属性（总大小≤400KB）。
    • 表：无限制的数据项集合（类似关系型数据库的表）。

序列化方法：个体学习器之间有强依赖关系，必须串行生成

Boosting算法族：Adaboost、GBDT、Xgboot

  • 工作机制：对基学习器的表现对训练样本分布进行调整，使错误的样本得到更多的关注，然后基于调整后的样本分布训练下一个基学习器，重复，最后对所有基学习器加权结合
  • **建模过程：**初始权重相同，迭代的、线性的，难分类的样本获得更高的权重，权重越高，被采样的几率越大

Adaboost 自适应增强

  • 将弱学习算法提升为强学习算法的过程

1、加法模型

最终强分类器是若干个弱分类器加权平均得到的

2、前向分布算法

  • 训练过程中，下一轮迭代产生的分类器是在上一轮分类器的基础上训练得到的

  • 通过一轮轮的弱学习器学习，利用前一个弱学习器的结果和当前弱学习器的结果来更新当前的强学习器模型

    第 $k - 1$ 轮的强学习器为：

    $$ f_{k-1}(x) = \sum_{i=1}^{k-1} \alpha_i G_i(x) $$

    而第 $k$ 轮的强学习器为：

    $$ f_k(x) = \sum_{i=1}^{k} \alpha_i G_i(x) $$

    上两式一比较可以得到：

    $$ f_k(x) = f_{k-1}(x) + \alpha_k G_k(x) $$

  • 强学习器是通过前向分步算法一步步得到的，后一个模型的训练永远是在前一个模型的基础上完成！

  • 初始化训练样本的权值分布，每个样本具有相同权重；

  • 训练弱分类器，如果样本分类正确，则在构造下一个训练集中，它的权值就会被降低；反之提高。用更新过的样本集去训练下一个分类器；

  • 将所有弱分类组合成强分类器，各个弱分类器的训练过程结束后，加大分类误差率小的弱分类器的权重，降低分类误差率大的弱分类器的权重。

优点

  • Adaboost作为分类器，精度很高
  • 可以使用各种回归分类模型来构建弱学习器，很灵活
  • 不容易发生过拟合

缺点

  • 对异常值敏感，异常值会获得较高的权重，影响最终的强学习器的正确性
  • 训练时间长，每次一个分类器都要用到全部样本，弱分类器还好，强分类器学习时间较长

并行化方法：个体学习器之间不存在强依赖关系，可同时并行生成

(一) 文档数据库概述

1. 文档数据库核心特点

  1. 灵活的数据模型：
    • 文档是基本存储单位，采用JSON/BSON格式
    • 支持嵌套结构和树形数据存储
    • 文档结构可自描述，无需严格模式定义
  2. 强大的功能支持：
    • 支持多种索引类型（单字段、复合、全文、地理空间等）
    • 提供丰富的查询语言和聚合框架
    • 支持ACID事务管理机制
  3. 扩展性与高可用：
    • 分布式集群架构（分片+复制集）
    • 易于水平扩展，支持高并发访问
    • 自动故障转移，保障数据高可用性
  4. 完善的生态系统：
    • 支持多种编程语言驱动
    • 提供管理监控工具（如MongoDB Atlas、Compass）
    • 具备完善的安全机制（认证、加密、审计）

2. 文档数据模型优势

  • 自包含性：文档同时包含数据及其结构信息
  • 灵活性：同一集合中的文档可具有不同结构
  • 高效性：相关数据存储在单一文档中，减少join操作

3. XML与JSON比较

特性 XML JSON
格式 标记语言，语法严格 轻量级键值对结构
扩展性 通过DTD/XSD定义模式 无严格模式定义
可读性 相对冗长 简洁易读
处理效率 解析复杂 解析高效
数据类型支持 有限 基本类型+嵌套
典型应用场景 企业级数据交换、文档标记 Web API、NoSQL数据库存储

4. JSON与BSON深入对比

JSON特点：

  • 人类可读的文本格式
  • 基本结构：对象（无序键值对）和数组（有序值列表）
  • 支持数据类型：字符串、数字、布尔值、null、对象、数组

BSON增强特性：

  1. 二进制编码：
    • 存储空间更紧凑
    • 包含长度前缀，支持快速跳转
    • 例：{"hello": "world"} → \x16\x00\x00\x00\x02hello\x00\x06\x00\x00\x00world\x00\x00
  2. 扩展数据类型：
    • 日期（Date）
    • 二进制数据（BinData）
    • 对象ID（ObjectId）
    • 正则表达式
    • JavaScript代码
    • 时间戳（Timestamp）
    • 小数128（Decimal128）
  3. 每种类型都有一个数字代号和一个英文别称
    • $type 运算可以返回field的类型
    • $isNumber运算可以返回是否是数值类型
  4. 查询优势：
    • 支持类型操作符：$type, $isNumber 示例查询：db.collection.find({"field": {$type: "date"}})

（一）相关知识回顾

1. 关于CREATE子句的问题

  1. 一个语句可以有多个CREATE子句吗？

    • 是的，一个Cypher语句可以包含多个CREATE子句，用逗号分隔。

  2. 不同CREATE子句节点变量名称能相同吗？

    • 不能，在同一查询中，变量名必须是唯一的。如果重复使用相同变量名，后面的会覆盖前面的。

2. Cypher语句分析

2.1 创建和修改节点

CREATE (n:人物{name:'关羽'}) RETURN n;
  • 创建一个带有"人物"标签的节点，设置name属性为"关羽"，并返回该节点
MATCH (n:人物{name:'关羽'}) SET n:五虎上将:蜀;
  • 查找name为"关羽"的人物节点，并添加"五虎上将"和"蜀"两个标签
MATCH (n:人物{name:'关羽'}) SET n.gender ='男';
  • 查找name为"关羽"的人物节点，设置gender属性为"男"
MATCH (n:人物{name:'关羽'}) 
RETURN labels(n) AS nodeLabel, keys(n) AS nodeProperties, n.name;
  • 查找name为"关羽"的人物节点，返回:
    • 节点的所有标签
    • 节点的所有属性键
    • 节点的name属性值

2.2 删除标签

MATCH (n:人物{name:'关羽'}) REMOVE n:蜀;
  • 查找name为"关羽"的人物节点，删除"蜀"标签

2.3 创建关系

MATCH (n:人物{name:'关羽'}) 
CREATE (n)-[r:义弟{地点:'桃园'}]->(n1:人物{name:'刘备'})
RETURN n,n1;
  • 查找name为"关羽"的人物节点
  • 创建一个新节点n1(刘备)和从n到n1的关系，关系类型为"义弟"，关系属性"地点"为"桃园"
  • 返回关羽和刘备两个节点

2.4 查询关系和节点信息

MATCH (n:人物{name:'关羽'}) -[r]- (n1) 
RETURN type(r) AS relationshipType,
keys(r) AS relationshipProperties,
labels(n1) AS nodeLabel, 
keys(n1) AS nodeProperties, 
n1.name;
  • 查找name为"关羽"的人物节点及其所有关系和相连节点
  • 返回:
    • 关系类型
    • 关系的所有属性键
    • 相连节点的所有标签
    • 相连节点的所有属性键
    • 相连节点的name属性值

2.5 删除节点及其关系

问题1：以下语句是否能删除两个节点及其关联关系？

match (a{name:"张三"})--(b{name:"李四"}) 
where id(a)=1241 and id(b)=1242
delete a,b;

答案：不能。这个语句会报错，因为节点上存在关系时不能直接删除节点。必须先删除关系或使用DETACH DELETE。

模型评估指标

Jinxiwei published on 2025-03-25 included in BA/DS

1. 混淆矩阵（Confusion Matrix）

混淆矩阵是分类任务的基础，用于计算以下核心值：

预测为正例 (1) 预测为负例 (0)
实际为正例 (1) True Positive (TP) False Negative (FN)
实际为负例 (0) False Positive (FP) True Negative (TN)
  • TP（True Positive）：模型正确预测为正例的样本数（真实为机器人，预测为机器人）。
  • TN（True Negative）：模型正确预测为负例的样本数（真实为人类，预测为人类）。
  • FP（False Positive）：模型错误预测为正例的样本数（真实为人类，预测为机器人）。
  • FN（False Negative）：模型错误预测为负例的样本数（真实为机器人，预测为人类）。

2. 常用评估指标

(1) 基于混淆矩阵的指标

指标 公式 解释
准确率 (Accuracy) ( \frac{TP + TN}{TP + TN + FP + FN} ) 所有预测正确的比例，对不平衡数据不敏感。
精确率 (Precision) ( \frac{TP}{TP + FP} ) 预测为正例的样本中实际为正例的比例（避免误杀人类用户）。
召回率 (Recall) ( \frac{TP}{TP + FN} ) 实际为正例的样本中预测为正例的比例（避免漏检机器人）。
F1-Score ( 2 \times \frac{Precision \times Recall}{Precision + Recall} ) 精确率和召回率的调和平均，平衡两者关系。
特异度 (Specificity) ( \frac{TN}{TN + FP} ) 实际为负例的样本中预测为负例的比例（人类用户不被误判的能力）。

(2) 类似AUC的阈值无关指标

指标 解释
AUC-ROC ROC曲线下面积，反映模型在不同阈值下区分正负例的能力（范围0.5~1）。
AUC-PR 精确率-召回率曲线下面积，适用于高度不平衡数据（正例极少时更敏感）。
KS统计量 正负例累积分布的最大差异，值越大模型区分能力越强（范围0~1）。

(3) 其他重要指标

指标 公式/解释
G-Mean ( \sqrt{Recall \times Specificity} )，平衡正负例的检测能力。
MCC (Matthews Correlation Coefficient) ( \frac{TP \times TN - FP \times FN}{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}} )，范围-1~1，综合衡量分类质量。
Log Loss 基于概率的损失函数，值越小模型校准越好（对概率预测敏感）。

3. 不同场景下的指标选择

(1) 平衡数据

  • 优先指标：Accuracy、F1-Score、AUC-ROC。
  • 示例：正负样本比例接近1:1时，Accuracy可直接反映模型性能。

(2) 不平衡数据（如机器人检测）

  • 优先指标：AUC-ROC、AUC-PR、Recall、F1-Score。
  • 原因：避免模型偏向多数类（人类用户），需关注少数类（机器人）的检测能力。
    • 高Recall：确保尽可能捕获更多机器人（减少FN）。
    • 高Precision：减少人类用户被误判为机器人（减少FP）。

(3) 概率预测任务

  • 优先指标：Log Loss、AUC-ROC、Brier Score。
  • 示例：预测用户是机器人的概率时，需评估概率的校准性。

4. 可视化工具辅助分析

  • ROC曲线：横轴为FPR（( \frac{FP}{FP + TN} )），纵轴为TPR（Recall），曲线越靠近左上角性能越好。
  • PR曲线：横轴为Recall，纵轴为Precision，正例极少时曲线下面积（AUC-PR）比AUC-ROC更敏感。

5. 总结

  • 核心四元组：TP、TN、FP、FN 是计算所有指标的基础。
  • AUC类似指标：AUC-ROC、AUC-PR、KS统计量等，关注模型整体排序能力。
  • 业务导向：
    • 若容忍少量误杀（FP），优先优化Recall；
    • 若需高精度（如法律场景），优先优化Precision。

通过组合这些指标，可以全面评估模型在不同方面的性能，避免单一指标的局限性。
