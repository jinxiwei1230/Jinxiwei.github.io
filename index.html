Urllib基本使用(urlencode\urlretrieve\urlopen\quote)

1urllib.request 发送 HTTP 请求并获取响应

1. 基本用法

1.1 发送请求并获取响应
import urllib.request

# 定义URL
url = 'http://www.baidu.com'

# 发送请求并获取响应对象
response = urllib.request.urlopen(url)
  • urlopen(url)：打开指定的 URL 并返回一个 HTTPResponse 对象。
1.2 获取响应内容
# 读取响应内容并解码为字符串
content = response.read().decode('utf-8')
print(content)
  • read()：读取整个响应内容，返回字节形式的二进制数据。
  • decode('utf-8')：将二进制数据解码为字符串，utf-8 是常见的编码格式。
1.3 读取部分内容
# 读取前10个字节
content = response.read(10)
print(content)
  • read(n)：读取响应内容的前 n 个字节。
1.4 逐行读取
# 读取一行
content1 = response.readline()
print(content1)

# 逐行读取所有内容
content2 = response.readlines()
print(content2)
  • readline()：读取一行内容。
  • readlines()：读取所有行并返回一个列表。

2. 响应对象 (HTTPResponse) 的方法和属性

2.1 获取状态码
print("状态码：", response.getcode())
  • getcode()：返回 HTTP 响应的状态码（如 200 表示成功）。
2.2 获取请求的 URL
print("URL: ", response.geturl())
  • geturl()：返回实际请求的 URL（可能会与原始 URL 不同，例如发生重定向时）。
2.3 获取响应头信息
print("头信息：", response.getheaders())
  • getheaders()：返回一个包含所有响应头信息的列表，每个元素是一个 (header, value) 元组。

3. 总结

  • 一个类型：HTTPResponse，表示 HTTP 响应对象。
  • 六个方法：
    1. read()：读取响应内容。
    2. read(n)：读取前 n 个字节。
    3. readline()：读取一行内容。
    4. readlines()：读取所有行。
    5. getcode()：获取状态码。
    6. geturl()：获取请求的 URL。
    7. getheaders()：获取响应头信息。

异常种类

urllib.error.URLError

常见场景：

  • 连接超时（如请求的目标服务器无法访问，网络中断）。
  • DNS 解析错误（例如，URL 域名无法解析到 IP 地址）。
  • 网络连接错误（例如，网络不可达）

urllib.error.HTTPError

HTTPError 是 urllib 模块中的一个子类异常，专门用于处理 HTTP 错误状态码（如 404、500 等）。 常见场景：

  • 请求的资源不存在，返回 404 错误。
  • 请求无法通过认证，返回 401 或 403 错误。
  • 服务器错误，返回 500 错误。

cookie、Referer

1、登录状态（Cookie）：

  • Cookie 是模拟登录状态时至关重要的一部分。爬虫通过获取登录后浏览器中的 Cookie，将其放在请求头中，以模拟已登录的状态。
  • cookie 包含一系列从微博登录后获得的身份信息，如 SCF、SINAGLOBAL、PC_TOKEN 等。 注意：使用 Cookie 时需要确保它是有效的，并且不要泄露敏感信息。

2、防止反爬虫措施：

  • Referer：一些网站通过检查 referer 来判断请求是否来自正常的浏览路径，防止直接访问资源。爬虫在请求头中加入合适的 referer 值可以绕过这种检查。
  • User-Agent：服务器根据请求头中的 User-Agent 判断请求是否来自浏览器。如果 User-Agent 显示是爬虫，服务器可能会阻止请求。为了绕过此问题，可以设置与常见浏览器相符的 User-Agent。

3、爬虫中的常见技巧：

  • 模拟浏览器请求：通过自定义请求头信息，特别是 User-Agent、Referer 和 Cookie，使爬虫看起来像一个正常用户在浏览网页。
  • 处理登录后的数据：当需要登录后获取数据时，确保爬虫能够通过获取到的 Cookie 维持登录状态。
  • 防止被封禁：通过设置适当的请求头信息和延时控制，避免被目标网站封禁 IP。

爬虫 handler

1. 什么是 Handler？

  • Handler 是 urllib 模块中的一个类，负责处理请求中的不同操作（如建立连接、发送请求、接收响应等）。Handler 可以定制请求的处理方式，以便实现不同的需求。
  • 作用：将某些操作（例如 HTTP 请求、代理设置、重定向、认证等）抽象为一个“处理程序”，可以将不同的处理逻辑组合在一起。

2. HTTPHandler 的作用：

  • HTTPHandler 是一个处理 HTTP 请求的 handler 类，它负责处理 HTTP 协议的请求和响应。
  • 它主要处理的操作包括建立 HTTP 连接、发送 HTTP 请求、获取 HTTP 响应等。
  • HTTPHandler 处理的内容相对简单，适用于普通的 HTTP 请求。

Java静态代码块

Jinxiwei published on 2025-02-25 included in Java

​ Java静态代码块（Static Block）：用 static 关键字修饰的代码块，它在类加载时执行，并且只执行一次。静态代码块通常用于初始化静态变量或执行一些只需要进行一次的静态初始化操作。

语法

静态代码块的语法如下：

static {
    // 静态代码块中的代码
}

特点

  1. 执行时机：静态代码块在类加载时执行，且只执行一次。
  2. 执行顺序：如果有多个静态代码块，它们会按照在类中出现的顺序依次执行。
  3. 用途：通常用于初始化静态变量或执行一些只需要进行一次的静态初始化操作。

示例

public class Example {
    static int staticVar;

    // 静态代码块
    static {
        System.out.println("静态代码块执行");
        staticVar = 10;
    }

    public static void main(String[] args) {
        System.out.println("main方法执行");
        System.out.println("staticVar = " + staticVar);
    }
}

输出

静态代码块执行
main方法执行
staticVar = 10

解释

  1. 当 Example 类被加载时，静态代码块首先执行，输出 "静态代码块执行"，并将 staticVar 初始化为 10。
  2. 然后，main 方法执行，输出 "main方法执行" 和 staticVar 的值。

多个静态代码块

如果有多个静态代码块，它们会按照在类中出现的顺序依次执行：

public class Example {
    static int staticVar;

    // 第一个静态代码块
    static {
        System.out.println("第一个静态代码块执行");
        staticVar = 10;
    }

    // 第二个静态代码块
    static {
        System.out.println("第二个静态代码块执行");
        staticVar += 5;
    }

    public static void main(String[] args) {
        System.out.println("main方法执行");
        System.out.println("staticVar = " + staticVar);
    }
}

输出

第一个静态代码块执行
第二个静态代码块执行
main方法执行
staticVar = 15

解释

  1. 第一个静态代码块执行，输出 "第一个静态代码块执行"，并将 staticVar 初始化为 10。
  2. 第二个静态代码块执行，输出 "第二个静态代码块执行"，并将 staticVar 增加 5，最终值为 15。
  3. main 方法执行，输出 "main方法执行" 和 staticVar 的值。

总结

静态代码块是Java中用于在类加载时执行初始化操作的一种机制。它在类加载时自动执行，并且只执行一次，适合用于初始化静态变量或执行一些只需要进行一次的静态初始化操作。

  • 如果 cmp(a, b) < 0（负数），则 a 排在 b 前面
  • 如果 cmp(a, b) > 0（正数），则 b 排在 a 前面
  • 如果 cmp(a, b) == 0（零），则 a 和 b 视为相等，顺序不变

Socket概述

1、网络协议栈分层实现

  1. 传输层以上（应用层）

    • 由用户态应用程序实现。
    • 提供网络服务接口，如 HTTP、FTP 等。

  2. 传输层和网络互联层

    • 传输层：TCP/UDP 在内核中实现。
    • 网络互联层：如 IP 协议的路由功能也在内核中实现。
    • 路由协议：如 OSPF、BGP，通常由用户态进程实现。

  3. 第一层和第二层（物理层和数据链路层）

    • 一般由硬件实现，如网卡、交换机等。

2、UNIX 提供的网络功能接口

  1. 文件方式组织设备与通信

    • BSD 将设备和通信管道都组织为文件，创建方式不同，但访问方式一致。
    • 主要包括：
      • 终端设备：用于用户与计算机交互。
      • 管道：实现进程间通信。
      • 通信服务 Socket：为网络通信设计。

  2. AT&T UNIX 的 TLI（Transport Layer Interface）编程接口

    • 提供面向网络通信的接口。
    • 不仅支持 TCP/IP，也支持其他协议。

  3. 虚拟 Loopback 接口

    • 使用回环地址 127.0.0.1。
    • 实现同一台计算机上不同进程之间的通信。

3、TCP 与 UDP 的区别

  1. TCP（Transmission Control Protocol）

    • 特点：
      • 面向连接。
      • 可靠传输（通过确认机制、重传机制、流量控制实现）。
      • 字节流传输（不保证报文边界）。
    • 适用场景：文件传输、邮件服务、远程登录等。

  2. UDP（User Datagram Protocol）

    • 特点：
      • 面向数据报。
      • 不可靠传输（可能错报、丢报、乱序，无流量控制）。
      • 支持广播和组播。
      • 数据报传输（保留报文边界）。
    • 适用场景：视频流、实时通信、广播消息等。

4、字节顺序

  1. CPU 字节顺序

    • Big Endian（大端序）：高字节存储在低地址。
      • 适用 CPU：PowerPC、SPARC、Motorola。
    • Little Endian（小端序）：低字节存储在低地址。
      • 适用 CPU：Intel X86。

Jinxiwei published on 2024-12-17 included in Basic Course

信号灯与共享内存(IPC)

这是对信号灯、共享内存和消息队列的简要总结，涵盖了UNIX中的进程间通信（IPC）机制。

1、信号灯（Semaphore）

  • 作用: 用于控制多进程对共享资源的互斥访问和进程间的同步。
  • 策略与机制分离: UNIX提供信号灯机制，进程本身需要正确使用信号灯来保证互斥和同步。
  • 不当使用: 如果进程错误使用信号灯，可能会导致信息访问的不安全和死锁。
  • P操作（sem_op < 0）: 用于请求资源（等待操作），如果信号灯值小于0，则进程会被阻塞。
  • V操作（sem_op > 0）: 用于释放资源（通知操作），进程释放信号灯。
  • 创建信号灯: 使用semget()函数来创建或获取信号灯组。 
    int semget(int key, int nsems, int flags);
  • 控制信号灯: 使用semctl()函数来进行对信号灯的控制操作，如删除、查询状态等。 
    int semctl(int sem_id, int snum, int cmd, char *arg);
  • 信号灯操作: 使用semop()函数进行P/V操作。 
    int semop(int sem_id, struct sembuf *ops, int nops);
    • sem_num: 信号灯编号。
    • sem_op: 操作值，决定是P操作、V操作还是等待。
    • sem_flg: 操作选项。

2、共享内存（Shared Memory）

  • 特点: 允许多个进程共同使用同一段物理内存空间，进程间传递数据速度快。
  • 问题: 访问共享内存时需要自行解决互斥和同步问题，通常使用信号灯来保证安全。
  • 应用: 适用于数据交换、运行监视等场景。
  • 共享内存操作:
    • 创建共享内存段: 使用shmget()函数。 
      int shmget(int key, int nbytes, int flags);
    • 获取共享内存段指针: 使用shmat()函数。 
      void *shmat(int shm_id, void *shmaddr, int shmflg);
    • 控制共享内存段: 使用shmctl()函数进行删除、查询等操作。 
      int shmctl(int shm_id, int cmd, char *arg);
