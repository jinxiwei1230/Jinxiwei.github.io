进程的基本概念和逻辑内存

1、进程与程序

  • 程序：

    • 是指令和数据的集合，存放在磁盘上的普通文件中。
    • 必须符合系统要求并标记为可执行文件。

  • 进程：

    • 是程序的运行实例，包括指令段、用户数据段和系统数据段。
    • 提供执行环境。

  • 程序与进程的关系：

    • 程序用于初始化进程的指令段和用户数据段，初始化后两者无直接联系。
    • 进程运行时，程序文件不可修改或删除。
    • 一个程序可以初始化多个进程，它们之间没有联系。
    • 内核可通过共享指令段或动态链接共享函数库来节省内存，对用户透明。

2、进程的组成部分

  • 指令段 (Text)：

    • 包含程序的CPU指令代码，包括主程序、子程序和调用的库函数代码。
    • 大小固定且只读。

  • 用户数据段(支持动态调整)：

    • 包括全局变量、静态变量、字符串常量等。
    • 支持动态内存分配，大小可通过 sbrk() 调整（单位为页）。
    • 使用库函数如 malloc() 和 free() 实现内存管理。

  • 用户栈段：

    • 提供程序执行所需的栈空间。
    • 用于保存子程序返回地址、传递参数，以及存储局部变量（非静态）。
    • 包含命令行参数和环境参数，初始化于 main 函数运行之前。
    • 支持动态增长，但有增长限制。

  • 系统数据段：

    • 包含内核维护的进程数据（如页表和进程控制块 PCB）。
    • 与指令段、数据段、栈段分离，由内核管理。

进程的执行状态

1、进程的系统数据（PCB）

  • 内存管理：

    • 页表：用于虚拟内存管理，占已分配虚拟内存的约 1/1024（32 位奔腾 CPU）。

  • 文件管理：

    • 打开的文件描述符表：记录进程打开的文件。
    • 当前目录：记录当前目录的 i 节点。
    • 根目录：记录根目录位置。

  • 进程状态信息：

    • 核心态堆栈：用于内核态操作，大小几 KB。
    • 进程状态：如运行、等待、就绪等。
    • 优先级：用于调度决策。

  • 标识信息：

    • PID（进程 ID）和 PPID（父进程 ID）。
    • 进程组号：进程所属的组号。

  • 权限管理：

    • 主 UID/GID：实际用户 ID 和组 ID。
    • 有效 UID/GID：用于权限验证。
    • umask 值：文件权限掩码。

进程与文件描述符

活动文件目录（AFD）及文件管理系统分析

1、磁盘文件目录（Disk File Directory） 磁盘文件目录通常包括两级：

  • 文件名：文件在磁盘上的名字。
  • i节点：每个文件在文件系统中的元数据（inode）记录，包含文件的属性，如文件大小、权限、创建时间、修改时间等。 在磁盘上的文件目录结构中，文件名和对应的 i 节点是最重要的信息。i 节点为文件提供了关于文件内容的描述，但是不包含文件的实际数据。

2、活动文件目录（Active File Directory） 活动文件目录通常分为三级，其中包括文件描述符表（FDT）、系统文件表（SFT）和活动 i 节点表（AIT）。

  1. 文件描述符表（FDT） 每个进程都有的一张表，通常存储在进程的 PCB（进程控制块）的 user 结构中。 FDT 维护每个进程打开的文件的描述信息。它的主要作用是将文件描述符（fd）映射到具体的文件操作，如文件读写等。
  • 文件描述符：fd 是进程打开的文件在 u_ofile 数组中的下标，每个进程有一张自己的文件描述符表。
  • user 结构：在每个进程的 user 结构中，整型数组 u_ofile 用来记录该进程已打开的文件。u_ofile 数组的下标即为文件描述符（fd）。
  1. 系统文件表（SFT） 系统文件表（SFT）是整个操作系统共享的一张表，存储在内核中，包含对文件的管理信息。每个文件在系统中有一个 file 结构，该结构包含文件的操作标志、引用计数、偏移量和对应的 i 节点等信息。
  • struct file: 
    struct file {
    char f_flag;      // 读写操作标志（例如：只读、只写等）
    char f_count;     // 文件的引用计数
    long f_offset;    // 文件读写位置指针
    int f_inode;      // 文件的 i 节点索引
};
  1. 活动 i 节点表（AIT） 活动 i 节点表存储了操作系统内核当前正在使用的 i 节点，整个系统只有一张活动 i 节点表。它缓存了磁盘上对应的 inode 信息，避免每次访问文件时都需要从磁盘读取。
  • inode 结构：i 节点描述了文件的元数据，例如文件权限、所有者、文件大小、时间戳等信息。
  • 引用计数：内存中的 i 节点表有一个专用的引用计数，用来记录 i 节点当前被多少个进程引用。如果一个进程打开了一个文件，i 节点的引用计数会增加。引用计数为零时，表示该 i 节点已经不再被使用，可以释放。

Linux：shell的基本机理

Jinxiwei published on 2024-11-07 included in Basic Course

第九章 Shell的基本原理

shell 概述

1、 Unix Shell 概述 Shell是Unix操作系统中的命令解释器，是用户与操作系统交互的桥梁。它通过解析和执行用户输入的命令，向操作系统内核发出指令。

2、 Shell的功能

  1. 命令解释器：Shell是用户与系统的接口，解释和执行用户的命令。
  2. 文件名替换、命令替换、变量替换
  3. 历史替换与别名替换
  4. 流程控制的内部命令

3、 Shell的特点

  • 主要用途：适用于批处理，能自动化执行大量任务，但在执行效率上比一些算法语言稍低。
  • 编程风格：Shell脚本语言是面向命令处理的，流程控制结构通过对内部命令的解释实现，简洁灵活。

4、 常见的Shell种类

  1. Bourne Shell (B-shell)：最早广泛应用的Shell，是早期UNIX的标准Shell，路径为/bin/sh。
  2. C Shell (C-shell)：路径为/bin/csh，最早应用于BSD系统。
  3. Korn Shell (K-shell)：是B-shell的超集，路径为/bin/ksh，支持类型变量和数组。
  4. Bourne Again Shell (bash)：Linux系统的标准Shell，路径为/bin/bash，兼容B-Shell并吸收了C-shell的特性，提供方便的命令行编辑功能。

bash 启动

1、启动交互式bash

  1. 注册 Shell：通过系统注册的方式启动 bash 作为用户的默认登录 shell。
  2. 键入 bash 命令：在命令行中输入 bash，进入一个新的交互式 shell 实例。
  3. 脚本解释器：通过执行 bash 脚本文件，将命令批量自动执行。

2、Bash 的启动与退出行为

  1. 用户偏好的自动执行命令 - 作为注册 Shell 启动时：自动执行用户主目录中的 .bash_profile 文件。该文件通常位于 ~/.bash_profile 或 $HOME/.bash_profile，用于设置用户的环境变量和启动项。 - 作为注册 Shell 退出时：自动执行 $HOME/.bash_logout 文件中的命令，用于用户退出登录时清理环境。 - 作为交互式 Shell 启动时：自动执行 $HOME/.bashrc 文件。该文件通常包含别名、环境变量和交互命令的配置，适用于每次打开新的 shell 会话时执行。 > 注意：如 umask 等命令应写在 .profile 文件中，以便在所有登录会话中生效。

Linux：文件和目录权限

Jinxiwei published on 2024-10-31 included in Basic Course

第8章 Linux文件和目录权限

文件的权限

1、用于控制进程对系统中文件和目录的访问

2、权限的三个级别

  • 文件主，同组用户，其他用户
  • 每个文件有唯一的属主

3、普通文件的权限

  • 读、写、可执行
  • 不可写文件也可能会被删除

4、两类可执行文件

  1. 程序文件（可执行文件）：
  • 包含二进制的CPU指令集合。
  • 必须符合操作系统的格式要求才能加载运行。
  • 例如：Linux系统的ELF格式，Windows系统的PE格式。
  1. 脚本文件：
  • 是普通的文本文件。
  • 默认解释程序为 /bin/sh。
  • 可以在文件第一行通过 #!（Shebang）指定解释程序，例如 #! /bin/bash。
  • 解释程序可以是操作系统内置的程序或用户自定义的应用程序。
  1. 脚本程序运行机制：
  • 运行时由指定的解释程序解析并执行指令。
  • 解释程序会创建一个进程来执行脚本的每条指令。

目录的权限

1、目录的读写权限

  • 目录的读权限决定了能否查看目录内容。
  • 目录的写权限决定了能否在目录中添加或删除文件，但不影响对已有文件内容的修改。

2、目录的执行权限（x权限）

  1. 目录的执行权限：

    • x权限（执行权限）在目录中表示对路径的“可访问性”，即是否允许进入或访问目录中的内容。
    • 只有在具有执行权限的情况下，系统才允许在路径解析过程中“进入”该目录并进一步访问下一级目录或文件。

  2. 路径解析：

    • 当访问某个文件时，例如执行 cat /a/b/c，系统会依次解析路径中的每一级目录。
    • 要成功访问 /a/b/c 文件，路径中的每个目录（/a 和 /a/b）都需要有执行权限，否则系统无法进入这些目录，也就无法找到 c 文件。
    • 最终文件 c 本身只需具备读权限，以便 cat 命令能读取它的内容。

3、STICKY权限（粘着位）

  1. STICKY权限的主要用途——公共目录的文件删除控制：当目录带有写权限且启用STICKY属性时，目录中的文件只能由文件的所有者或管理员删除，其他用户的删除操作会被禁止。这使公共目录更加安全，不会因意外删除影响其他用户的文件。

  2. 示例：

  • /tmp 目录通常带有STICKY权限，因为它是公共目录，供所有用户存放临时文件。查看 /tmp 目录权限时可以看到STICKY位标志 t，例如： 
    drwxrwxrwt 13 root root 20480 Mar 22 06:11 /tmp
    • 权限的第一列显示 t 表示 /tmp 目录有STICKY权限。

第七章 命令风格与目录存储结构

命令风格

Linux系统命令和用户程序(ap)运行时获取信息的方式

配置信息等硬编码是不可取的

  • 硬编码需要编程时就确定服务器的地址，程序运行时就无法改变，太不灵活
  • 运行时获取信息的常见方式，易变性从小到大为 :
    • 配置文件
    • 环境变量
    • 命令行参数
    • 交互式键盘输入

1、配置文件

  • 系统级配置与用户级配置：

    • 系统级配置文件通常存储在系统目录下（如/etc），这些文件影响整个系统的行为，所有用户使用相同的配置。例如/etc/profile是所有用户登录时读取的Shell环境配置文件。
    • 用户级配置文件存储在用户的家目录下（如~/.bash_profile）。这些文件只影响该用户的配置和环境，而不会对系统中的其他用户产生影响。

  • 持久化存储：配置文件通常用于存储相对不频繁改变的信息，比如数据库连接配置、日志级别、文件路径等。因为这些配置不需要频繁更改，存放在配置文件中可以确保即使系统重启或应用重新启动，配置信息仍然保持不变。

  • 灵活性：配置文件为程序提供了灵活性。不同的用户可以读取自己的配置文件，使得同一程序可以表现出不同的行为。

  • 优势：持久性高、可以定制不同环境的配置，不同用户可以使用不同配置来调整同一个程序的行为。

2、环境变量

命令env： - 在Linux或类Unix系统中，env命令可以用来打印出当前用户会话中的所有环境变量。例如： bash env 这会显示诸如PATH、HOME、USER、SHELL等环境变量。

设置环境变量： 环境变量可以通过命令行或者配置文件设置。设置环境变量可以使其在程序执行期间动态影响程序行为。例如： bash export SERVER="180.249.151.131" 这样设置的环境变量只会影响当前会话或当前终端执行的程序。如果要使其永久生效，可以将其写入用户的~/.bash_profile或~/.bashrc文件中。

用途：环境变量非常适合那些在程序运行时需要灵活调整的参数，例如程序路径、临时目录、语言设置等。它们可以动态设置，程序在运行时读取并应用。

系统级与用户级环境变量：

  • 系统级环境变量可以设置在系统的配置文件中（如/etc/environment），会影响整个系统所有用户的环境。
  • 用户级环境变量则设置在用户的Shell配置文件中（如~/.bash_profile或~/.bashrc），仅影响当前用户的Shell会话。

示例： - 系统级环境变量：/etc/environment 中设置 JAVA_HOME 以指示所有用户的Java安装路径。 - 用户级环境变量：用户可以在~/.bashrc中设置自己的环境变量，比如export PATH="$PATH:/home/user/myapp/bin"，为自己的程序添加自定义路径。

优势：灵活性高，可以在程序运行时动态更改，特别适合在不同环境中快速调整配置，不需要修改代码或配置文件。

与环境相关：环境变量通常存储一些与系统环境或用户环境有关的参数。例如： - LANG：系统的语言设置，决定程序运行时的语言环境。 - HOME：当前用户的主目录路径。 - TERM：终端类型，影响终端显示和交互行为。 - PATH：可执行文件的搜索路径，决定从哪些目录中查找可执行程序。 - CLASSPATH：在Java程序中，指定查找Java类文件的位置。 - CVSROOT：版本控制系统CVS的根路径，指示CVS操作的默认目录。

感知环境差异：即使运行的程序（可执行文件）是相同的，程序可以通过读取环境变量来“感知”不同的环境设置，从而调整其行为。例如，不同的用户可能会有不同的HOME目录，程序读取此环境变量后会在用户自己的目录中执行操作。

环境变量的获取与设置： C语言中的getenv()函数：C语言提供了getenv()函数，用来从环境中获取指定变量的值。
