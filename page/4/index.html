1、约束

1.1 概念

  • 约束是作用于表中列上的规则，用于限制加入表的数据

    例如：我们可以给id列加约束，让其值不能重复，不能为null值。

  • 约束的存在保证了数据库中数据的正确性、有效性和完整性

    添加约束可以在添加数据的时候就限制不正确的数据，年龄是3000，数学成绩是-5分这样无效的数据，继而保障数据的完整性。

1.2 分类

  • 非空约束： 关键字是 NOT NULL

保证列中所有的数据不能有null值。

例如：id列在添加 马花疼 这条数据时就不能添加成功。

  • 唯一约束：关键字是 UNIQUE

    保证列中所有数据各不相同。

    例如：id列中三条数据的值都是1，这样的数据在添加时是绝对不允许的。

  • 主键约束： 关键字是 PRIMARY KEY

主键是一行数据的唯一标识，要求非空且唯一。一般我们都会给没张表添加一个主键列用来唯一标识数据。

例如：上图表中id就可以作为主键，来标识每条数据。那么这样就要求数据中id的值不能重复，不能为null值。

  • 检查约束： 关键字是 CHECK

    保证列中的值满足某一条件。

    例如：我们可以给age列添加一个范围，最低年龄可以设置为1，最大年龄就可以设置为300，这样的数据才更合理些。

    注意：MySQL不支持检查约束。

    这样是不是就没办法保证年龄在指定的范围内了？从数据库层面不能保证，以后可以在java代码中进行限制，一样也可以实现要求。

  • 默认约束： 关键字是 DEFAULT

    保存数据时，未指定值则采用默认值。

    例如：我们在给english列添加该约束，指定默认值是0，这样在添加数据时没有指定具体值时就会采用默认给定的0。

  • 外键约束： 关键字是 FOREIGN KEY

    外键用来让两个表的数据之间建立链接，保证数据的一致性和完整性。

    外键约束现在可能还不太好理解，后面我们会重点进行讲解。

1.3 非空约束

  • 概念

    非空约束用于保证列中所有数据不能有NULL值

  • 语法

    • 添加约束

      -- 创建表时添加非空约束
CREATE TABLE 表名(
   列名 数据类型 NOT NULL,
   …
); 

      -- 建完表后添加非空约束
ALTER TABLE 表名 MODIFY 字段名 数据类型 NOT NULL;

    • 删除约束

      ALTER TABLE 表名 MODIFY 字段名 数据类型;

1.4 唯一约束

  • 概念

    唯一约束用于保证列中所有数据各不相同

SQL触发器

触发器(Trigger)是数据库中的一种特殊存储过程，它会在特定事件(如INSERT、UPDATE、DELETE)发生时自动执行。触发器主要用于维护数据的完整性、实施业务规则以及审计数据变更。

一、触发器的基本概念

1. 触发器的定义

触发器是一段与表相关联的PL/SQL代码，当表发生特定事件时自动执行。触发器不接收参数，也不能被直接调用。

2. 触发器的组成要素

  • 触发事件：引起触发器执行的操作(INSERT/UPDATE/DELETE)
  • 触发时间：BEFORE或AFTER，表示在事件之前或之后触发
  • 触发级别：ROW或STATEMENT，表示行级或语句级触发
  • 触发条件：WHEN子句指定的额外条件
  • 触发体：触发器被激活时执行的PL/SQL代码块

3. 触发器的分类

按触发时间分类

  • BEFORE触发器：在触发事件执行之前激活
  • AFTER触发器：在触发事件执行之后激活

按触发级别分类

  • 行级触发器(ROW)：对受影响的每一行都触发一次
  • 语句级触发器(STATEMENT)：对整个SQL语句触发一次

按触发事件分类

  • INSERT触发器：当插入数据时触发
  • UPDATE触发器：当更新数据时触发
  • DELETE触发器：当删除数据时触发

二、触发器的创建语法

CREATE [OR REPLACE] TRIGGER trigger_name
{BEFORE | AFTER} {INSERT | UPDATE | DELETE [OF column_name,...]} 
ON table_name
[REFERENCING [OLD AS old_name] [NEW AS new_name]]
[FOR EACH ROW]
[WHEN (condition)]
DECLARE
    -- 声明部分(可选)
BEGIN
    -- 执行部分
EXCEPTION
    -- 异常处理部分(可选)
END;

三、触发器的详细使用

1. BEFORE触发器

在数据被修改前执行，常用于数据验证或修改即将插入/更新的数据。

示例1：数据验证

CREATE OR REPLACE TRIGGER check_salary
BEFORE INSERT OR UPDATE ON employees
FOR EACH ROW
BEGIN
    IF :NEW.salary < 0 THEN
        RAISE_APPLICATION_ERROR(-20001, 'Salary cannot be negative');
    END IF;
END;

Urllib基本使用(urlencode\urlretrieve\urlopen\quote)

1urllib.request 发送 HTTP 请求并获取响应

1. 基本用法

1.1 发送请求并获取响应
import urllib.request

# 定义URL
url = 'http://www.baidu.com'

# 发送请求并获取响应对象
response = urllib.request.urlopen(url)
  • urlopen(url)：打开指定的 URL 并返回一个 HTTPResponse 对象。
1.2 获取响应内容
# 读取响应内容并解码为字符串
content = response.read().decode('utf-8')
print(content)
  • read()：读取整个响应内容，返回字节形式的二进制数据。
  • decode('utf-8')：将二进制数据解码为字符串，utf-8 是常见的编码格式。
1.3 读取部分内容
# 读取前10个字节
content = response.read(10)
print(content)
  • read(n)：读取响应内容的前 n 个字节。
1.4 逐行读取
# 读取一行
content1 = response.readline()
print(content1)

# 逐行读取所有内容
content2 = response.readlines()
print(content2)
  • readline()：读取一行内容。
  • readlines()：读取所有行并返回一个列表。

2. 响应对象 (HTTPResponse) 的方法和属性

2.1 获取状态码
print("状态码：", response.getcode())
  • getcode()：返回 HTTP 响应的状态码（如 200 表示成功）。
2.2 获取请求的 URL
print("URL: ", response.geturl())
  • geturl()：返回实际请求的 URL（可能会与原始 URL 不同，例如发生重定向时）。
2.3 获取响应头信息
print("头信息：", response.getheaders())
  • getheaders()：返回一个包含所有响应头信息的列表，每个元素是一个 (header, value) 元组。

3. 总结

  • 一个类型：HTTPResponse，表示 HTTP 响应对象。
  • 六个方法：
    1. read()：读取响应内容。
    2. read(n)：读取前 n 个字节。
    3. readline()：读取一行内容。
    4. readlines()：读取所有行。
    5. getcode()：获取状态码。
    6. geturl()：获取请求的 URL。
    7. getheaders()：获取响应头信息。

异常种类

urllib.error.URLError

常见场景：

  • 连接超时（如请求的目标服务器无法访问，网络中断）。
  • DNS 解析错误（例如，URL 域名无法解析到 IP 地址）。
  • 网络连接错误（例如，网络不可达）

urllib.error.HTTPError

HTTPError 是 urllib 模块中的一个子类异常，专门用于处理 HTTP 错误状态码（如 404、500 等）。 常见场景：

  • 请求的资源不存在，返回 404 错误。
  • 请求无法通过认证，返回 401 或 403 错误。
  • 服务器错误，返回 500 错误。

cookie、Referer

1、登录状态（Cookie）：

  • Cookie 是模拟登录状态时至关重要的一部分。爬虫通过获取登录后浏览器中的 Cookie，将其放在请求头中，以模拟已登录的状态。
  • cookie 包含一系列从微博登录后获得的身份信息，如 SCF、SINAGLOBAL、PC_TOKEN 等。 注意：使用 Cookie 时需要确保它是有效的，并且不要泄露敏感信息。

2、防止反爬虫措施：

  • Referer：一些网站通过检查 referer 来判断请求是否来自正常的浏览路径，防止直接访问资源。爬虫在请求头中加入合适的 referer 值可以绕过这种检查。
  • User-Agent：服务器根据请求头中的 User-Agent 判断请求是否来自浏览器。如果 User-Agent 显示是爬虫，服务器可能会阻止请求。为了绕过此问题，可以设置与常见浏览器相符的 User-Agent。

3、爬虫中的常见技巧：

  • 模拟浏览器请求：通过自定义请求头信息，特别是 User-Agent、Referer 和 Cookie，使爬虫看起来像一个正常用户在浏览网页。
  • 处理登录后的数据：当需要登录后获取数据时，确保爬虫能够通过获取到的 Cookie 维持登录状态。
  • 防止被封禁：通过设置适当的请求头信息和延时控制，避免被目标网站封禁 IP。

爬虫 handler

1. 什么是 Handler？

  • Handler 是 urllib 模块中的一个类，负责处理请求中的不同操作（如建立连接、发送请求、接收响应等）。Handler 可以定制请求的处理方式，以便实现不同的需求。
  • 作用：将某些操作（例如 HTTP 请求、代理设置、重定向、认证等）抽象为一个“处理程序”，可以将不同的处理逻辑组合在一起。

2. HTTPHandler 的作用：

  • HTTPHandler 是一个处理 HTTP 请求的 handler 类，它负责处理 HTTP 协议的请求和响应。
  • 它主要处理的操作包括建立 HTTP 连接、发送 HTTP 请求、获取 HTTP 响应等。
  • HTTPHandler 处理的内容相对简单，适用于普通的 HTTP 请求。

Java静态代码块

Jinxiwei published on 2025-02-25 included in Java

​ Java静态代码块（Static Block）：用 static 关键字修饰的代码块，它在类加载时执行，并且只执行一次。静态代码块通常用于初始化静态变量或执行一些只需要进行一次的静态初始化操作。

语法

静态代码块的语法如下：

static {
    // 静态代码块中的代码
}

特点

  1. 执行时机：静态代码块在类加载时执行，且只执行一次。
  2. 执行顺序：如果有多个静态代码块，它们会按照在类中出现的顺序依次执行。
  3. 用途：通常用于初始化静态变量或执行一些只需要进行一次的静态初始化操作。

示例

public class Example {
    static int staticVar;

    // 静态代码块
    static {
        System.out.println("静态代码块执行");
        staticVar = 10;
    }

    public static void main(String[] args) {
        System.out.println("main方法执行");
        System.out.println("staticVar = " + staticVar);
    }
}

输出

静态代码块执行
main方法执行
staticVar = 10

解释

  1. 当 Example 类被加载时，静态代码块首先执行，输出 "静态代码块执行"，并将 staticVar 初始化为 10。
  2. 然后，main 方法执行，输出 "main方法执行" 和 staticVar 的值。

多个静态代码块

如果有多个静态代码块，它们会按照在类中出现的顺序依次执行：

public class Example {
    static int staticVar;

    // 第一个静态代码块
    static {
        System.out.println("第一个静态代码块执行");
        staticVar = 10;
    }

    // 第二个静态代码块
    static {
        System.out.println("第二个静态代码块执行");
        staticVar += 5;
    }

    public static void main(String[] args) {
        System.out.println("main方法执行");
        System.out.println("staticVar = " + staticVar);
    }
}

输出

第一个静态代码块执行
第二个静态代码块执行
main方法执行
staticVar = 15

解释

  1. 第一个静态代码块执行，输出 "第一个静态代码块执行"，并将 staticVar 初始化为 10。
  2. 第二个静态代码块执行，输出 "第二个静态代码块执行"，并将 staticVar 增加 5，最终值为 15。
  3. main 方法执行，输出 "main方法执行" 和 staticVar 的值。

总结

静态代码块是Java中用于在类加载时执行初始化操作的一种机制。它在类加载时自动执行，并且只执行一次，适合用于初始化静态变量或执行一些只需要进行一次的静态初始化操作。

1. qsort 函数：来自 C 标准库 stdlib.h，使用比较函数来确定两个元素的顺序。 cmp 比较函数：cmp 是一个函数指针，指向用户定义的比较函数。该比较函数接受两个参数，返回值为：

  • 如果 cmp(a, b) < 0（负数），则 a 排在 b 前面
  • 如果 cmp(a, b) > 0（正数），则 b 排在 a 前面
  • 如果 cmp(a, b) == 0（零），则 a 和 b 视为相等，顺序不变
qsort(nums1, nums1Size, sizeof(int), cmp);

// 升序比较函数
int cmp(const void *a, const void *b)
{
    return *(int*)a - *(int*)b;
}

// 降序比较函数
int cmp_desc(const void* a, const void* b) {
    return *(int*)b - *(int*)a;  // 让较大的数排在前面
}
