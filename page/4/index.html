Socket概述

1、网络协议栈分层实现

  1. 传输层以上（应用层）

    • 由用户态应用程序实现。
    • 提供网络服务接口，如 HTTP、FTP 等。

  2. 传输层和网络互联层

    • 传输层：TCP/UDP 在内核中实现。
    • 网络互联层：如 IP 协议的路由功能也在内核中实现。
    • 路由协议：如 OSPF、BGP，通常由用户态进程实现。

  3. 第一层和第二层（物理层和数据链路层）

    • 一般由硬件实现，如网卡、交换机等。

2、UNIX 提供的网络功能接口

  1. 文件方式组织设备与通信

    • BSD 将设备和通信管道都组织为文件，创建方式不同，但访问方式一致。
    • 主要包括：
      • 终端设备：用于用户与计算机交互。
      • 管道：实现进程间通信。
      • 通信服务 Socket：为网络通信设计。

  2. AT&T UNIX 的 TLI（Transport Layer Interface）编程接口

    • 提供面向网络通信的接口。
    • 不仅支持 TCP/IP，也支持其他协议。

  3. 虚拟 Loopback 接口

    • 使用回环地址 127.0.0.1。
    • 实现同一台计算机上不同进程之间的通信。

3、TCP 与 UDP 的区别

  1. TCP（Transmission Control Protocol）

    • 特点：
      • 面向连接。
      • 可靠传输（通过确认机制、重传机制、流量控制实现）。
      • 字节流传输（不保证报文边界）。
    • 适用场景：文件传输、邮件服务、远程登录等。

  2. UDP（User Datagram Protocol）

    • 特点：
      • 面向数据报。
      • 不可靠传输（可能错报、丢报、乱序，无流量控制）。
      • 支持广播和组播。
      • 数据报传输（保留报文边界）。
    • 适用场景：视频流、实时通信、广播消息等。

4、字节顺序

  1. CPU 字节顺序

    • Big Endian（大端序）：高字节存储在低地址。
      • 适用 CPU：PowerPC、SPARC、Motorola。
    • Little Endian（小端序）：低字节存储在低地址。
      • 适用 CPU：Intel X86。

Jinxiwei published on 2024-12-17 included in Basic Course

信号灯与共享内存(IPC)

这是对信号灯、共享内存和消息队列的简要总结，涵盖了UNIX中的进程间通信（IPC）机制。

1、信号灯（Semaphore）

  • 作用: 用于控制多进程对共享资源的互斥访问和进程间的同步。
  • 策略与机制分离: UNIX提供信号灯机制，进程本身需要正确使用信号灯来保证互斥和同步。
  • 不当使用: 如果进程错误使用信号灯，可能会导致信息访问的不安全和死锁。
  • P操作（sem_op < 0）: 用于请求资源（等待操作），如果信号灯值小于0，则进程会被阻塞。
  • V操作（sem_op > 0）: 用于释放资源（通知操作），进程释放信号灯。
  • 创建信号灯: 使用semget()函数来创建或获取信号灯组。 
    int semget(int key, int nsems, int flags);
  • 控制信号灯: 使用semctl()函数来进行对信号灯的控制操作，如删除、查询状态等。 
    int semctl(int sem_id, int snum, int cmd, char *arg);
  • 信号灯操作: 使用semop()函数进行P/V操作。 
    int semop(int sem_id, struct sembuf *ops, int nops);
    • sem_num: 信号灯编号。
    • sem_op: 操作值，决定是P操作、V操作还是等待。
    • sem_flg: 操作选项。

2、共享内存（Shared Memory）

  • 特点: 允许多个进程共同使用同一段物理内存空间，进程间传递数据速度快。
  • 问题: 访问共享内存时需要自行解决互斥和同步问题，通常使用信号灯来保证安全。
  • 应用: 适用于数据交换、运行监视等场景。
  • 共享内存操作:
    • 创建共享内存段: 使用shmget()函数。 
      int shmget(int key, int nbytes, int flags);
    • 获取共享内存段指针: 使用shmat()函数。 
      void *shmat(int shm_id, void *shmaddr, int shmflg);
    • 控制共享内存段: 使用shmctl()函数进行删除、查询等操作。 
      int shmctl(int shm_id, int cmd, char *arg);

Linux：信号

Jinxiwei published on 2024-12-12 included in Basic Course

信号的产生及类型

1、命令kill

  • 功能：用于向进程发送信号。
  • 基本用法：
    • kill -signal PID-list：发送指定信号到一个或多个进程。
    • 默认信号为 SIGTERM（15），用于正常终止进程。
    • 示例：
      • kill 1275：向进程 1275 发送 SIGTERM 信号。
      • kill -9 1326：向进程 1326 发送 SIGKILL 信号，强制终止进程。

2、进程组

  • 定义：
    • 进程组由 p_pgrp 字段标识，相同 p_pgrp 值的进程属于同一组。
    • 如果 p_pgrp 等于 p_pid，则该进程是组长。
  • 行为：
    • 创建新组：setsid() 系统调用让进程脱离原组并成为新组组长。
    • 继承：子进程通过 fork 继承父进程的 p_pgrp。
    • 示例：kill -0 0 会向与当前进程同组的所有进程发送信号。

3、信号机制

  • 功能：信号是一种“软件中断”，用于通知进程处理异常事件。
  • 信号产生：
    1. 用户态进程：
      • 通过 kill() 或 alarm() 调用发送信号。
    2. 内核触发：
      • 由中断或异常事件触发。
      • 例子：
        • SIGSEGV（段违例）：进程访问非法内存地址时触发。
        • SIGFPE（浮点溢出）：如零做除数。
        • SIGPIPE：管道读端关闭时写端触发。

4、信号类型

  • 信号在 <sys/signal.h> 文件中以宏定义，种类有限（约几十种）。
  • 关键信号及其作用：
    • SIGTERM（15）：软件终止信号（默认信号）。
    • SIGHUP（1）：挂断信号，用户退出 shell 时触发。
    • SIGINT（2）：中断信号，用户按 Ctrl-C 触发。
    • SIGQUIT（3）：退出信号，按 Ctrl-\ 触发，产生 core 文件。
    • SIGKILL（9）：强制终止信号，不可被捕获或忽略。
    • SIGALRM（14）：计时器信号，由 alarm() 触发。
    • SIGPIPE：管道写端对已关闭读端写操作。
    • 用户自定义信号：SIGUSR1、SIGUSR2。
    • 异常信号：
      • SIGSEGV：段违例。
      • SIGFPE：浮点溢出。
      • SIGILL：非法指令。
    • 其他信号：
      • SIGCLD：子进程终止。
      • SIGWINCH：终端窗口大小改变。

进程的基本概念和逻辑内存

1、进程与程序

  • 程序：

    • 是指令和数据的集合，存放在磁盘上的普通文件中。
    • 必须符合系统要求并标记为可执行文件。

  • 进程：

    • 是程序的运行实例，包括指令段、用户数据段和系统数据段。
    • 提供执行环境。

  • 程序与进程的关系：

    • 程序用于初始化进程的指令段和用户数据段，初始化后两者无直接联系。
    • 进程运行时，程序文件不可修改或删除。
    • 一个程序可以初始化多个进程，它们之间没有联系。
    • 内核可通过共享指令段或动态链接共享函数库来节省内存，对用户透明。

2、进程的组成部分

  • 指令段 (Text)：

    • 包含程序的CPU指令代码，包括主程序、子程序和调用的库函数代码。
    • 大小固定且只读。

  • 用户数据段(支持动态调整)：

    • 包括全局变量、静态变量、字符串常量等。
    • 支持动态内存分配，大小可通过 sbrk() 调整（单位为页）。
    • 使用库函数如 malloc() 和 free() 实现内存管理。

  • 用户栈段：

    • 提供程序执行所需的栈空间。
    • 用于保存子程序返回地址、传递参数，以及存储局部变量（非静态）。
    • 包含命令行参数和环境参数，初始化于 main 函数运行之前。
    • 支持动态增长，但有增长限制。

  • 系统数据段：

    • 包含内核维护的进程数据（如页表和进程控制块 PCB）。
    • 与指令段、数据段、栈段分离，由内核管理。

进程的执行状态

1、进程的系统数据（PCB）

  • 内存管理：

    • 页表：用于虚拟内存管理，占已分配虚拟内存的约 1/1024（32 位奔腾 CPU）。

  • 文件管理：

    • 打开的文件描述符表：记录进程打开的文件。
    • 当前目录：记录当前目录的 i 节点。
    • 根目录：记录根目录位置。

  • 进程状态信息：

    • 核心态堆栈：用于内核态操作，大小几 KB。
    • 进程状态：如运行、等待、就绪等。
    • 优先级：用于调度决策。

  • 标识信息：

    • PID（进程 ID）和 PPID（父进程 ID）。
    • 进程组号：进程所属的组号。

  • 权限管理：

    • 主 UID/GID：实际用户 ID 和组 ID。
    • 有效 UID/GID：用于权限验证。
    • umask 值：文件权限掩码。

进程与文件描述符

活动文件目录（AFD）及文件管理系统分析

1、磁盘文件目录（Disk File Directory） 磁盘文件目录通常包括两级：

  • 文件名：文件在磁盘上的名字。
  • i节点：每个文件在文件系统中的元数据（inode）记录，包含文件的属性，如文件大小、权限、创建时间、修改时间等。 在磁盘上的文件目录结构中，文件名和对应的 i 节点是最重要的信息。i 节点为文件提供了关于文件内容的描述，但是不包含文件的实际数据。

2、活动文件目录（Active File Directory） 活动文件目录通常分为三级，其中包括文件描述符表（FDT）、系统文件表（SFT）和活动 i 节点表（AIT）。

  1. 文件描述符表（FDT） 每个进程都有的一张表，通常存储在进程的 PCB（进程控制块）的 user 结构中。 FDT 维护每个进程打开的文件的描述信息。它的主要作用是将文件描述符（fd）映射到具体的文件操作，如文件读写等。
  • 文件描述符：fd 是进程打开的文件在 u_ofile 数组中的下标，每个进程有一张自己的文件描述符表。
  • user 结构：在每个进程的 user 结构中，整型数组 u_ofile 用来记录该进程已打开的文件。u_ofile 数组的下标即为文件描述符（fd）。
  1. 系统文件表（SFT） 系统文件表（SFT）是整个操作系统共享的一张表，存储在内核中，包含对文件的管理信息。每个文件在系统中有一个 file 结构，该结构包含文件的操作标志、引用计数、偏移量和对应的 i 节点等信息。
  • struct file: 
    struct file {
    char f_flag;      // 读写操作标志（例如：只读、只写等）
    char f_count;     // 文件的引用计数
    long f_offset;    // 文件读写位置指针
    int f_inode;      // 文件的 i 节点索引
};
  1. 活动 i 节点表（AIT） 活动 i 节点表存储了操作系统内核当前正在使用的 i 节点，整个系统只有一张活动 i 节点表。它缓存了磁盘上对应的 inode 信息，避免每次访问文件时都需要从磁盘读取。
  • inode 结构：i 节点描述了文件的元数据，例如文件权限、所有者、文件大小、时间戳等信息。
  • 引用计数：内存中的 i 节点表有一个专用的引用计数，用来记录 i 节点当前被多少个进程引用。如果一个进程打开了一个文件，i 节点的引用计数会增加。引用计数为零时，表示该 i 节点已经不再被使用，可以释放。

第九章 Shell的基本原理

shell 概述

1、 Unix Shell 概述 Shell是Unix操作系统中的命令解释器，是用户与操作系统交互的桥梁。它通过解析和执行用户输入的命令，向操作系统内核发出指令。

2、 Shell的功能

  1. 命令解释器：Shell是用户与系统的接口，解释和执行用户的命令。
  2. 文件名替换、命令替换、变量替换
  3. 历史替换与别名替换
  4. 流程控制的内部命令

3、 Shell的特点

  • 主要用途：适用于批处理，能自动化执行大量任务，但在执行效率上比一些算法语言稍低。
  • 编程风格：Shell脚本语言是面向命令处理的，流程控制结构通过对内部命令的解释实现，简洁灵活。

4、 常见的Shell种类

  1. Bourne Shell (B-shell)：最早广泛应用的Shell，是早期UNIX的标准Shell，路径为/bin/sh。
  2. C Shell (C-shell)：路径为/bin/csh，最早应用于BSD系统。
  3. Korn Shell (K-shell)：是B-shell的超集，路径为/bin/ksh，支持类型变量和数组。
  4. Bourne Again Shell (bash)：Linux系统的标准Shell，路径为/bin/bash，兼容B-Shell并吸收了C-shell的特性，提供方便的命令行编辑功能。

bash 启动

1、启动交互式bash

  1. 注册 Shell：通过系统注册的方式启动 bash 作为用户的默认登录 shell。
  2. 键入 bash 命令：在命令行中输入 bash，进入一个新的交互式 shell 实例。
  3. 脚本解释器：通过执行 bash 脚本文件，将命令批量自动执行。

2、Bash 的启动与退出行为

  1. 用户偏好的自动执行命令 - 作为注册 Shell 启动时：自动执行用户主目录中的 .bash_profile 文件。该文件通常位于 ~/.bash_profile 或 $HOME/.bash_profile，用于设置用户的环境变量和启动项。 - 作为注册 Shell 退出时：自动执行 $HOME/.bash_logout 文件中的命令，用于用户退出登录时清理环境。 - 作为交互式 Shell 启动时：自动执行 $HOME/.bashrc 文件。该文件通常包含别名、环境变量和交互命令的配置，适用于每次打开新的 shell 会话时执行。 > 注意：如 umask 等命令应写在 .profile 文件中，以便在所有登录会话中生效。
